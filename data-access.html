11 · ADO.NET, DataTable and EF Core

Understand direct SQL access and ORM-based data access, including concepts used in hospital systems.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

ADO.NET building blocks

  • SqlConnection manages a database connection.
  • SqlCommand represents a SQL statement or stored procedure.
  • SqlParameter passes values safely.
  • SqlDataReader reads rows forward-only and efficiently.
  • ExecuteReader returns rows; ExecuteScalar returns one value; ExecuteNonQuery executes commands without returning a rowset.
await using var connection = new SqlConnection(connectionString);
await using var command = new SqlCommand("dbo.GetPatientById", connection);
command.CommandType = CommandType.StoredProcedure;
command.Parameters.Add("@PatientId", SqlDbType.Int).Value = patientId;
await connection.OpenAsync(cancellationToken);
await using var reader = await command.ExecuteReaderAsync(cancellationToken);

DataTable and DataRow

DataTable is an in-memory table with columns, rows and optional constraints. DataRow represents one record. These are useful for disconnected data, legacy systems, reports and GridView binding.

var table = new DataTable();
table.Columns.Add("PatientId", typeof(int));
table.Columns.Add("PatientName", typeof(string));

DataRow row = table.NewRow();
row["PatientId"] = 101;
row["PatientName"] = "Amina";
table.Rows.Add(row);

foreach (DataRow patientRow in table.Rows)
    Console.WriteLine(patientRow["PatientName"]);

Practice creating columns, adding rows, reading values, updating rows, deleting rows and binding a DataTable to a GridView.

Entity Framework Core

EF Core is an object-relational mapper. DbContext coordinates entity tracking and database operations; DbSet represents an entity set. LINQ queries are translated by the provider into SQL.

var patient = await db.Patients
    .AsNoTracking()
    .Where(p => p.PatientId == id)
    .Select(p => new PatientDto(p.PatientId, p.Name))
    .SingleOrDefaultAsync(cancellationToken);

Relationships, migrations and query behavior

  • Configure primary/foreign keys and relationships with conventions or Fluent API.
  • Use migrations to evolve schema under version control.
  • Understand tracking versus AsNoTracking.
  • Choose eager, explicit or lazy loading deliberately; watch for N+1 queries.
  • Project only required fields into DTOs.
  • Use transactions and concurrency tokens when appropriate.

Deep dive: move hospital data between C# and SQL Server

ADO.NET: explicit database control

ADO.NET exposes connections, commands, parameters and readers. It is useful for direct SQL and legacy WebForms code.

await using var connection = new SqlConnection(connectionString);
await connection.OpenAsync(ct);
await using var command = new SqlCommand("SELECT PatientId, PatientName FROM Patients WHERE PatientId=@Id", connection);
command.Parameters.Add("@Id", SqlDbType.Int).Value = patientId;
await using var reader = await command.ExecuteReaderAsync(ct);
if (await reader.ReadAsync(ct)) Console.WriteLine(reader.GetString(1));

Parameters prevent SQL injection. Never concatenate user input into SQL.

DataReader, DataTable and DataRow

SqlDataReader is forward-only and read-only. DataTable is an in-memory table with columns and rows; each DataRow represents one record. It is useful for WebForms GridView binding and disconnected editing.

var table = new DataTable("Patients");
table.Columns.Add("PatientId", typeof(int));
table.Columns.Add("PatientName", typeof(string));
DataRow row = table.NewRow();
row["PatientId"] = 101; row["PatientName"] = "Amina";
table.Rows.Add(row);
foreach (DataRow r in table.Rows) Console.WriteLine($"{r["PatientId"]}: {r["PatientName"]}");
// GridViewPatients.DataSource = table; GridViewPatients.DataBind();

DataRow tracks Added, Modified and Deleted states. DataTable does not automatically update SQL Server; persist changes explicitly through a DataAdapter or commands.

EF Core

var patient = await db.Patients.AsNoTracking()
    .Where(p => p.PatientId == id)
    .Select(p => new PatientResponse(p.PatientId, p.PatientName))
    .SingleOrDefaultAsync(ct);

EF Core translates LINQ to SQL. Use AsNoTracking for read-only queries, project required columns and inspect generated SQL when performance matters. DbContext is short-lived, scoped per request and not thread-safe. Review migrations before production; use a transaction when invoice header and lines must succeed together.
