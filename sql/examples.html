SQL Server and MySQL side-by-side examples

Compare common production tasks in T-SQL and MySQL while learning which SQL concepts are portable and which are vendor-specific.

Schema and keys — SQL Server

CREATE TABLE dbo.Patients (
    PatientId int IDENTITY(1,1) PRIMARY KEY,
    MRN varchar(20) NOT NULL UNIQUE,
    FullName nvarchar(150) NOT NULL,
    DateOfBirth date NULL,
    IsActive bit NOT NULL CONSTRAINT DF_Patients_IsActive DEFAULT (1)
);

Schema and keys — MySQL

CREATE TABLE Patients (
    PatientId int NOT NULL AUTO_INCREMENT PRIMARY KEY,
    MRN varchar(20) NOT NULL UNIQUE,
    FullName varchar(150) NOT NULL,
    DateOfBirth date NULL,
    IsActive boolean NOT NULL DEFAULT true
) ENGINE=InnoDB;

SQL Server uses IDENTITY and bit in this example; MySQL uses AUTO_INCREMENT and BOOLEAN (an alias for TINYINT(1)). Collation, Unicode behavior and default constraints differ by engine.

Safe parameterized query

-- T-SQL
SELECT PatientId, MRN, FullName
FROM dbo.Patients
WHERE PatientId = @PatientId;
-- MySQL
SELECT PatientId, MRN, FullName
FROM Patients
WHERE PatientId = ?;

Parameter placeholder syntax depends on the driver. Parameters bind values, not identifiers such as table names or sort directions. Allow-list dynamic identifiers.

Joins and reporting

SELECT
    a.AppointmentId,
    p.MRN,
    p.FullName,
    d.DoctorName,
    a.AppointmentDate
FROM Appointments AS a
JOIN Patients AS p ON p.PatientId = a.PatientId
JOIN Doctors AS d ON d.DoctorId = a.DoctorId
WHERE a.AppointmentDate >= @FromDate
  AND a.AppointmentDate < @ToDate
ORDER BY a.AppointmentDate;

This join and date-range pattern is broadly portable; parameter declaration and date/time types vary by database.

Transactions for payment posting

-- T-SQL
SET XACT_ABORT ON;
BEGIN TRY
    BEGIN TRANSACTION;

    INSERT dbo.Payments(InvoiceId, Amount, PaidAt)
    VALUES (@InvoiceId, @Amount, SYSUTCDATETIME());

    UPDATE dbo.Invoices
    SET PaidAmount = PaidAmount + @Amount
    WHERE InvoiceId = @InvoiceId;

    COMMIT TRANSACTION;
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0 ROLLBACK TRANSACTION;
    THROW;
END CATCH;

MySQL/InnoDB uses START TRANSACTION, COMMIT and ROLLBACK, with handler syntax inside stored programs. Application-level transaction APIs are often clearer for multi-step business workflows.

Index and query plan examples

-- SQL Server
CREATE INDEX IX_Appointments_Doctor_Date
ON dbo.Appointments(DoctorId, AppointmentDate)
INCLUDE (PatientId, Status);

-- MySQL
CREATE INDEX IX_Appointments_Doctor_Date
ON Appointments(DoctorId, AppointmentDate);

-- Inspect plans
-- SQL Server: Actual Execution Plan / SET STATISTICS IO, TIME ON
-- MySQL: EXPLAIN ANALYZE SELECT ...

Indexes should follow measured query patterns. Every extra index adds storage and write cost. Compare estimated and actual plans and validate with representative data volumes.
