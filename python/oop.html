Python OOP, dataclasses and typing

Model domain concepts and define maintainable contracts using Python's object model and type system.

Classes, dataclasses and encapsulation

from dataclasses import dataclass

@dataclass(frozen=True)
class PatientSummary:
    patient_id: int
    full_name: str
    mrn: str

class Invoice:
    def __init__(self, invoice_id: int, total: int) -> None:
        if total < 0:
            raise ValueError("Total cannot be negative")
        self.invoice_id = invoice_id
        self._total = total
        self._paid = 0

    @property
    def balance(self) -> int:
        return self._total - self._paid

Python uses conventions such as leading underscores rather than C#-style access modifiers. Dataclasses reduce boilerplate for data carriers; they do not replace domain validation.

Composition, inheritance and protocols

from typing import Protocol

class AppointmentRepository(Protocol):
    def get_by_id(self, appointment_id: int) -> dict | None: ...

class AppointmentService:
    def __init__(self, repository: AppointmentRepository) -> None:
        self._repository = repository

    def find(self, appointment_id: int):
        return self._repository.get_by_id(appointment_id)

Protocols provide structural typing: an object can satisfy the contract by implementing the required behavior. Prefer composition and dependency injection over deep inheritance trees.

Type hints, generics and enums

from enum import StrEnum
from typing import TypeVar, Generic

class AppointmentStatus(StrEnum):
    BOOKED = "booked"
    COMPLETED = "completed"
    CANCELLED = "cancelled"

T = TypeVar("T")
class Result(Generic[T]):
    def __init__(self, value: T | None, error: str | None = None):
        self.value = value
        self.error = error

Learn Optional/union types, Literal, TypedDict, Protocol, TypeVar, ParamSpec and type narrowing with mypy or Pyright.
