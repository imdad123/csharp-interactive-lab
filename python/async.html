Async programming and concurrency

Understand asyncio, concurrent tasks, cancellation, threads and process pools.

Async I/O with asyncio

import asyncio

async def get_patient(patient_id: int):
    await asyncio.sleep(0.1)  # stands in for async database/network I/O
    return {"id": patient_id, "name": "Amina"}

async def main():
    patient = await get_patient(101)
    print(patient)

asyncio.run(main())

async def creates a coroutine. await suspends the coroutine while an awaitable completes; it does not create a new OS thread by itself.

Run independent tasks concurrently

async def load_patient_dashboard(patient_id: int):
    patient_task = asyncio.create_task(get_patient(patient_id))
    appointments_task = asyncio.create_task(get_appointments(patient_id))

    patient, appointments = await asyncio.gather(
        patient_task, appointments_task
    )
    return {"patient": patient, "appointments": appointments}

Understand TaskGroup, gather, cancellation, timeouts, exception propagation, semaphores and backpressure. Use bounded concurrency rather than launching unbounded tasks.

Threads, processes and the GIL

For I/O-bound work, async or threads can help. For CPU-bound Python code, process pools or native libraries may use multiple CPU cores. Learn the GIL implications for the Python implementation/version you deploy.

Background jobs

Appointment reminders, report generation and document processing are often better handled by durable queues and workers (Celery, RQ, Dramatiq or cloud queue services) than by keeping an HTTP request open.
