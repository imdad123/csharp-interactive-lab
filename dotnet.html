08 · .NET platform and runtime internals

Understand how C# source becomes an executing application and how .NET supports it.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Roslyn and compilation

The C# compiler (Roslyn) parses source, checks language and type rules, then emits Intermediate Language (IL) and metadata into assemblies. Compiler diagnostics catch many errors before execution.

CLR, CTS and CLS

  • CLR: managed execution services such as garbage collection, exception handling, loading, type safety and JIT.
  • CTS: common representation and behavior of types across .NET languages.
  • CLS: rules for cross-language public API compatibility.

Assemblies, IL, JIT and AOT

Assemblies are deployment/versioning units containing IL, metadata and resources. The JIT compiler translates IL into native machine code as methods execute. Native AOT compiles ahead of time and has different startup, deployment and reflection trade-offs.

Garbage collection and memory

The GC reclaims managed objects that are no longer reachable. Generational collection optimizes for the common pattern that many objects die young. GC does not deterministically close files, sockets or database resources—use disposal.

Hosting and project system

Understand SDK-style projects, .csproj, NuGet, restore/build/publish, Generic Host, configuration, logging, dependency injection and application lifetime. ASP.NET Core adds web hosting and the HTTP request pipeline.

Practical checkpoints

  • Distinguish compiler errors from runtime exceptions.
  • Explain source → IL/assembly → JIT/native execution.
  • Know why IDisposable is required in a garbage-collected runtime.
  • Inspect project dependencies and deployment output.

Deep dive: what happens when HospitalApp runs?

C# is the language; .NET is the platform, runtime and library ecosystem. This distinction helps diagnose startup, deployment, memory and performance issues.

Compilation pipeline

  1. Roslyn parses C# and checks types.
  2. The compiler emits Intermediate Language and metadata into assemblies.
  3. The runtime loads assemblies and resolves dependencies.
  4. JIT compiles IL to native machine code as needed; supported AOT deployments compile ahead of time.
dotnet new console -n HospitalApp.Console
dotnet build
dotnet run

CLR, CTS and assemblies

The Common Language Runtime manages execution services such as type safety, exceptions, garbage collection and threading. The Common Type System defines how types are represented across .NET languages. An assembly is a deployment/versioning unit containing IL and metadata.

Garbage collection

GC reclaims managed objects that are no longer reachable. It does not promptly close every external resource. Dispose files, sockets and database connections with using; GC is not a substitute for deterministic disposal.

Hosting and configuration

ASP.NET Core hosting configures dependency injection, logging, configuration and application lifetime. Development, test and production should use separate settings. Keep secrets outside source control and restrict production access.

Diagnostics

  • dotnet --info inspects SDK/runtime installations.
  • Use structured logs and correlation IDs to trace an appointment request.
  • Profile CPU and allocations before optimizing.
  • Record runtime, OS, configuration and deployment mode when diagnosing environment-specific failures.
