PRODUCTION ENGINEERING

CI/CD and cloud roadmap

Learn one end-to-end pipeline, then compare the equivalent services in the major cloud providers. Avoid trying to master every vendor at once.

Phase 1 — CI/CD pipeline fundamentals

A typical pipeline is: commit/pull request → restore dependencies → compile/build → unit tests → integration tests → static analysis/security scans → package artifact/container → publish artifact → deploy to staging → smoke tests → approval → production deployment → health verification.

Understand pipeline YAML, secrets, variables, agents/runners, caching, artifacts, environment protection, approvals, release gates and rollback.

Phase 2 — Common CI/CD platforms

  • GitHub Actions: natural choice when source code and pull requests live in GitHub; workflows, jobs, runners, environments and reusable actions.
  • Azure DevOps Pipelines: common in Microsoft enterprise environments; YAML pipelines, agents, environments, approvals, artifacts and integration with Azure Boards/Repos.
  • GitLab CI/CD: integrated pipelines, runners, stages, environments and registry.
  • Jenkins: highly extensible automation server, often found in established enterprise/on-premise estates; requires plugin and controller maintenance.

Phase 3 — Cloud service map

Learn the service category first; names are examples, not identical products.

  • Compute / app hosting: Azure App Service and Azure Container Apps; AWS App Runner, Elastic Beanstalk and ECS; Google Cloud Run and App Engine.
  • Virtual machines: Azure Virtual Machines; Amazon EC2; Google Compute Engine.
  • Containers / Kubernetes: Azure Kubernetes Service (AKS); Amazon EKS; Google Kubernetes Engine (GKE).
  • Managed relational databases: Azure SQL Database / Azure Database for MySQL; Amazon RDS / Aurora; Cloud SQL.
  • Object storage: Azure Blob Storage; Amazon S3; Google Cloud Storage.
  • Identity and secrets: Microsoft Entra ID / Key Vault; AWS IAM / Secrets Manager; Google Cloud IAM / Secret Manager.
  • Networking: Azure VNet; AWS VPC; Google VPC, plus DNS, load balancers, firewall and private networking.
  • Monitoring: Azure Monitor / Application Insights; CloudWatch / X-Ray; Cloud Monitoring / Logging / Trace.

Phase 4 — Infrastructure and operations

  1. Dockerize the API and frontend; use multi-stage builds and non-root containers.
  2. Provision network, app hosting, database, storage and secrets using Terraform or native IaC.
  3. Use separate development, staging and production environments.
  4. Deploy with rolling, blue/green or canary strategies where justified.
  5. Implement migrations with backward-compatible expand/contract changes.
  6. Configure logs, metrics, traces, alerts, dashboards and on-call runbooks.
  7. Practice backups, restore tests, RPO/RTO, failover and incident response.

Recommended learning order

Start with GitHub Actions for this GitHub-hosted academy and a simple application. Learn Docker next. Then choose one cloud provider as your primary lab: Azure is a natural first path for a .NET/SQL Server enterprise stack; AWS and GCP comparisons follow after the core concepts are understood. Learn Azure DevOps as a second pipeline platform because it is common in Microsoft-centric organizations.
