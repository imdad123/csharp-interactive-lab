DELIVERY ENGINEERING

CI/CD pipelines for every language

Build one consistent delivery pipeline and adapt its build/test commands to C#, PHP, JavaScript/TypeScript and Python.

Pipeline stages

  1. Checkout source and select a pinned SDK/runtime.
  2. Restore dependencies and cache safely.
  3. Lint, format-check, compile and run unit tests.
  4. Run integration tests against disposable test services/databases.
  5. Scan dependencies, source code, containers and secrets.
  6. Build immutable artifact or container image and publish it.
  7. Deploy to development/staging, run migrations and smoke tests.
  8. Require approval for production where required.
  9. Deploy using rolling/blue-green/canary strategy and verify health.
  10. Keep rollback and database recovery procedures documented.

Example: .NET pipeline commands

dotnet restore
dotnet format --verify-no-changes
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build
dotnet publish -c Release -o ./publish

Example: PHP pipeline commands

composer install --no-interaction --prefer-dist
vendor/bin/phpunit
vendor/bin/phpstan analyse
vendor/bin/phpcs src

Example: Node.js / TypeScript pipeline commands

npm ci
npm run lint
npm run typecheck
npm test
npm run build

Example: Python pipeline commands

python -m pip install -r requirements.txt
ruff check .
mypy app
pytest --cov=app

Database migrations in deployment

Database changes are often the riskiest part of a release. Prefer backward-compatible expand/contract migrations: add nullable/new structures first, deploy code that supports both shapes, backfill safely, then remove obsolete structures in a later release. Take and verify backups before high-risk changes. Do not assume application rollback automatically reverses database changes.

Deployment strategies and operational checks

Understand rolling, blue/green and canary releases. Add readiness/liveness health checks, smoke tests, alert thresholds, deployment annotations, rollback conditions and a human incident owner.

Cloud mapping

Deploy containers to Azure Container Apps/App Service/AKS, AWS App Runner/ECS/EKS or Google Cloud Run/GKE. Use managed SQL databases, object storage, secret managers, IAM and monitoring services. Start with one provider and compare service categories rather than memorizing vendor names.
