MODULE 10 · PROFESSIONAL GUIDE

Angular for .NET developers

TypeScript, components, templates, signals, routing, forms, HttpClient, interceptors, guards, RxJS, state, accessibility and API integration.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. TypeScript and Angular foundations

Why it exists. Angular applications need type-safe models and predictable component boundaries when they grow beyond a few screens.

Professional practice. Use strict TypeScript, standalone components, typed interfaces and feature-oriented organization.

Example / implementation direction

export interface PatientSummary { id: number; medicalRecordNo: string; fullName: string; }

HMS exercise: Create typed patient and appointment models from the API contract.

2. Components, templates and signals

Why it exists. Components own UI behavior; signals provide a straightforward reactive state primitive for local and derived state.

Professional practice. Keep components focused, use inputs/outputs and computed state, and move reusable business access into services.

Example / implementation direction

readonly selectedPatient = signal(null);
readonly hasSelection = computed(() => this.selectedPatient() !== null);

HMS exercise: Build a patient search result component with selection state.

3. Routing, lazy loading and guards

Why it exists. Routes organize application features and allow role-aware navigation, but guards are not server authorization.

Professional practice. Use lazy-loaded feature routes, resolvers where appropriate and guards for UX only; API still enforces access.

Example / implementation direction

export const routes: Routes = [{ path: 'patients', loadComponent: () => import('./patients.page').then(m => m.PatientsPage) }];

HMS exercise: Create lazy routes for patients, appointments and billing.

4. Reactive forms and validation

Why it exists. Forms need immediate feedback while preserving server authority for business validation.

Professional practice. Use typed reactive forms, validators, async checks carefully and map API validation errors back to fields.

Example / implementation direction

this.form = new FormGroup({ fullName: new FormControl('', {nonNullable:true, validators:[Validators.required, Validators.maxLength(160)]}) });

HMS exercise: Build a patient registration form that displays server-side errors.

5. HttpClient, interceptors and auth

Why it exists. Frontend services should isolate HTTP details and centralize cross-cutting behavior.

Professional practice. Use typed HttpClient calls, functional interceptors for correlation/auth, safe token storage and explicit error mapping.

Example / implementation direction

this.http.get('/api/patients', { params: { search } });

HMS exercise: Connect patient search to the ASP.NET Core API with loading and error states.

6. RxJS, state and accessibility

Why it exists. Asynchronous streams need cancellation and composition; accessible interfaces must work beyond mouse-only interaction.

Professional practice. Use switchMap for changing searches, debounceTime for input, takeUntilDestroyed and semantic labels/focus management.

Example / implementation direction

this.search.valueChanges.pipe(debounceTime(250), distinctUntilChanged(), switchMap(q => this.api.searchPatients(q)), takeUntilDestroyed()).subscribe();

HMS exercise: Implement cancellable patient search and keyboard-accessible results.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
