MODULE 16 · PROFESSIONAL GUIDE

Enterprise Hospital Management capstone

Design and deliver a secure HMS with SQL Server, EF Core, ASP.NET Core APIs, Angular administration, MAUI patient/staff app, tests, deployment and operational runbooks.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. Domain scope and architecture

Why it exists. The capstone proves that the stack works as one system with clear ownership and safe workflows.

Professional practice. Define bounded contexts, roles, data classification, audit requirements and non-functional targets before coding.

Example / implementation direction

// Modules: Identity, Patients, Scheduling, Admissions, Pharmacy, Billing, Reporting

HMS exercise: Create the context map and threat model for the hospital platform.

2. Database and persistence implementation

Why it exists. A reliable HMS depends on constraints, transactions and query performance more than ORM abstractions.

Professional practice. Build SQL schema, indexes and procedures; map with EF Core and verify generated SQL for critical endpoints.

Example / implementation direction

// Patient -> Appointment -> Encounter -> Invoice
// Use FK constraints, unique MRN and rowversion concurrency.

HMS exercise: Implement patient and appointment schema plus EF Core migrations.

3. API, validation and security

Why it exists. Healthcare APIs must protect every patient resource and return stable, validated contracts.

Professional practice. Implement DTOs, Problem Details, policies, audit events, rate limits and integration tests.

Example / implementation direction

// POST /api/appointments
// Validate patient access, doctor availability and idempotency key.

HMS exercise: Deliver secure appointment booking and patient history APIs.

4. Angular administration client

Why it exists. Staff need fast, accessible workflows with role-aware navigation and consistent server validation.

Professional practice. Build feature routes, typed API services, forms, search, pagination and live ward updates.

Example / implementation direction

// Features: patients, schedules, admissions, pharmacy, billing, reports

HMS exercise: Deliver an Angular staff portal using the same API contract.

5. MAUI patient and staff client

Why it exists. Mobile users need resilient workflows and careful storage of sensitive information.

Professional practice. Build login, appointment booking, notifications and limited offline support; minimize local health data.

Example / implementation direction

// Features: patient appointments, reminders, profile and secure sign-out

HMS exercise: Deliver a mobile app that books and views appointments.

6. Distributed workflows and operations

Why it exists. Cross-module workflows need reliable events, idempotency and observability before they need service decomposition.

Professional practice. Add outbox-based reminders and reporting; extract a service only with measured justification.

Example / implementation direction

// AppointmentBooked -> ReminderRequested -> NotificationSent
// All handlers idempotent and traceable.

HMS exercise: Demonstrate reliable reminders, monitoring, deployment and recovery.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
