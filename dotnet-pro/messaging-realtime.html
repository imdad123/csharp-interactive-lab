MODULE 13 · PROFESSIONAL GUIDE

Messaging, background work and realtime

Hosted services, queues, broker fundamentals, retries, dead-letter queues, scheduling, SignalR, WebSockets, backpressure and reliable delivery.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. Hosted services and durable background jobs

Why it exists. Long-running work should not depend on a browser request staying open or a single process remaining alive.

Professional practice. Use BackgroundService for process-local tasks and a durable queue/job system for work that must survive restarts.

Example / implementation direction

public sealed class ReminderWorker(ILogger log) : BackgroundService { protected override Task ExecuteAsync(CancellationToken stoppingToken) => Task.CompletedTask; }

HMS exercise: Create a reminder worker and explain what happens if the process restarts.

2. Retries, backoff and dead-letter handling

Why it exists. Transient failures occur in networks and dependencies; unlimited retries can amplify outages.

Professional practice. Use bounded exponential backoff with jitter, classify transient errors and route poison messages for inspection.

Example / implementation direction

// Retry transient timeout; do not retry invalid patient data indefinitely.

HMS exercise: Simulate an unavailable SMS provider and verify bounded retry behavior.

3. Scheduling and recurring jobs

Why it exists. Recurring reminders, reports and cleanup need durable schedules and overlap control.

Professional practice. Use a scheduler with persisted job state, idempotent execution and distributed coordination when multiple instances run.

Example / implementation direction

// Job key: appointment-reminder:{appointmentId}:{reminderWindow}

HMS exercise: Schedule reminders without sending duplicates after a restart.

4. SignalR and realtime updates

Why it exists. Polling creates unnecessary load and delayed feedback for live operational dashboards.

Professional practice. Use SignalR hubs with authenticated groups, server-side authorization and reconnect-aware clients.

Example / implementation direction

await hubContext.Clients.Group($"ward:{wardId}").SendAsync("BedStatusChanged", update, ct);

HMS exercise: Push bed occupancy updates to authorized ward dashboards.

5. Backpressure and bounded processing

Why it exists. A fast producer can overwhelm memory or downstream services when consumers are slower.

Professional practice. Use bounded channels/queues, concurrency limits and load shedding; monitor queue age and depth.

Example / implementation direction

var channel = Channel.CreateBounded(new BoundedChannelOptions(500) { FullMode = BoundedChannelFullMode.Wait });

HMS exercise: Limit reminder throughput and measure queue wait time.
