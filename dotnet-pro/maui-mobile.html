MODULE 11 · PROFESSIONAL GUIDE

.NET MAUI cross-platform apps

MAUI project structure, XAML, MVVM, dependency injection, Shell navigation, data binding, HttpClient, secure storage, offline cache, validation and device capabilities.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. MAUI project structure and XAML

Why it exists. MAUI provides a shared app model with platform-specific integration where needed.

Professional practice. Understand Platforms, Resources, MauiProgram, XAML compilation and target-specific capabilities.

Example / implementation direction

builder.UseMauiApp().ConfigureFonts(fonts => { fonts.AddFont("OpenSans-Regular.ttf", "OpenSansRegular"); });

HMS exercise: Create an HMS mobile shell targeting Android and Windows initially.

2. MVVM and data binding

Why it exists. Separating view state from UI markup improves testability and keeps code-behind small.

Professional practice. Use CommunityToolkit.Mvvm observable properties and commands; avoid putting business logic in pages.

Example / implementation direction

public partial class PatientViewModel : ObservableObject { [ObservableProperty] private string searchText = ""; [RelayCommand] private Task SearchAsync() => Task.CompletedTask; }

HMS exercise: Build a patient lookup screen with a view model.

3. Navigation and dependency injection

Why it exists. Mobile navigation and service lifetimes differ from web request scopes.

Professional practice. Register app services in MauiProgram, use Shell routes and keep navigation concerns out of domain services.

Example / implementation direction

builder.Services.AddTransient();
builder.Services.AddTransient();

HMS exercise: Navigate from login to appointment list and patient detail.

4. API communication and validation

Why it exists. Mobile clients must handle unreliable networks, expired credentials and server validation consistently.

Professional practice. Use HttpClientFactory patterns, typed clients, cancellation, DTOs and Problem Details mapping.

Example / implementation direction

builder.Services.AddHttpClient(c => c.BaseAddress = new Uri(apiBaseUrl));

HMS exercise: Book an appointment through the shared API and display validation errors.

5. Secure storage and offline behavior

Why it exists. Mobile devices are lost, disconnected and shared; sensitive health data needs deliberate local handling.

Professional practice. Store tokens in SecureStorage, minimize cached patient data, encrypt sensitive local stores and define cache expiry.

Example / implementation direction

await SecureStorage.Default.SetAsync("access_token", token);

HMS exercise: Implement sign-out that clears tokens and sensitive cached data.

6. Device capabilities and release

Why it exists. Camera, notifications and platform permissions differ; release builds require signing and privacy review.

Professional practice. Use abstractions for device features, request permissions at point of need and test on physical devices.

Example / implementation direction

var status = await Permissions.RequestAsync();

HMS exercise: Add a controlled document capture workflow with permission-denied handling.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
