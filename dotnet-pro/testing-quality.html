MODULE 09 · PROFESSIONAL GUIDE

Testing and quality engineering

Unit tests, integration tests, WebApplicationFactory, test containers, SQL integration, mocking boundaries, contract tests, load tests and CI quality gates.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. Unit tests for domain and use cases

Why it exists. Fast feedback isolates business rules from HTTP, database and external dependencies.

Professional practice. Test outcomes and invariants, not private implementation details; use deterministic clocks and explicit test data.

Example / implementation direction

[Fact] public void Confirm_RequiresPendingStatus(){ /* arrange, act, assert */ }

HMS exercise: Test appointment transitions and billing calculation rules.

2. Integration tests for ASP.NET Core

Why it exists. A unit test cannot prove middleware, routing, serialization, DI or database integration works together.

Professional practice. Use WebApplicationFactory and a disposable test database; test the real HTTP contract.

Example / implementation direction

await using var factory = new WebApplicationFactory();
var client = factory.CreateClient();

HMS exercise: Exercise patient registration through HTTP and assert persisted results.

3. Database integration and Testcontainers

Why it exists. Mocks cannot reveal SQL translation, constraints, transaction and provider-specific behavior.

Professional practice. Run integration tests against SQL Server-compatible infrastructure where feasible; isolate databases and clean state reliably.

Example / implementation direction

// Start a disposable SQL Server container in test infrastructure;
// apply migrations; execute repository/API integration tests.

HMS exercise: Verify unique constraints, rowversion and migrations against a real SQL Server engine.

4. Contract and end-to-end tests

Why it exists. Independent Angular, MAUI and API teams need confidence that request/response contracts remain compatible.

Professional practice. Validate OpenAPI changes, test consumer expectations and cover critical workflows end-to-end.

Example / implementation direction

// Contract checks: required fields, enum compatibility, status codes and auth scopes.

HMS exercise: Add tests that protect the mobile client from breaking API changes.

5. Load, security and CI quality gates

Why it exists. A green unit suite does not prove capacity, resilience or dependency security.

Professional practice. Add load profiles, dependency scanning, formatting, analyzers and test reports to CI; define measurable SLOs.

Example / implementation direction

dotnet test --configuration Release
dotnet format --verify-no-changes
dotnet list package --vulnerable

HMS exercise: Run a controlled appointment-search load test and publish results.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
