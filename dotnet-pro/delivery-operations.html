MODULE 15 · PROFESSIONAL GUIDE

Docker, CI/CD and production operations

Dockerfiles, Compose, GitHub Actions/Azure DevOps, secrets, migrations, deployment slots, reverse proxies, TLS, monitoring, rollback and restore drills.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. Docker images and local dependencies

Why it exists. Containers make runtime dependencies repeatable across developer machines and CI agents.

Professional practice. Use multi-stage builds, non-root users, small trusted base images and explicit health checks.

Example / implementation direction

docker build -t hospital-api:dev .
docker run --rm -p 8080:8080 hospital-api:dev

HMS exercise: Containerize API and SQL Server development dependencies.

2. CI pipelines and quality gates

Why it exists. Automated checks prevent broken code and unreviewed dependencies from reaching shared environments.

Professional practice. Build, test, scan, publish immutable artifacts and require review; keep secrets in pipeline secret stores.

Example / implementation direction

dotnet restore
dotnet build -c Release --no-restore
dotnet test -c Release --no-build

HMS exercise: Create a pipeline that blocks deployment when tests fail.

3. Configuration, secrets and TLS

Why it exists. Secrets in repositories or container images are durable leaks; TLS termination and forwarding headers need trusted proxy configuration.

Professional practice. Use managed secrets, rotate credentials, configure HTTPS and trust forwarded headers only from known proxies.

Example / implementation direction

// Load production secrets from the platform secret provider;
// never commit connection strings or signing keys.

HMS exercise: Move database credentials out of appsettings and document rotation.

4. Database deployment and compatibility

Why it exists. Application and database deployments can happen at different times; destructive schema changes can break rolling deployments.

Professional practice. Use expand-migrate-contract, review SQL scripts and coordinate backfills with app compatibility.

Example / implementation direction

dotnet ef migrations script --idempotent -o deploy.sql

HMS exercise: Deploy an additive column, backfill it, switch reads and later remove the old column.

5. Release, rollback and recovery

Why it exists. A release is not complete until rollback and recovery are understood.

Professional practice. Use staged rollout, smoke tests, rollback criteria, backup verification and incident runbooks.

Example / implementation direction

// Release checklist: health, migration status, smoke tests, error rate,
// rollback artifact and verified database restore point.

HMS exercise: Write a production release and database restore runbook.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
