MODULE 02 · PROFESSIONAL GUIDE

SQL Server engineering

Stored procedures, functions, transactions, isolation, locking, indexing, execution plans, Query Store, backup and restore.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. Stored procedures and parameterization

Why it exists. Stored procedures encapsulate database operations and can reduce round trips, but they require clear contracts and permissions.

Professional practice. Use schema-qualified names, typed parameters, SET NOCOUNT ON and THROW; avoid dynamic SQL unless safely parameterized.

Example / implementation direction

CREATE OR ALTER PROCEDURE dbo.GetDoctorSchedule @DoctorId int, @From datetime2, @To datetime2 AS BEGIN SET NOCOUNT ON; SELECT AppointmentId, StartAt, PatientId FROM dbo.Appointment WHERE DoctorId=@DoctorId AND StartAt>=@From AND StartAt<@To; END;

HMS exercise: Create a schedule procedure and call it with typed parameters.

2. Functions, views and procedures: choosing correctly

Why it exists. These database objects serve different purposes; choosing based on habit creates awkward contracts and hidden performance costs.

Professional practice. Use inline table-valued functions for composable relational logic, procedures for operations and views for reusable projections.

Example / implementation direction

CREATE OR ALTER FUNCTION dbo.GetPatientAppointments(@PatientId bigint) RETURNS TABLE AS RETURN (SELECT AppointmentId, StartAt, Status FROM dbo.Appointment WHERE PatientId=@PatientId);

HMS exercise: Compare a view, inline TVF and procedure for a patient history query.

3. Execution plans and Query Store

Why it exists. Performance tuning needs evidence over representative workload, not guesswork based on query text alone.

Professional practice. Capture actual plans, inspect estimates versus actual rows, use Query Store to compare regressions and avoid forced plans without evidence.

Example / implementation direction

-- Inspect workload history in Query Store
SELECT TOP (20) qt.query_sql_text, rs.avg_duration, rs.count_executions FROM sys.query_store_query_text AS qt JOIN sys.query_store_query AS q ON q.query_text_id=qt.query_text_id JOIN sys.query_store_plan AS p ON p.query_id=q.query_id JOIN sys.query_store_runtime_stats AS rs ON rs.plan_id=p.plan_id ORDER BY rs.avg_duration DESC;

HMS exercise: Identify the slowest HMS report query using measured workload data.

4. Index design and maintenance

Why it exists. Indexes speed selected reads but increase write cost, storage and maintenance. Too many indexes can harm throughput.

Professional practice. Use workload evidence, key order, INCLUDE columns, filtered indexes and statistics; avoid routine rebuilds without checking fragmentation and workload.

Example / implementation direction

CREATE INDEX IX_Invoice_Patient_Date ON dbo.Invoice(PatientId, InvoiceDate) INCLUDE (TotalAmount, Status);

HMS exercise: Design and justify indexes for patient invoice history.

5. Concurrency, blocking and deadlocks

Why it exists. Concurrent requests can block or deadlock even when each request works alone.

Professional practice. Capture deadlock graphs, keep transactions short, access resources consistently and retry only known transient failures.

Example / implementation direction

SET DEADLOCK_PRIORITY LOW;
-- Inspect active requests and blocking sessions with DMVs in a controlled environment.

HMS exercise: Reproduce two competing bed allocations and document the resolution strategy.

6. Backup, restore and recovery objectives

Why it exists. A successful backup job does not prove recoverability. Recovery requires tested restore procedures and defined RPO/RTO.

Professional practice. Understand full, differential and log backups, recovery models, point-in-time restore and integrity checks.

Example / implementation direction

BACKUP DATABASE HospitalDb TO DISK='D:\SqlBackups\HospitalDb_full.bak' WITH COMPRESSION, CHECKSUM;
RESTORE VERIFYONLY FROM DISK='D:\SqlBackups\HospitalDb_full.bak' WITH CHECKSUM;

HMS exercise: Write and rehearse a restore runbook on a non-production database.

7. Security, permissions and auditing

Why it exists. Database access should follow least privilege and sensitive healthcare access should be auditable.

Professional practice. Use roles, schemas, parameterized access, encryption strategy and audit requirements; do not grant application users sysadmin.

Example / implementation direction

CREATE ROLE HospitalApiRole;
GRANT SELECT, INSERT, UPDATE ON SCHEMA::dbo TO HospitalApiRole;

HMS exercise: Create a least-privilege application role and test denied operations.
