MODULE 04 · PROFESSIONAL GUIDE

.NET 10 platform and modern tooling

SDK/runtime, solution structure, CLI, NuGet, configuration, options, logging, DI, analyzers, formatting, user secrets and environment management.

Why this module matters: production systems fail when engineers know syntax but not data integrity, operational behavior, security boundaries or failure modes. Learn the reasoning, then implement each exercise in the HMS solution.

1. SDK, runtime and target frameworks

Why it exists. The SDK builds projects while the runtime executes them; installed runtimes and target frameworks are not interchangeable.

Professional practice. Use supported LTS .NET releases for production, pin SDK expectations with global.json when team consistency requires it.

Example / implementation direction

dotnet --info
dotnet --list-sdks
dotnet new webapi -n Hospital.Api

HMS exercise: Create a clean API project and record its SDK and target framework.

2. Solution and project boundaries

Why it exists. A solution organizes deployable apps and reusable libraries; project boundaries help enforce dependency direction.

Professional practice. Separate API, Application, Domain and Infrastructure only where the boundary earns its complexity; avoid circular references.

Example / implementation direction

dotnet new sln -n Hospital
dotnet new classlib -n Hospital.Domain
dotnet sln add Hospital.Domain/Hospital.Domain.csproj

HMS exercise: Create a multi-project solution with dependencies pointing inward.

3. CLI, NuGet and package hygiene

Why it exists. Reproducible builds require controlled dependencies and an understanding of transitive packages.

Professional practice. Use central package management where appropriate, review package provenance, update deliberately and commit lock files when required.

Example / implementation direction

dotnet list package --vulnerable
dotnet restore
dotnet build --no-restore

HMS exercise: Audit package vulnerabilities and remove unused dependencies.

4. Configuration and options

Why it exists. Environment-specific settings must be externalized without leaking secrets into source control.

Professional practice. Use strongly typed options, validation on startup, environment variables and secret stores; keep secrets out of appsettings files.

Example / implementation direction

builder.Services.AddOptions().BindConfiguration("Mail").ValidateDataAnnotations().ValidateOnStart();

HMS exercise: Configure database and email settings for development and staging separately.

5. Dependency injection and lifetimes

Why it exists. DI separates object construction from use, but lifetime mismatches can leak state or capture scoped dependencies.

Professional practice. Understand singleton, scoped and transient; keep business logic independent of the container and avoid service locator patterns.

Example / implementation direction

builder.Services.AddScoped();

HMS exercise: Choose lifetimes for API services, DbContext and stateless helpers and justify each.

6. Logging, diagnostics and analyzers

Why it exists. Production debugging depends on structured context and early feedback from compiler and analyzers.

Professional practice. Use ILogger message templates, correlation IDs, nullable reference types, analyzers and format checks in CI.

Example / implementation direction

logger.LogInformation("Appointment {AppointmentId} booked for {PatientId}", id, patientId);

HMS exercise: Add structured logs without patient secrets or unnecessary personal data.

7. Developer workflow and modern tools

Why it exists. Fast feedback reduces integration risk; tools should automate repeatable checks rather than replace engineering judgment.

Professional practice. Use Visual Studio or VS Code, dotnet format, test explorer, debugger, Git, API clients, containers and local SQL tooling.

Example / implementation direction

dotnet format --verify-no-changes
dotnet test
dotnet publish -c Release

HMS exercise: Create a one-command local verification script for the solution.

Module review checklist

  • Can you explain the problem this tool or pattern solves?
  • Can you implement it without copying a template blindly?
  • Have you tested success, invalid input, concurrency and failure paths?
  • Can you explain its security, performance and operational trade-offs?
