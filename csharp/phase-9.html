PHASE 9 · 15 TOPICS

Phase 9 — Advanced Concurrency and Parallel Programming

Advanced C# and .NET library knowledge for engineers building reliable, high-throughput ASP.NET Core systems. Each topic explains the problem, shows practical code and gives you an implementation task.

Professional rule: understand correctness first, then measure performance. Do not add concurrency, unsafe code, pooling or complex abstractions without a concrete requirement and evidence.

TOPIC 01

CancellationToken and linked cancellation

Why this matters

Server work must stop when a client disconnects, a timeout occurs or shutdown begins. Cancellation is cooperative: each operation must observe and forward the token.

Code example

public async Task<Patient?> FindAsync(Guid id, CancellationToken ct)
{
    ct.ThrowIfCancellationRequested();
    return await db.Patients.SingleOrDefaultAsync(x => x.Id == id, ct);
}

What you must practise

Pass cancellation through controller/endpoint, service, repository, EF Core and HttpClient. Test cancellation while a request is in progress.

TOPIC 02

Task.WhenAll and Task.WhenAny

Why this matters

When independent I/O operations can run together, awaiting them sequentially increases response time. Task.WhenAll joins all operations; WhenAny observes the first completion.

Code example

Task<DoctorDto> doctorTask = doctors.GetAsync(doctorId, ct);
Task<IReadOnlyList<SlotDto>> slotsTask = schedule.GetSlotsAsync(doctorId, day, ct);
await Task.WhenAll(doctorTask, slotsTask);
return new DoctorSchedule(doctorTask.Result, slotsTask.Result);

What you must practise

Fetch doctor details and availability concurrently. Measure sequential and parallel latency and ensure neither task depends on the other's result.

TOPIC 03

ValueTask and ValueTask

Why this matters

ValueTask can reduce allocations when an operation often completes synchronously, but it adds usage constraints. Prefer Task unless profiling shows a real benefit.

Code example

public ValueTask<ClinicSettings> GetSettingsAsync(CancellationToken ct)
    => _cached is not null
        ? ValueTask.FromResult(_cached)
        : new ValueTask<ClinicSettings>(LoadSettingsAsync(ct));

What you must practise

Understand single-consumption and awaiting rules. Benchmark before replacing Task-based APIs.

TOPIC 04

IAsyncEnumerable and async streams

Why this matters

Large result sets should sometimes be processed incrementally rather than fully buffered. Async streams yield elements as asynchronous work completes.

Code example

public async IAsyncEnumerable<PatientRow> StreamPatientsAsync(
    [EnumeratorCancellation] CancellationToken ct = default)
{
    await foreach (var row in db.Patients.AsAsyncEnumerable().WithCancellation(ct))
        yield return new PatientRow(row.Id, row.FullName);
}

What you must practise

Stream a large export and verify cancellation, memory use and database reader lifetime.

TOPIC 05

ConfigureAwait and synchronization context

Why this matters

Await normally captures a context when one exists. Library code may use ConfigureAwait(false) to avoid context capture; ASP.NET Core generally has no legacy request synchronization context.

Code example

public async Task< byte[]> DownloadAsync(HttpClient client, Uri uri, CancellationToken ct)
{
    using var response = await client.GetAsync(uri, ct).ConfigureAwait(false);
    return await response.Content.ReadAsByteArrayAsync(ct).ConfigureAwait(false);
}

What you must practise

Know when ConfigureAwait matters in reusable libraries versus ASP.NET Core application code. Do not add it mechanically.

TOPIC 06

Lock and critical sections

Why this matters

Multiple threads may update shared state at the same time. A lock protects a critical section, but holding it too long harms throughput.

Code example

private readonly object _gate = new();
private int _issued;
public int NextNumber()
{
    lock (_gate) return ++_issued;
}

What you must practise

Protect a small in-memory counter. Then explain why a process-local lock cannot protect data across multiple web servers.

TOPIC 07

Monitor and synchronization primitives

Why this matters

Monitor underlies lock and offers lower-level control. Mutex, SemaphoreSlim, AutoResetEvent and ManualResetEvent solve different coordination problems.

Code example

private readonly SemaphoreSlim _limit = new(3);
public async Task SendAsync(CancellationToken ct)
{
    await _limit.WaitAsync(ct);
    try { await sms.SendAsync(ct); }
    finally { _limit.Release(); }
}

What you must practise

Limit concurrent calls to an SMS provider. Handle cancellation and ensure Release always occurs.

TOPIC 08

SemaphoreSlim and bounded concurrency

Why this matters

Unbounded fan-out can overwhelm SQL Server or an external service. SemaphoreSlim limits how many operations run concurrently.

Code example

await Parallel.ForEachAsync(patientIds,
    new ParallelOptions { MaxDegreeOfParallelism = 4, CancellationToken = ct },
    async (id, token) => await ProcessPatientAsync(id, token));

What you must practise

Process a batch with a deliberate concurrency limit and compare resource use with an unbounded implementation.

TOPIC 09

ConcurrentDictionary and concurrent collections

Why this matters

Ordinary collections are not safe for simultaneous writes. Concurrent collections provide thread-safe operations, but do not make multi-step business workflows automatically atomic.

Code example

private readonly ConcurrentDictionary<Guid, int> _attempts = new();
public int RecordAttempt(Guid userId) =>
    _attempts.AddOrUpdate(userId, 1, (_, old) => old + 1);

What you must practise

Use concurrent collections for in-process counters or caches, not as durable shared state between server instances.

TOPIC 10

Channels and producer-consumer pipelines

Why this matters

A producer may create work faster than a consumer can process it. Channels provide asynchronous producer-consumer coordination and bounded backpressure.

Code example

var channel = Channel.CreateBounded<AppointmentJob>(
    new BoundedChannelOptions(100) { FullMode = BoundedChannelFullMode.Wait });
await channel.Writer.WriteAsync(job, ct);
var next = await channel.Reader.ReadAsync(ct);

What you must practise

Create a bounded in-memory work queue and explain why durable jobs need a persistent broker or database.

TOPIC 11

Parallel.For and Parallel.ForEach

Why this matters

Parallel loops distribute CPU-bound iterations across workers. They are not a substitute for asynchronous I/O and can make small workloads slower.

Code example

Parallel.ForEach(records,
    new ParallelOptions { MaxDegreeOfParallelism = Environment.ProcessorCount },
    record => CalculateRiskScore(record));

What you must practise

Parallelize a CPU-heavy anonymized report calculation and benchmark it against a sequential loop.

TOPIC 12

PLINQ

Why this matters

Parallel LINQ partitions a query across threads. Ordering, shared state and small workloads can reduce its benefit.

Code example

var highRisk = records.AsParallel()
    .WithDegreeOfParallelism(4)
    .Where(IsHighRisk)
    .ToArray();

What you must practise

Benchmark PLINQ for CPU-bound calculations only. Check that predicates are thread-safe and result ordering is not accidentally required.

TOPIC 13

Interlocked and atomic operations

Why this matters

Simple increments and compare-and-swap operations can be performed atomically without taking a general lock.

Code example

private long _processed;
public long Processed => Interlocked.Read(ref _processed);
public void MarkProcessed() => Interlocked.Increment(ref _processed);

What you must practise

Implement an atomic counter and explain why `_count++` is not an atomic operation.

TOPIC 14

Thread safety and race conditions

Why this matters

A race condition occurs when correctness depends on timing between threads. Shared mutable state is a major source of intermittent production defects.

Code example

// Immutable snapshots avoid exposing a mutable shared list.
private ImmutableArray<string> _wards = [];
public ImmutableArray<string> GetWards() => _wards;

What you must practise

Reproduce a race in a test, then remove shared mutation or add correct synchronization.

TOPIC 15

Deadlocks and thread-pool starvation

Why this matters

Deadlocks arise from cyclic waits or blocking on asynchronous work. Thread-pool starvation occurs when workers are blocked faster than the pool can compensate.

Code example

// Avoid this in server code:
// var result = service.GetAsync().Result;
// Prefer:
var result = await service.GetAsync(ct);

What you must practise

Find `.Result`, `.Wait()` and synchronous blocking in a sample API. Replace them and explain the starvation risk.
