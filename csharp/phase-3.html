Phase 3 — Advanced C# Types and Features

Complete topic-by-topic reference with explanations, syntax and practical Hospital Management System examples.

1. Structs

Structs are value types suited to small values with value semantics. Prefer readonly structs when practical and avoid large mutable structs.

public readonly struct WardNumber(int value)
{
    public int Value { get; } = value;
}

2. Classes vs Structs

Classes have reference semantics and support inheritance; structs copy values and cannot inherit from another struct/class. Choose based on identity, copying and lifecycle semantics.

PatientEntity patient = new(10); // class reference
WardNumber ward = new(3);       // struct value

3. Records

Records provide value-based equality and concise data modeling. Record classes are reference types and are useful for DTOs and immutable data.

public sealed record PatientDto(int Id, string Mrn, string Name);
var a = new PatientDto(1, "MR-1", "Amina");
var b = a with { Name = "Sara" };

4. Record classes vs Record structs

record class has reference semantics; record struct has value semantics. Both generate value-oriented equality and useful formatting/deconstruction behavior.

public sealed record class InvoiceDto(int Id, decimal Total);
public readonly record struct Temperature(decimal Celsius);

5. Tuples

Tuples group a small number of related values without declaring a dedicated type. Use named tuple elements for readability; use a named record when the shape is a stable domain contract.

(int Count, decimal Total) summary = (3, 2500m);
Console.WriteLine(summary.Total);

6. ValueTuple

ValueTuple is the mutable value type underlying modern C# tuple syntax. Tuple names are compile-time conveniences and are not a substitute for a domain type.

ValueTuple<int, string> patientKey = (1205, "MR-1205");
Console.WriteLine(patientKey.Item1);

7. Anonymous types

Anonymous types create compiler-generated immutable property containers, commonly for local LINQ projections. They cannot be named as a normal public API contract.

var summary = patients.Select(p => new { p.Id, p.Name }).ToList();

8. Enumerations

Enums define a closed set of named integral constants and make state clearer than magic numbers or strings.

public enum AppointmentStatus { Booked, CheckedIn, Completed, Cancelled }
AppointmentStatus status = AppointmentStatus.Booked;

9. Flags Enum

[Flags] enums combine independent bit values. Assign powers of two and use bitwise operators to combine and test flags.

[Flags]
public enum Permission { None=0, Read=1, Create=2, Update=4, Delete=8 }
var access = Permission.Read | Permission.Update;
bool canUpdate = access.HasFlag(Permission.Update);

10. Pattern Matching

Pattern matching tests a value's shape/type and can bind a matching value. It often replaces nested casts and conditionals.

if (value is PatientDto { Id: > 0 } patient)
    Console.WriteLine(patient.Name);

11. Property patterns

Property patterns match one or more properties in an object and can be nested.

if (appointment is { Status: AppointmentStatus.Booked, Patient.Id: > 0 })
    Console.WriteLine("Valid booked appointment");

12. Relational patterns

Relational patterns compare values using <, <=, > and >= inside pattern expressions.

string ageBand = age switch { < 0 => "Invalid", < 18 => "Child", < 65 => "Adult", _ => "Senior" };

13. List patterns

List patterns match arrays and list-like values by length and element patterns. They are useful for parsing structured sequences.

int[] codes = [10, 20, 30];
if (codes is [10, .., 30]) Console.WriteLine("Expected range");

14. Switch expressions

Switch expressions return a value from pattern arms. Include a discard arm or intentionally handle unmatched input.

string label = status switch
{
    AppointmentStatus.Booked => "Booked",
    AppointmentStatus.Completed => "Completed",
    _ => "Other"
};

15. Deconstruction

Deconstruction assigns tuple or record components into separate variables. It improves readability when a method intentionally returns a small group of values.

var (id, name) = (1205, "Amina");
Console.WriteLine($"{id}: {name}");

16. Extension methods

Extension methods add callable syntax to an existing type without modifying it. Keep them discoverable and avoid hiding important domain operations.

public static class PatientExtensions
{
    public static bool IsAdult(this PatientDto p) => p.Id > 0;
}

17. Indexers

An indexer lets an object be accessed using array-like syntax. Define it when the type naturally represents an indexed collection or keyed view.

public sealed class WardRoster
{
    private readonly List<string> _names = [];
    public string this[int index] => _names[index];
}

18. Operator overloading

Operators can be overloaded for custom value types when the operation is intuitive and consistent with expected mathematical meaning.

public readonly record struct Money(decimal Amount)
{
    public static Money operator +(Money a, Money b) => new(a.Amount + b.Amount);
}

19. Custom conversions

User-defined conversion operators allow a type to convert to/from another type. Prefer explicit conversions when information may be lost or validation is involved.

public readonly record struct PatientId(int Value)
{
    public static explicit operator int(PatientId id) => id.Value;
}

20. Generics

Generics parameterize algorithms and data structures by type while preserving compile-time safety and avoiding casts.

static T First<T>(IReadOnlyList<T> items) => items[0];
int firstId = First(new[] { 10, 20 });

21. Generic classes

A generic class stores or operates on a type parameter chosen by the caller.

public sealed class Result<T>(T? data, string? error)
{
    public T? Data { get; } = data;
    public string? Error { get; } = error;
}

22. Generic methods

Generic methods infer or accept type parameters per call, allowing reusable operations across types.

static T Echo<T>(T value) => value;
string patientName = Echo("Amina");

23. Generic constraints

Constraints restrict type parameters to types that support required operations or relationships.

static int GetId<T>(T entity) where T : IEntity => entity.Id;
public interface IEntity { int Id { get; } }

24. Covariance and Contravariance

Covariance (out) allows a more derived output type to be used where a base output is expected. Contravariance (in) reverses that relationship for inputs.

IEnumerable<string> names = new List<string>();
IEnumerable<object> values = names; // covariance
Action<object> logAny = o => Console.WriteLine(o);
Action<string> logName = logAny; // contravariance

25. is, as and typeof

is tests runtime compatibility and can bind a value; as attempts a reference/nullable conversion and returns null on failure; typeof obtains a Type at compile time.

if (obj is PatientDto dto) Console.WriteLine(dto.Name);
var text = obj as string;
Type type = typeof(PatientDto);

26. nameof and typeof

nameof produces a compile-time identifier string, useful for argument exceptions and refactoring-safe property names. typeof returns runtime type metadata.

throw new ArgumentNullException(nameof(patient));
Type dtoType = typeof(PatientDto);

27. Attributes

Attributes attach declarative metadata to program elements. Frameworks use them for validation, routing, serialization and testing.

[Obsolete("Use PatientSummaryDto")]
public sealed class LegacyPatientDto { }

28. Custom attributes

Custom attributes define application-specific metadata. Attribute classes normally derive from System.Attribute and can be inspected through reflection.

[AttributeUsage(AttributeTargets.Class)]
public sealed class AuditedAttribute : Attribute { }
[Audited] public sealed class PatientRecord { }

29. Reflection

Reflection inspects types and members at runtime. It powers serializers, dependency injection and test frameworks, but can be slower and less compile-time safe than direct calls.

Type type = typeof(PatientDto);
foreach (var property in type.GetProperties())
    Console.WriteLine(property.Name);

30. Dynamic programming features (dynamic)

dynamic bypasses compile-time member checking and resolves operations at runtime. It can help with COM/interoperability or dynamic payloads, but runtime binder errors are possible.

dynamic payload = new System.Dynamic.ExpandoObject();
payload.PatientName = "Amina";
Console.WriteLine(payload.PatientName);
