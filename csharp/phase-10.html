PHASE 10 · 15 TOPICS

Phase 10 — Files, Streams, Serialization and Networking

Advanced C# and .NET library knowledge for engineers building reliable, high-throughput ASP.NET Core systems. Each topic explains the problem, shows practical code and gives you an implementation task.

Professional rule: understand correctness first, then measure performance. Do not add concurrency, unsafe code, pooling or complex abstractions without a concrete requirement and evidence.

TOPIC 01

File and directory APIs

Why this matters

Applications import documents, export reports and read configuration files. File APIs provide path and directory operations, but paths and permissions must be handled safely.

Code example

var directory = Path.Combine(rootPath, "patient-documents");
Directory.CreateDirectory(directory);
var path = Path.Combine(directory, $"{documentId:N}.pdf");
await File.WriteAllBytesAsync(path, pdfBytes, ct);

What you must practise

Create an export folder, handle missing directories and avoid accepting arbitrary user-supplied filesystem paths.

TOPIC 02

Streams and stream composition

Why this matters

Streams abstract sequential data access across files, memory, network and compression. They allow processing without loading every byte into memory.

Code example

await using var input = File.OpenRead(sourcePath);
await using var output = File.Create(destinationPath);
await input.CopyToAsync(output, ct);

What you must practise

Copy a large file and compare streaming with File.ReadAllBytesAsync for memory use.

TOPIC 03

MemoryStream and buffering

Why this matters

MemoryStream provides an in-memory stream useful for small payloads, tests and transformations. Large payloads should not be buffered without limits.

Code example

await using var buffer = new MemoryStream();
await reportStream.CopyToAsync(buffer, ct);
buffer.Position = 0;
await buffer.CopyToAsync(destination, ct);

What you must practise

Build a small PDF export test using MemoryStream. Add size limits before using the same approach for user uploads.

TOPIC 04

BinaryReader and BinaryWriter

Why this matters

Binary formats store primitive values compactly and require a clearly defined schema, byte order and versioning strategy.

Code example

await using var stream = File.Create("ward.bin");
using var writer = new BinaryWriter(stream);
writer.Write(1); // format version
writer.Write("Ward A");
writer.Write(24);

What you must practise

Write and read a small versioned binary record. Explain why public interchange formats usually need stronger compatibility guarantees.

TOPIC 05

Text encodings and Unicode

Why this matters

Text is bytes interpreted using an encoding. Incorrect assumptions about UTF-8, UTF-16, normalization or culture can corrupt names and identifiers.

Code example

var bytes = Encoding.UTF8.GetBytes("Patient: زینب");
var text = Encoding.UTF8.GetString(bytes);

What you must practise

Round-trip multilingual patient names and test normalization and invalid byte sequences.

TOPIC 06

System.Text.Json serialization

Why this matters

Serialization converts objects to JSON for APIs, files and messaging. Explicit options and DTOs keep the wire contract predictable.

Code example

var options = new JsonSerializerOptions(JsonSerializerDefaults.Web);
string json = JsonSerializer.Serialize(response, options);
var copy = JsonSerializer.Deserialize<PatientResponse>(json, options);

What you must practise

Test null values, enum representation, date/time formats and backwards compatibility of stored JSON.

TOPIC 07

Custom JSON converters

Why this matters

Converters handle types whose wire representation differs from their default representation, such as strongly typed IDs or special date formats.

Code example

public sealed class PatientIdConverter : JsonConverter<PatientId>
{
    public override PatientId Read(ref Utf8JsonReader r, Type t, JsonSerializerOptions o)
        => new(r.GetGuid());
    public override void Write(Utf8JsonWriter w, PatientId v, JsonSerializerOptions o)
        => w.WriteStringValue(v.Value);
}

What you must practise

Implement and test a converter for a value object. Reject malformed values clearly.

TOPIC 08

XML serialization and XML APIs

Why this matters

Some healthcare and enterprise integrations use XML. Know when to use XmlSerializer, XDocument and XmlReader, especially for large documents.

Code example

var document = XDocument.Load(xmlPath);
var patientName = document.Root?
    .Element("Patient")?.Element("Name")?.Value;

What you must practise

Parse a sample partner XML document. Handle missing nodes and namespaces without assuming the input is trustworthy.

TOPIC 09

Compression with GZipStream

Why this matters

Compression reduces storage and transfer size at the cost of CPU. It is useful for suitable exports and data streams.

Code example

await using var source = File.OpenRead(inputPath);
await using var target = File.Create(outputPath);
await using var gzip = new GZipStream(target, CompressionMode.Compress);
await source.CopyToAsync(gzip, ct);

What you must practise

Compress and decompress a report. Measure file size and elapsed time.

TOPIC 10

Cryptographic hashing

Why this matters

Hashes provide fixed-size digests for integrity checks and content addressing. Passwords require dedicated password hashing algorithms, not plain SHA-256.

Code example

byte[] digest = SHA256.HashData(fileBytes);
string hex = Convert.ToHexString(digest);

What you must practise

Verify a downloaded file against a trusted checksum. Learn why hashes do not encrypt data and why password storage needs Argon2id, scrypt or PBKDF2.

TOPIC 11

HttpClient fundamentals

Why this matters

HttpClient sends HTTP requests and manages connections. Repeatedly creating and disposing clients incorrectly can cause socket exhaustion and connection problems.

Code example

public sealed class SmsGateway(HttpClient client)
{
    public Task<HttpResponseMessage> SendAsync(SmsRequest request, CancellationToken ct)
        => client.PostAsJsonAsync("messages", request, ct);
}

What you must practise

Use IHttpClientFactory or typed clients in ASP.NET Core, configure timeouts and handle non-success responses.

TOPIC 12

Sockets and TCP fundamentals

Why this matters

TCP provides a reliable byte stream, not message boundaries. Socket code requires framing, cancellation, timeout and resource management.

Code example

using var client = new TcpClient();
await client.ConnectAsync("localhost", 9000, ct);
await using NetworkStream stream = client.GetStream();
await stream.WriteAsync(payload, ct);

What you must practise

Build a small local TCP client/server exercise and explain partial reads, framing and why HTTP is often preferable.

TOPIC 13

Pipelines and System.IO.Pipelines

Why this matters

Pipelines support high-performance parsing of streaming data with fewer allocations. They are useful for protocol and high-throughput infrastructure work.

Code example

Pipe pipe = new();
await using var writer = pipe.Writer.AsStream();
await writer.WriteAsync(payload, ct);
await writer.FlushAsync(ct);

What you must practise

Study PipeReader/PipeWriter, buffer advancement and backpressure. Build a framed-message parser.

TOPIC 14

Regular expressions

Why this matters

Regular expressions recognize text patterns and are useful for parsing constrained identifiers, but complex patterns can become slow or unsafe.

Code example

bool validMrn = Regex.IsMatch(mrn, @"^MR-[0-9]{6}$",
    RegexOptions.CultureInvariant | RegexOptions.NonBacktracking);

What you must practise

Validate a known identifier format, add maximum input length and test malformed and adversarial input.

TOPIC 15

Culture-aware formatting and parsing

Why this matters

Dates, numbers and currency vary by culture. Persist machine data in stable formats and format it for users at the presentation boundary.

Code example

string display = amount.ToString("C", CultureInfo.GetCultureInfo("en-PK"));
string invariant = amount.ToString(CultureInfo.InvariantCulture);

What you must practise

Test decimal and date parsing under multiple cultures. Never rely on server machine culture for persisted values.
