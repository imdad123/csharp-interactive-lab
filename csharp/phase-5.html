Phase 5 — LINQ

Complete topic-by-topic reference with explanations, syntax and practical Hospital Management System examples.

1. Introduction to LINQ

LINQ provides a consistent query model for in-memory collections and provider-backed data sources such as EF Core. It separates what data is needed from iteration details.

var adults = patients.Where(p => p.Age >= 18);

2. LINQ Query Syntax

Query syntax resembles SQL and is useful for joins and grouped queries. It compiles into method calls.

var names = from p in patients where p.Age >= 18 select p.Name;

3. LINQ Method Syntax

Method syntax chains extension methods and is common for fluent filtering, projection and sorting.

var names = patients.Where(p => p.Age >= 18).Select(p => p.Name).ToList();

4. Lambda expressions

Lambdas are inline functions used as delegates or expression trees. A lambda can capture local variables, so be mindful of closure lifetime.

var overdue = invoices.Where(i => i.DueDate < today);

5. Expression trees

Expression trees represent code as data, allowing providers such as EF Core to inspect and translate expressions into SQL.

Expression<Func<Patient, bool>> filter = p => p.Age >= 18;
var query = db.Patients.Where(filter);

6. Func, Action and Predicate

Func returns a value, Action returns void, and Predicate returns bool. They are common delegate types used by .NET APIs.

Func<Patient, string> name = p => p.Name;
Action<string> log = Console.WriteLine;
Predicate<Patient> adult = p => p.Age >= 18;

7. Where

Where filters elements matching a predicate. With IQueryable, the provider may translate the filter to SQL.

var active = patients.Where(p => p.IsActive);

8. Select

Select projects each source item into a new shape. Project only required fields when querying a database.

var cards = patients.Select(p => new { p.Id, p.Name });

9. SelectMany

SelectMany flattens nested sequences, such as each patient's appointments into one sequence.

var allAppointments = patients.SelectMany(p => p.Appointments);

10. OrderBy and ThenBy

OrderBy sorts by the first key; ThenBy adds secondary ordering. Use descending variants when needed.

var ordered = patients.OrderBy(p => p.Department).ThenBy(p => p.Name);

11. GroupBy

GroupBy partitions elements by key and supports per-group aggregates. On databases, verify provider translation and result size.

var totals = invoices.GroupBy(i => i.Department).Select(g => new { Department=g.Key, Total=g.Sum(x=>x.Amount) });

12. Join

Join combines sequences by matching key values, like an inner join.

var rows = patients.Join(appointments, p=>p.Id, a=>a.PatientId, (p,a)=>new { p.Name, a.StartsAt });

13. GroupJoin

GroupJoin produces a group of matching inner elements for each outer element, useful for left-join-style projections.

var rows = patients.GroupJoin(appointments, p=>p.Id, a=>a.PatientId, (p,items)=>new { p.Name, Appointments=items });

14. Any and All

Any checks whether at least one item matches; All checks whether every item matches. Both can short-circuit.

bool hasDebt = patients.Any(p => p.Balance > 0);
bool allHaveMrn = patients.All(p => !string.IsNullOrWhiteSpace(p.Mrn));

15. First and FirstOrDefault

First requires a match and throws if none exists. FirstOrDefault returns default when no match exists; with nullable reference types, handle null.

Patient? patient = patients.FirstOrDefault(p => p.Id == id);

16. Single and SingleOrDefault

Single enforces exactly one match; SingleOrDefault allows zero or one. Both throw when multiple matches exist, making them useful for uniqueness assumptions.

Patient? patient = patients.SingleOrDefault(p => p.Mrn == mrn);

17. Last and LastOrDefault

Last returns the final matching element and throws if none exists; LastOrDefault returns default. Some query providers translate these differently, so specify ordering.

var latest = appointments.OrderBy(a => a.StartsAt).LastOrDefault();

18. Count and LongCount

Count returns an int; LongCount returns a long for very large sequences. Prefer database-side counts for large tables.

int todayCount = appointments.Count(a => a.StartsAt.Date == today);

19. Sum, Average, Min and Max

Aggregate operators calculate numeric summaries. Define behavior for empty sequences, especially Average, Min and Max.

decimal total = invoices.Sum(i => i.Amount);
decimal average = invoices.Average(i => i.Amount);

20. Distinct and DistinctBy

Distinct removes duplicate values using equality; DistinctBy removes duplicates based on a selected key.

var departments = patients.Select(p => p.Department).Distinct();
var uniquePatients = patients.DistinctBy(p => p.Mrn);

21. Union, Intersect and Except

Set operators combine, find common elements or subtract elements, using equality semantics.

var all = morning.Union(evening);
var shared = morning.Intersect(evening);
var onlyMorning = morning.Except(evening);

22. Skip and Take

Skip and Take implement offset pagination over ordered data. Always use a deterministic ordering for database paging.

var page = query.OrderBy(p => p.Id).Skip(20).Take(10);

23. SkipWhile and TakeWhile

SkipWhile ignores elements until a predicate becomes false; TakeWhile yields elements only while the predicate remains true. These operate from the sequence start.

var recent = readings.OrderBy(r => r.Time).SkipWhile(r => r.Time < cutoff);

24. Aggregate

Aggregate folds a sequence into one result using an accumulator. It is useful for custom reductions but often Sum/Min/Max are clearer.

decimal total = invoiceLines.Aggregate(0m, (sum, line) => sum + line.Amount);

25. ToList and ToArray

ToList and ToArray materialize a query immediately into an in-memory snapshot. Materialization consumes memory and executes provider queries.

var snapshot = query.ToList();

26. Deferred execution

Many LINQ operators build a query that executes only when enumerated. Changes to the source before enumeration may affect results.

var query = patients.Where(p => p.IsActive); // deferred
patients.Add(new Patient { IsActive = true });
var result = query.ToList();

27. Immediate execution

Terminal operations such as ToList, Count and aggregates execute the query immediately.

int count = db.Patients.Count(p => p.IsActive);

28. Lazy evaluation

Lazy evaluation computes values only as they are requested. Iterator methods using yield return are a common implementation.

static IEnumerable<int> Numbers() { yield return 1; yield return 2; }
foreach (var n in Numbers()) Console.WriteLine(n);

29. IQueryable vs IEnumerable

IEnumerable represents in-process iteration; IQueryable builds provider-translatable expression trees. Keep filters/projections/paging on the database side until necessary.

IQueryable<Patient> dbQuery = db.Patients.Where(p => p.Age > 18);
var result = await dbQuery.Select(p => p.Name).ToListAsync(ct);

30. Custom LINQ extension methods

A custom extension can encapsulate a reusable query operation. Keep it predictable and avoid hiding expensive provider operations.

public static class PatientQueries
{
    public static IEnumerable<Patient> WithBalance(this IEnumerable<Patient> source)
        => source.Where(p => p.Balance > 0);
}
