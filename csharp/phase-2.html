Phase 2 — Object-Oriented Programming

A reference guide in the exact roadmap order. Each topic explains the purpose, shows C# syntax, and connects the idea to a realistic Hospital Management System scenario.

1. Introduction to OOP

Object-oriented programming organizes software around objects that combine state and behavior. It helps model entities and enforce rules, but should be used to simplify the domain rather than add layers without purpose.

public sealed class Patient
{
    public string Mrn { get; }
    public Patient(string mrn) => Mrn = mrn;
}

2. Classes and Objects

A class defines a reference type; an object is an instance created from that type. Model identity-bearing entities such as patients and appointments as classes.

var patient = new Patient("MR-1205");
Console.WriteLine(patient.Mrn);

public sealed class Patient(string mrn) { public string Mrn { get; } = mrn; }

3. Fields and Properties

Fields store implementation state. Properties expose controlled access and can validate or compute values. Prefer properties for public APIs and keep fields private.

public sealed class Patient
{
    private string _name = "";
    public string Name { get => _name; set => _name = value.Trim(); }
}

4. Constructors

A constructor establishes a valid initial state when an object is created. Validate required data at the boundary and avoid objects that can exist in an invalid state.

public sealed class Invoice(int id, decimal total)
{
    public int Id { get; } = id > 0 ? id : throw new ArgumentOutOfRangeException(nameof(id));
    public decimal Total { get; } = total >= 0 ? total : throw new ArgumentOutOfRangeException(nameof(total));
}

5. Constructor overloading

Constructor overloading provides multiple creation paths. Use constructor chaining with this(...) to centralize initialization rules.

public sealed class Doctor
{
    public string Name { get; }
    public string Specialty { get; }
    public Doctor(string name) : this(name, "General") { }
    public Doctor(string name, string specialty) => (Name, Specialty) = (name, specialty);
}

6. Static constructors

A static constructor initializes static state once before the type is first used. It has no access modifier or parameters; keep it simple and deterministic.

public static class HospitalDefaults
{
    public static readonly string TimeZoneId;
    static HospitalDefaults() => TimeZoneId = "Pakistan Standard Time";
}

7. Object initializers

Object initializers set accessible properties after construction. They improve readability for DTOs and configuration objects; they do not replace constructor validation for invariants.

var patient = new PatientProfile { Name = "Amina", IsActive = true };

public sealed class PatientProfile { public string Name { get; set; } = ""; public bool IsActive { get; set; } }

8. Encapsulation

Encapsulation hides internal state and exposes operations that protect invariants. Avoid public setters when callers must not bypass business rules.

public sealed class Invoice
{
    private decimal _paid;
    public decimal Balance { get; private set; }
    public void RecordPayment(decimal amount)
    {
        if (amount <= 0 || amount > Balance) throw new ArgumentOutOfRangeException(nameof(amount));
        _paid += amount; Balance -= amount;
    }
}

9. Inheritance

Inheritance models an is-a relationship and reuses a base contract. Use it only when derived types can safely substitute for the base type.

public abstract class Person(string name) { public string Name { get; } = name; }
public sealed class Doctor(string name, string specialty) : Person(name) { public string Specialty { get; } = specialty; }

10. Method overriding

A derived class overrides a virtual or abstract base member to provide specialized behavior. Dispatch is selected at runtime through the base contract.

public class Notification { public virtual string Format(string text) => text; }
public sealed class SmsNotification : Notification { public override string Format(string text) => $"SMS: {text}"; }

11. Method hiding (new)

The new modifier hides an inherited member rather than overriding it. Member selection depends on the compile-time type, so hiding can be surprising.

public class BaseReport { public void Print() => Console.WriteLine("Base"); }
public class DailyReport : BaseReport { public new void Print() => Console.WriteLine("Daily"); }
BaseReport report = new DailyReport(); report.Print(); // Base

12. Polymorphism

Polymorphism allows code to work with a base class or interface while runtime objects provide different implementations. It reduces branching across concrete types.

IEnumerable<INotification> channels = [new Email(), new Sms()];
foreach (var channel in channels) channel.Send("Appointment confirmed");

13. Abstraction

Abstraction exposes essential behavior and hides implementation details. An application service can depend on a repository contract rather than a database vendor.

public interface IPatientReader { Task<PatientDto?> FindAsync(int id, CancellationToken ct); }

14. Abstract classes

An abstract class cannot be instantiated directly and can combine shared implementation with abstract members that derived types must implement.

public abstract class Report { public abstract string Generate(); public void Print() => Console.WriteLine(Generate()); }
public sealed class WardReport : Report { public override string Generate() => "Ward occupancy"; }

15. Interfaces

An interface defines a contract/capability without prescribing a concrete implementation. It supports substitutability, dependency inversion and test doubles.

public interface IClock { DateTimeOffset UtcNow { get; } }
public sealed class SystemClock : IClock { public DateTimeOffset UtcNow => DateTimeOffset.UtcNow; }

16. Interface implementation

A class implements an interface by providing members that satisfy its contract. The compiler checks required members and signatures.

public sealed class PatientRepository : IPatientReader
{
    public Task<PatientDto?> FindAsync(int id, CancellationToken ct) => Task.FromResult<PatientDto?>(null);
}

17. Multiple interface implementation

A class can implement multiple interfaces to expose several independent capabilities. Keep each interface cohesive.

public sealed class PatientDocument : IAuditable, IArchivable
{
    public DateTimeOffset CreatedAt { get; } = DateTimeOffset.UtcNow;
    public void Archive() { }
}

18. Explicit interface implementation

Explicit implementation qualifies the member with the interface name. It is useful when interfaces have conflicting member names or when an implementation should only be accessed through the interface.

public interface IPrintable { void Export(); }
public interface IExportable { void Export(); }
public sealed class Invoice : IPrintable, IExportable
{
    void IPrintable.Export() => Console.WriteLine("Print invoice");
    void IExportable.Export() => Console.WriteLine("Export PDF");
}

19. Sealed classes and methods

sealed prevents inheritance or further overriding. Use it when extension is not part of the intended contract, not as a default for every type.

public class BaseService { public virtual void Run() { } }
public sealed class FinalService : BaseService { public sealed override void Run() { } }

20. Partial classes

Partial allows one type declaration to be split across files. It is commonly used by generated code and designer files; avoid splitting manually without a clear reason.

// Patient.Generated.cs
public partial class PatientForm { private void InitializeControls() { } }
// Patient.cs
public partial class PatientForm { public void Save() { } }

21. Nested classes

A nested class is declared inside another type and can be useful for tightly scoped implementation details. Avoid nesting types merely to shorten names.

public class PatientImport
{
    private sealed class CsvRow { public string Mrn { get; init; } = ""; }
}

22. Static classes

A static class cannot be instantiated and contains only static members. Use it for stateless utilities; do not use it as a global service locator.

public static class MrnFormatter
{
    public static string Normalize(string mrn) => mrn.Trim().ToUpperInvariant();
}

23. this and base keywords

this refers to the current instance and can disambiguate members or chain constructors. base accesses base-class members and constructors.

public class Person(string name) { public string Name { get; } = name; }
public sealed class Doctor(string name, string specialty) : Person(name)
{
    public string Specialty { get; } = specialty;
}

24. Object class and its methods

All .NET classes ultimately derive from object. Important members include ToString, Equals, GetHashCode and GetType. Override equality consistently when defining value-like equality.

public sealed class PatientCode(string value)
{
    public override string ToString() => value;
}

25. Composition vs Inheritance

Composition builds behavior by holding collaborators; inheritance extends a base type. Prefer composition when a type uses another service rather than being a specialized form of it.

public sealed class AppointmentService(INotificationSender sender)
{
    public Task ConfirmAsync(string message, CancellationToken ct) => sender.SendAsync(message, ct);
}

26. Association, Aggregation and Composition

Association means objects know about one another. Aggregation is a whole-part relationship where parts can live independently. Composition implies strong ownership/lifecycle. C# does not enforce these UML distinctions; model them through references and lifecycle rules.

public sealed class Appointment(Patient patient, Doctor doctor)
{
    public Patient Patient { get; } = patient; // associated existing entities
    public Doctor Doctor { get; } = doctor;
}
public sealed class Invoice { private readonly List<InvoiceLine> _lines = []; } // owns its lines
