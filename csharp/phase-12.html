Phase 12 — Modern C# Language Features and Compiler Tooling

Advanced C# and .NET library knowledge for engineers building reliable, high-throughput ASP.NET Core systems. Each topic explains the problem, shows practical code and gives you an implementation task.

Professional rule: understand correctness first, then measure performance. Do not add concurrency, unsafe code, pooling or complex abstractions without a concrete requirement and evidence.

TOPIC 01

Nullable reference types in depth

Why this matters

Nullable annotations let the compiler reason about possible null values. They improve API contracts and prevent many runtime NullReferenceExceptions.

Code example

#nullable enable
public sealed record Patient(string Name, string? Email);
static string DisplayEmail(Patient p) => p.Email ?? "Not provided";

What you must practise

Enable nullable in a project and fix warnings at their source. Distinguish unknown input from genuinely optional domain data.

TOPIC 02

Required members and required properties

Why this matters

Required members force callers to initialize essential state. They help prevent partially constructed objects, especially DTOs and configuration models.

Code example

public sealed class CreatePatientRequest
{
    public required string FullName { get; init; }
    public required DateOnly DateOfBirth { get; init; }
}

What you must practise

Model required and optional request fields. Compare required members with constructor parameters and validation attributes.

TOPIC 03

Init-only setters and immutable initialization

Why this matters

Init-only properties allow initialization while preventing later reassignment through normal code. They support immutable DTO design.

Code example

public sealed class AppointmentRequest
{
    public required Guid PatientId { get; init; }
    public required DateTimeOffset StartsAt { get; init; }
}

What you must practise

Use init-only DTOs and explain that init-only does not make referenced mutable objects deeply immutable.

TOPIC 04

Primary constructors

Why this matters

Primary constructors let classes and structs declare constructor parameters in the type header. They reduce boilerplate but parameters are not automatically properties.

Code example

public sealed class AppointmentService(
    IAppointmentRepository repository,
    ILogger<AppointmentService> logger)
{
    public Task<Appointment?> FindAsync(Guid id, CancellationToken ct)
        => repository.FindAsync(id, ct);
}

What you must practise

Refactor a service to a primary constructor and identify when explicit fields or validation logic make a traditional constructor clearer.

TOPIC 05

Global using directives and implicit usings

Why this matters

Global usings reduce repeated using directives across a project. Implicit usings are SDK-provided global imports enabled by project settings.

Code example

global using System.Collections.Generic;
global using System.Threading;
global using System.Threading.Tasks;

What you must practise

Inspect generated implicit global usings and decide which project-wide imports improve readability.

TOPIC 06

File-scoped namespaces

Why this matters

File-scoped namespaces reduce indentation and keep source files focused on declarations.

Code example

namespace Hospital.Application.Patients;

public sealed record PatientSummary(Guid Id, string Name);

What you must practise

Convert block-scoped namespaces and follow one consistent convention across the solution.

TOPIC 07

Raw string literals and interpolated raw strings

Why this matters

Raw strings simplify JSON, SQL, HTML and multiline templates by reducing escaping. Interpolated raw strings require deliberate brace counts.

Code example

string json = """
{
  "module": "patients",
  "enabled": true
}
""";

What you must practise

Store a JSON sample and a SQL query as raw strings. Keep secrets and user data out of source literals.

TOPIC 08

Collection expressions

Why this matters

Collection expressions provide concise syntax for arrays and collection-compatible targets. They improve readability when target types are clear.

Code example

int[] roomNumbers = [101, 102, 103];
List<string> wards = ["Medical", "Surgical"];
int[] all = [..roomNumbers, 104];

What you must practise

Convert array/list initializers and learn target typing and spread elements.

TOPIC 09

Pattern matching refinements

Why this matters

Modern patterns combine type, property, relational and logical tests. They make branching expressive when patterns remain readable.

Code example

string Classify(int age) => age switch
{
    < 0 => "Invalid",
    < 18 => "Minor",
    >= 18 and < 65 => "Adult",
    _ => "Senior"
};

What you must practise

Replace a nested conditional with a switch expression and test every boundary value.

TOPIC 10

Ref readonly parameters

Why this matters

Ref readonly parameters allow a method to accept a variable by reference while preventing the method from modifying it. They are useful for large value types and API contracts.

Code example

static decimal Calculate(in Money amount)
    => amount.Amount * 1.15m;

What you must practise

Understand value copying, readonly references and when a normal by-value parameter is simpler.

TOPIC 11

Params collections and collection-based parameters

Why this matters

Modern params support can accept collection expressions and more collection shapes, reducing overload proliferation in APIs.

Code example

static void LogEvents(params ReadOnlySpan<string> events)
{
    foreach (var item in events) Console.WriteLine(item);
}

What you must practise

Check the exact language version and supported params collection types. Build a helper that accepts a variable number of values.

TOPIC 12

Extension members in C# 14

Why this matters

C# 14 introduces extension members, extending beyond traditional extension methods. This is a newer language feature and requires a C# 14 compiler.

Code example

// C# 14 extension block example
public static class PatientExtensions
{
    extension(Patient patient)
    {
        public bool HasEmail => !string.IsNullOrWhiteSpace(patient.Email);
    }
}

What you must practise

Compare classic extension methods with C# 14 extension blocks. Verify compiler and SDK version before using in a project.

TOPIC 13

The field keyword in properties (C# 14)

Why this matters

The contextual field keyword lets an auto-property-like accessor validate or transform access to its compiler-generated backing field.

Code example

public string MedicalRecordNumber
{
    get;
    init => field = string.IsNullOrWhiteSpace(value)
        ? throw new ArgumentException("MRN is required")
        : value.Trim();
}

What you must practise

Use field-backed validation in a small value model. Learn the C# 14 compiler support and avoid shadowing identifiers named field.

TOPIC 14

Null-conditional assignment (C# 14)

Why this matters

Null-conditional assignment lets a write occur only when the receiver is non-null, reducing a simple guard without changing null semantics.

Code example

patient?.EmergencyContact = request.EmergencyContact;

What you must practise

Compare with an explicit null check and verify that the right-hand assignment is skipped when the receiver is null.

TOPIC 15

Analyzers, code style and EditorConfig

Why this matters

Compiler analyzers detect correctness, maintainability and style issues before runtime. Consistent rules make large teams safer and reviews faster.

Code example

// .editorconfig
[*.cs]
dotnet_analyzer_diagnostic.severity = warning
dotnet_style_qualification_for_field = false:warning

What you must practise

Enable .NET analyzers, treat selected warnings as errors in CI and document intentional suppressions.
