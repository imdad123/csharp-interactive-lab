What is .NET? Build your first HospitalApp

Before learning C# syntax, understand the platform that compiles, runs and supports your C# applications.

1. The problem .NET solves

A computer's processor executes machine instructions. It does not directly execute the C# source code that a developer writes. A real application also needs memory management, exception handling, libraries, networking, file access and a consistent way to build and run it.

Without a common platform, developers would have to solve many of these infrastructure problems themselves and deal with different operating systems and execution environments.

Why .NET exists: .NET gives developers a shared platform, runtime, libraries and tools so they can focus more on application behavior—such as registering patients and calculating invoices—instead of rebuilding low-level infrastructure.

2. What is .NET?

.NET is a free, open-source, cross-platform developer platform from Microsoft. It includes a runtime, base libraries, SDK tools and application frameworks.

C#

The programming language used to express application logic.

.NET

The platform and runtime that provide execution and libraries.

ASP.NET Core

The framework we'll later use to build web applications and APIs.

EF Core

An object-relational mapper for working with databases from .NET.

SQL Server

The relational database that will store hospital records.

With .NET you can build console programs, web APIs, websites, desktop apps, mobile apps, cloud services and background workers.

3. .NET, SDK, runtime and CLR are not the same thing

.NET SDK — Software Development Kit

The SDK is the developer's toolbox. It includes the command-line interface, build tools, compiler and the components needed to create, build and publish .NET applications.

.NET Runtime

The runtime is what a machine needs to execute a built .NET application. A machine that only runs an application may need the runtime without the full SDK.

CLR — Common Language Runtime

The CLR is the managed execution environment in .NET. It handles services such as garbage collection, exception handling, type safety and execution of managed code.

Base Class Library (BCL)

The BCL supplies reusable types and APIs for strings, collections, dates, files, networking, tasks and many other common operations.

Hospital analogy: Think of the SDK as the workshop and tools used to build the hospital system; the runtime as the environment that operates it; the CLR as the managed execution supervisor; and the libraries as ready-made equipment you can use instead of building every tool yourself.

4. What happens when C# code runs?

Program.cs
Your C# source code
↓ SDK build: C# compiler
Assembly (for example, HospitalApp.dll)
Contains Intermediate Language (IL), metadata and other information
↓ .NET runtime loads the assembly; JIT compiles methods when needed
Native machine instructions
Executed by the processor

The C# compiler normally translates C# into Intermediate Language (IL), not directly into final processor instructions. The runtime's Just-In-Time (JIT) compiler converts IL methods into native machine code as the application executes. Ahead-of-time compilation is also available for certain deployment scenarios.

5. Which .NET version should we learn?

We'll target .NET 10 LTS for this bootcamp and our initial hospital application. It is a supported Long Term Support release. .NET 11 is also supported, but it is a Standard Term Support release.

Microsoft's current support policy lists .NET 10 LTS and .NET 11 STS as supported releases. Always keep the chosen release on its latest servicing patch.

Download .NET 10 SDK from Microsoft · Official .NET support policy

6. Install and verify the SDK on Windows

Install the .NET 10 SDK. You can use Visual Studio with the .NET desktop development workload, or use Visual Studio Code / another editor with the SDK installed.

Open PowerShell or Windows Terminal and run:

dotnet --info
dotnet --list-sdks
dotnet --list-runtimes

dotnet --info displays SDK and environment details. --list-sdks lists installed SDKs. --list-runtimes lists installed runtimes.

Important distinction: Having a runtime installed does not necessarily mean you have the SDK needed to create and compile projects. For development, install the SDK.

7. Create your first real .NET project

We will create a console application because it lets us learn the language and platform without adding web-server complexity yet.

mkdir HospitalManagement
cd HospitalManagement

dotnet new console --name HospitalApp.Console --framework net10.0

cd HospitalApp.Console
dotnet run

What each command means:

CommandPurpose
mkdirCreates a folder for the solution's work.
cdChanges the current directory.
dotnet new consoleUses an SDK template to create a console project.
--nameSets the project name.
--framework net10.0Targets the .NET 10 framework.
dotnet runBuilds and runs the project.

The template may print a simple greeting. That is generated starter code—not magic. We will inspect the files next.

8. Understand the project structure

Open the HospitalApp.Console folder. You should see files similar to these:

HospitalApp.Console/
│
├── HospitalApp.Console.csproj
├── Program.cs
├── bin/
└── obj/

HospitalApp.Console.csproj

This is the project file. It tells the SDK how to build the project, including its target framework and other settings.

<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
  • OutputType: this project produces an executable application.
  • TargetFramework: the .NET version the project targets.
  • ImplicitUsings: enables common namespaces without writing every using directive.
  • Nullable: enables nullable reference type analysis to help detect possible null errors.

Program.cs

This is where our first C# instructions live. Modern console templates use top-level statements, so you do not need to write a class and Main method immediately.

Console.WriteLine("Hospital Management System");
Console.WriteLine("Starting patient registration...");

bin and obj

obj contains intermediate build files. bin contains build outputs. These folders are generated by the SDK; normally you do not edit them manually or commit them to Git.

9. Build versus run

dotnet build
dotnet run

dotnet build compiles the project and reports errors without intentionally starting your application. dotnet run runs the project and builds it first when necessary.

Try introducing a spelling error in Program.cs, run dotnet build, and inspect the compiler error. Fix it and build again. Reading compiler messages is a core developer skill.
