Anatomy of a C# Program

Understand how a .NET application starts, what Program.cs contains, and how the compiler and runtime work together.

What you will learn

  • How a C# application gets its starting point.
  • What Program.cs, Main(), namespaces, and using directives mean.
  • Why modern C# supports top-level statements.
  • How to build and run the Hospital Management System console project.

1. Why does a program need an entry point?

Imagine a hospital opening in the morning. Before staff can register patients, book appointments, or collect payments, the hospital system must start and prepare itself. A computer program has the same requirement: the runtime needs to know where execution begins.

That starting location is called the entry point. In a traditional C# console application, the entry point is the Main() method.

2. The traditional Main method

Open Program.cs in the HospitalApp.Console project and replace its contents with this code:

using System;

namespace HospitalApp
{
    internal class Program
    {
        private static void Main(string[] args)
        {
            Console.WriteLine("================================");
            Console.WriteLine("     HOSPITAL MANAGEMENT SYSTEM");
            Console.WriteLine("================================");

            Console.WriteLine("System started successfully.");
            Console.WriteLine("Welcome to the hospital!");
        }
    }
}

Run the application using dotnet run. Expected output:

================================
     HOSPITAL MANAGEMENT SYSTEM
================================
System started successfully.
Welcome to the hospital!

Understand each part

CodePurpose
using System;Allows types in the System namespace to be referenced by their short names.
namespace HospitalAppGroups related types under a logical name and helps prevent naming conflicts.
internal class ProgramDeclares a class named Program. Internal means it is accessible within the same assembly.
private static void Main(string[] args)Declares the application's entry point.
Console.WriteLine()Writes text followed by a new line to the console.

Why is Main static?

The runtime must be able to start the application before an instance of the Program class exists. A static method belongs to the type itself, so it can be called without first creating a Program object.

Why does Main accept string[] args?

It can receive command-line arguments supplied when the application starts. For example, dotnet run -- report passes the word report to the application. We will use arguments later; for now, understand that they are startup inputs.

Why void?

void means the method does not return a value to its caller. C# also supports entry-point forms that return an integer exit code, and asynchronous entry points; those will make more sense when we study methods and async programming.

3. What is a namespace?

As the hospital application grows, it will contain many types: Patient, Doctor, Appointment, Billing, and Medicine. Namespaces provide logical organization and help avoid naming collisions.

namespace HospitalApp.Patients
{
    internal class Patient
    {
    }
}

namespace HospitalApp.Doctors
{
    internal class Doctor
    {
    }
}

Think of namespaces like departments in a hospital: they organize related responsibilities. A namespace is an organizational name, not a physical folder requirement—although projects often use matching folders for clarity.

4. What does using do?

The fully qualified type name can be written as:

System.Console.WriteLine("Patient registered");

After importing the namespace, the shorter form is available:

using System;

Console.WriteLine("Patient registered");
Important: using System; does not install a package, create an object, or execute code. It lets you refer to types in that namespace without repeatedly writing the full namespace.

The project template has ImplicitUsings enabled in its .csproj file. This automatically imports commonly used namespaces, including System for this project. That is why a new .NET console project may work without an explicit using System;.

5. Modern C#: top-level statements

A new .NET console project may contain only this:

Console.WriteLine("Hello, World!");

There is no visible namespace, class, or Main method. C# supports top-level statements: the compiler generates the entry-point structure for you. This reduces boilerplate in small programs.

Try replacing Program.cs with:

Console.WriteLine("================================");
Console.WriteLine("     HOSPITAL MANAGEMENT SYSTEM");
Console.WriteLine("================================");

Console.WriteLine("System started successfully.");

Run dotnet run. It works too. These are two ways to express an application's entry point, not two different languages.

Professional practice: Learn both forms. We will use the style that best supports the clarity of each stage of our project. Top-level statements are convenient for small apps; an explicit Program class can make the structure more visible while learning.

Rule to remember: top-level statements must appear before namespace and type declarations in the same file.

6. The simplified .NET execution flow

You write C# code
Program.cs
↓
The .NET SDK builds the project
The C# compiler produces Intermediate Language (IL) in an assembly.
↓
The .NET runtime executes it
The runtime uses JIT compilation to turn methods into native machine code as needed.
↓
Your hospital application runs
It can display output and perform its work.

This is a simplified model. The runtime also provides services such as managed memory, garbage collection, exception handling, and type safety.

7. Build versus run

dotnet build

Compiles the project and reports build errors. It does not normally launch the application.

dotnet run

Builds the project if needed, then runs it. Use dotnet build to check whether your code compiles; use dotnet run to execute it.

Lesson summary

  • The entry point tells .NET where application execution begins.
  • Traditional console applications use a Main method.
  • Namespaces organize types and reduce naming conflicts.
  • Using directives make names shorter; they do not install libraries.
  • Top-level statements let the compiler generate the entry-point boilerplate.
  • dotnet build compiles; dotnet run builds if needed and executes.
