Variables, Data Types & Memory Basics

Store and work with real hospital information using C#.

What you will learn

  • What variables solve and how to declare them.
  • How to choose suitable data types.
  • How values and object references behave.
  • How to convert and validate input.
  • What nullable values mean.

1. Why do variables exist?

A hospital registration form contains a patient name, age, phone number, registration number, consultation fee, and admission status. Printing fixed text is not enough: each patient has different information, and the program must store and reuse it.

A variable is a named storage location used by a program to work with a value while it runs.

string patientName = "Ahmad Khan";
int patientAge = 35;
decimal consultationFee = 1500.50m;

These variables let the application reuse patient data without hard-coding the same values in every output statement.

C# is statically typed: each variable has a type known to the compiler. Types help detect invalid operations before the application runs. Adding a patient's age to their name is not a meaningful operation; type checking helps prevent mistakes like that.

Why decimal for money?

For financial values, decimal is generally preferred because it represents base-10 decimal fractions more appropriately than binary floating-point. The m suffix marks a decimal literal.

decimal consultationFee = 1500.50m;

Why is a phone number a string?

string phoneNumber = "03001234567";

A phone number is an identifier, not a quantity. We do not perform arithmetic on it, and a string preserves leading zeros.

4. Build a patient registration summary

Replace Program.cs with this complete example:

using System;

namespace HospitalApp
{
    internal class Program
    {
        private static void Main(string[] args)
        {
            string patientName = "Ahmad Khan";
            int patientAge = 35;
            string phoneNumber = "03001234567";
            decimal consultationFee = 1500.50m;
            bool isAdmitted = false;
            char bloodGroup = 'B';

            Console.WriteLine("===== PATIENT REGISTRATION =====");
            Console.WriteLine($"Patient Name: {patientName}");
            Console.WriteLine($"Age: {patientAge}");
            Console.WriteLine($"Phone: {phoneNumber}");
            Console.WriteLine($"Consultation Fee: Rs. {consultationFee}");
            Console.WriteLine($"Blood Group: {bloodGroup}");
            Console.WriteLine($"Admitted: {isAdmitted}");
        }
    }
}

Run dotnet run. The $ before a string enables string interpolation, so values can be inserted with curly braces: {patientName}.

You could also concatenate strings with +, but interpolation is usually easier to read when combining text and several values.

5. Variables can change

int patientAge = 35;
patientAge = 36;

Console.WriteLine(patientAge); // 36

The first line declares the variable. The next line assigns a new value to the existing variable, so the type is not repeated.

Type inference with var

var patientName = "Ahmad";       // string
var patientAge = 35;             // int
var consultationFee = 1500.50m;  // decimal

var asks the compiler to infer the type from the initial value. It does not turn C# into a dynamically typed language: the variable still has a definite type. Use it when the type is obvious; explicit types can make business meaning clearer.

6. Constants: values that should not change

const decimal RegistrationFee = 500m;

A constant must be assigned when declared and cannot be changed later. This is useful for genuine fixed values. If hospital administrators need to update a fee, that value should eventually come from application configuration or a database—not be hard-coded as a constant.

7. Value types and reference types

C# types are broadly classified as value types and reference types. A value-type assignment copies the value:

int age1 = 35;
int age2 = age1;
age2 = 40;

Console.WriteLine(age1); // 35
Console.WriteLine(age2); // 40

For a reference type, assignment copies the reference. Both variables can then refer to the same object:

Patient patient1 = new Patient();
patient1.Name = "Ahmad";

Patient patient2 = patient1;
patient2.Name = "Bilal";

Console.WriteLine(patient1.Name); // Bilal

class Patient
{
    public string Name { get; set; } = "";
}

Both variables refer to the same Patient object, so changing its Name through patient2 is visible through patient1. This is a conceptual model; the JIT compiler can optimize physical storage. Local variables are not guaranteed to occupy a particular memory region.

Common value types include int, decimal, bool, and char. Common reference types include string, arrays, classes, and objects.

This distinction becomes important when we study classes, collections, and Entity Framework Core.

8. Type conversion and input validation

Sometimes a value arrives as text but must be used as a number:

string ageInput = "35";
int age = int.Parse(ageInput);
Console.WriteLine(age + 5); // 40

int.Parse() throws an exception if the text is not a valid integer. For user input, TryParse() is safer:

Console.Write("Enter patient age: ");

string? input = Console.ReadLine();

if (int.TryParse(input, out int age))
{
    Console.WriteLine($"Patient age: {age}");
}
else
{
    Console.WriteLine("Invalid age. Enter a whole number.");
}

TryParse() returns true when conversion succeeds and false when it fails. The converted value is supplied through the out variable named age.

9. Nullable values

string? input = Console.ReadLine();

The question mark means the variable is allowed to contain null, meaning no value/object is present. For example, a user may submit an empty input. Our project has nullable reference types enabled with <Nullable>enable</Nullable> in its project file. This helps the compiler warn when code may use a missing value.

Lesson summary

  • Variables give names to values that a program needs to store and reuse.
  • Choose data types according to the meaning of the data.
  • Use decimal for many financial calculations and string for identifiers such as phone numbers.
  • Value-type assignment copies a value; reference-type assignment copies a reference.
  • Use TryParse to validate user input without relying on exceptions for normal invalid input.
  • Nullable annotations help identify code paths where values may be missing.
