07 · Delegates, events and async

Pass behavior as data, notify subscribers and build responsive I/O-bound workflows.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Delegates and lambdas

Delegates solve the problem of passing a method as a value. They support callbacks and configurable behavior. Learn delegate declarations and built-in Action, Func and Predicate<T>. Lambdas provide concise function expressions; understand captured variables and closures.

Func<decimal, decimal, decimal> add = (a, b) => a + b;
decimal total = add(100m, 20m);

Events and publisher/subscriber

Events let an object announce that something happened without knowing all subscribers. Learn event declarations, EventHandler patterns, subscription and unsubscription. Unsubscribe when appropriate to avoid retaining objects longer than intended.

Task and async/await

Async/await is mainly about non-blocking I/O. While a database or network call waits, the thread can serve other work. Task represents an operation that may complete later.

public async Task<Patient?> GetPatientAsync(
    int id, CancellationToken cancellationToken)
{
    return await repository.GetByIdAsync(id, cancellationToken);
}

Cancellation and concurrency

  • Pass CancellationToken through async call chains.
  • Use Task.WhenAll for independent operations that can safely run concurrently.
  • Avoid .Result and .Wait() in normal async application code.
  • Avoid async void except event handlers.
  • Do not use Task.Run to disguise I/O-bound work.
  • Understand race conditions and shared mutable state.

HospitalApp practice

  1. Make repository calls asynchronous.
  2. Pass cancellation from API endpoint to database calls.
  3. Raise an appointment-booked event after a successful booking operation.
  4. Keep notifications separate from the core appointment rule.

Deep dive: delegates, events and asynchronous workflows

Delegates pass behavior as data

A report can accept a rule from its caller. Func returns a value; Action returns void; Predicate<T> represents a boolean test.

Func<Appointment, bool> isUrgent = a => a.Priority == Priority.Emergency;
var urgentAppointments = appointments.Where(isUrgent);

Events notify subscribers

When an appointment is confirmed, audit logging, SMS and dashboard refresh may react. The publisher should not need direct references to all subscribers.

public sealed class Appointment : EventArgs
{
    public event EventHandler<int>? Confirmed;
    public void Confirm(int id) => Confirmed?.Invoke(this, id);
}

In-process events are not durable messaging. For reliable cross-service communication, use a broker and an outbox pattern.

Async/await for I/O

SQL Server, payment and SMS calls wait on external I/O. Async APIs free request threads while waiting; async does not automatically speed up CPU-heavy calculations.

public async Task<Patient?> FindAsync(int id, CancellationToken ct)
    => await _db.Patients.FirstOrDefaultAsync(p => p.Id == id, ct);

Propagate CancellationToken from the request to database and HTTP operations. Avoid .Result and .Wait() in request paths. They block threads and hurt scalability.

Concurrency and Task.WhenAll

Independent I/O such as loading clinic details and doctor availability may run concurrently. Limit fan-out and respect provider/database capacity. EF Core DbContext is not thread-safe: do not run concurrent operations on the same instance.

Practice task

  1. Pass a Func<Appointment,bool> to filter emergencies.
  2. Raise an event when an appointment is confirmed.
  3. Implement an async EF Core repository method.
  4. Propagate CancellationToken through every layer.
  5. Compare sequential calls with Task.WhenAll for independent I/O.
