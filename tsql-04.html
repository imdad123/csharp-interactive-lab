15 · SQL performance, indexing and administration

Diagnose query behavior, design indexes from evidence and operate SQL Server safely.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Indexes and key design

Understand heap versus clustered index, nonclustered indexes, included columns, composite key order, unique and filtered indexes, covering indexes, selectivity and cardinality. Index design must match real predicates, joins and ordering.

SARGability, statistics and execution plans

A SARGable predicate can use an index efficiently. Avoid wrapping indexed columns in functions where possible. Watch implicit conversions and mismatched types. Read actual execution plans: scans, seeks, key lookups, sorts, spools, Nested Loops, Hash Match and Merge Join. Compare estimated and actual row counts.

Performance diagnostics

  • SET STATISTICS IO, TIME ON for logical reads and execution timing.
  • Query Store for query, plan and runtime history.
  • Parameter sniffing and parameter-sensitive plan behavior.
  • Extended Events for targeted diagnostics.
  • Index maintenance based on evidence, not blind rebuilds.

Blocking, deadlocks and waits

Diagnose blocking chains, long transactions, wait types and deadlocks. Fix root causes such as unindexed access, inconsistent write order and transactions held open too long. Retry only operations that are safe and idempotent.

Backup, restore and recovery

  • Full, differential and transaction log backups.
  • Simple, full and bulk-logged recovery models.
  • Point-in-time recovery prerequisites.
  • Test restores regularly; a backup is useful only if it can be restored.

SQL Server administration and security

  • SQL Server Agent jobs and schedules.
  • DBCC CHECKDB, database files, filegroups and growth settings.
  • Users, roles, permissions and least privilege.
  • Error logs, monitoring, capacity planning and data migration.
  • High availability and disaster recovery concepts.
  • JSON functions, PIVOT/UNPIVOT, temporal tables, CDC, Change Tracking, full-text search, Service Broker awareness, row-level security, masking and encryption.

HospitalApp performance checklist

  1. Capture baseline IO/time and actual execution plans.
  2. Tune queries and indexes based on workload evidence.
  3. Test blocking and deadlocks under concurrent load.
  4. Schedule backups and test restores in a separate environment.
  5. Document permissions, jobs, maintenance and recovery procedures.

Deep dive: SQL Server performance, operations and reliability

Indexes

Indexes help locate rows but consume storage and add write cost. A candidate index for patient appointment history:

CREATE INDEX IX_Appointments_Patient_ScheduledAt
ON dbo.Appointments(PatientId, ScheduledAt DESC) INCLUDE (Status);

Choose key order from real predicates and sorting. INCLUDE columns can cover a query without widening the key. Measure workload evidence rather than indexing every column.

SARGability and execution plans

-- Less index-friendly
WHERE CAST(ScheduledAt AS date)=@Day;
-- Prefer a range
WHERE ScheduledAt >= @Day AND ScheduledAt < DATEADD(day,1,@Day);

Read actual plans: scans are not always bad and seeks are not always good. Check estimated versus actual rows, key lookups, spills, implicit conversions and statistics. Query Store tracks query plans and runtime history.

Statistics and parameter sensitivity

Statistics help estimate row counts. A query may be fast for one department and slow for another with very different data volumes. Diagnose with Query Store and representative parameters before hints or recompilation.

Blocking, backups and restore

Investigate blocking chains, waits and long transactions; do not kill sessions blindly. Understand full, differential and transaction log backups, recovery models and point-in-time recovery. Define RPO (acceptable data loss) and RTO (acceptable recovery time). A backup is useful only if restore works; perform restore drills.

Administration and security

  • Use least-privilege logins and roles; application accounts should not be sysadmin.
  • Encrypt connections and protect backups and secrets.
  • Patch SQL Server and monitor CPU, memory, disk and job failures.
  • Use SQL Agent for controlled scheduled jobs with alerts.
  • Audit sensitive access and follow health-data retention rules.

Advanced features and practice

Learn JSON functions for integration payloads, PIVOT for report reshaping, temporal tables for row history and CDC for downstream pipelines. Capture an actual plan for a slow appointment search, measure an index, inspect Query Store, restore a backup to a test server and remove unnecessary application permissions.
