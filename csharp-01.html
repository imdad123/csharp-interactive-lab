C# LANGUAGE REFERENCE · TOPICS 01–08

01 · C# foundations

A detailed reference for the language fundamentals used in every C# application. Examples use a HospitalApp.Console project and are written for modern C# / .NET 10 unless a version note says otherwise.

How to use this page: Read the explanation, type each example into a small console project, change the values, observe the output, then complete the practice tasks. Code examples are intentionally small enough to run and modify independently.

Start with a minimal console project

Create a project with the .NET CLI. The SDK supplies the compiler, build tools and runtime targeting packs.

dotnet new console -n HospitalApp.Console
cd HospitalApp.Console
dotnet run

A minimal top-level program:

Console.WriteLine("HospitalApp starting...");
Console.WriteLine($"Runtime: {Environment.Version}");

Top-level statements remove the ceremony of an explicit Program class and Main method for small applications. The compiler still generates an entry point. For larger projects, split code into types and files rather than keeping all logic in Program.cs.

Explicit entry point (traditional form)

namespace HospitalApp.ConsoleApp;

internal static class Program
{
    private static void Main(string[] args)
    {
        System.Console.WriteLine("HospitalApp starting...");
    }
}

Both forms are valid. Understand the explicit form because older codebases, generated code and some advanced scenarios still use it.

1. Variables and data types

A variable is a named storage location with a compile-time type. Types let the compiler reject invalid operations, select the right operations and communicate the meaning of data.

Choose a type that matches the business meaning

int patientId = 1205;                 // whole-number identifier
long nationalIdNumber = 123456789012L; // larger whole number
string patientName = "Amina Khan";
decimal consultationFee = 1800.50m;   // financial amount
double temperatureCelsius = 37.2;    // scientific measurement
bool isRegistered = true;
char bloodGroup = 'A';
DateOnly dateOfBirth = new(1995, 4, 12);
TimeOnly clinicOpens = new(9, 0);
DateTime createdAtUtc = DateTime.UtcNow;
Guid requestId = Guid.NewGuid();

Use decimal for money because decimal fractions such as 0.1 cannot always be represented exactly by binary floating-point. Use double for many scientific calculations where binary floating-point is appropriate. An identifier is not automatically a number: if you never calculate with it, a string may better preserve leading zeros and formatting.

Type inference with var

var patientCount = 25;             // inferred as int
var doctorName = "Dr. Sara";       // inferred as string
var fee = 1250.00m;                // inferred as decimal

// var is still statically typed; it is not dynamic.
patientCount = 30;
// patientCount = "thirty";        // compile-time error

Use var when the right-hand side makes the type obvious, especially with constructors and LINQ. Prefer explicit types when they make important domain meaning clearer.

Constants and readonly fields

const decimal StandardTaxRate = 0.15m;

public sealed class HospitalSettings
{
    public readonly string HospitalCode;

    public HospitalSettings(string hospitalCode)
    {
        HospitalCode = hospitalCode;
    }
}

const is a compile-time constant and is implicitly static. readonly fields can be assigned at declaration or in a constructor. For configuration that changes between environments, use configuration options rather than constants.

Nullable value types

int? assignedDoctorId = null; // appointment not assigned yet
DateOnly? dischargeDate = null;

if (assignedDoctorId.HasValue)
{
    Console.WriteLine(assignedDoctorId.Value);
}

int effectiveDoctorId = assignedDoctorId ?? 0;

Use null to represent “not supplied” only when that is a real business state. Do not silently turn missing values into zero unless zero has a defined meaning.

String interpolation, formatting and immutability

string patient = "Amina";
decimal amount = 1800.5m;

string receiptLine = $"Patient: {patient}; Fee: {amount:N2}";
Console.WriteLine(receiptLine);

string code = "MR-";
code += "00125"; // creates a new string; strings are immutable

For a financial receipt, specify culture deliberately at the presentation boundary:

using System.Globalization;

decimal amount = 1800.50m;
string display = amount.ToString("N2", CultureInfo.GetCultureInfo("en-PK"));
Console.WriteLine(display);

Store the numeric amount in the domain model. Format it as text only when displaying or exporting it.

2. Console input, TryParse and validation

Input from a console, form, API or file is untrusted text. Parsing converts text into a typed value; validation checks whether that value is allowed by the business rules. These are separate steps.

ReadLine and nullable input

Console.Write("Patient name: ");
string? patientName = Console.ReadLine();

if (string.IsNullOrWhiteSpace(patientName))
{
    Console.WriteLine("Patient name is required.");
    return;
}

patientName = patientName.Trim();

ReadLine() can return null when input ends. IsNullOrWhiteSpace catches null, empty and whitespace-only input.

Parse safely with TryParse

Console.Write("Patient age: ");
string? ageText = Console.ReadLine();

if (!int.TryParse(ageText, out int age))
{
    Console.WriteLine("Age must be a whole number.");
    return;
}

if (age is < 0 or > 125)
{
    Console.WriteLine("Age must be between 0 and 125.");
    return;
}

Console.WriteLine($"Validated age: {age}");

Parse decimal values with a known culture

using System.Globalization;

Console.Write("Consultation fee: ");
string? feeText = Console.ReadLine();

bool parsed = decimal.TryParse(
    feeText,
    NumberStyles.Number,
    CultureInfo.InvariantCulture,
    out decimal fee);

if (!parsed || fee < 0)
{
    Console.WriteLine("Enter a valid non-negative fee.");
    return;
}

Choose a culture policy for imported data and user interfaces. A web application should normally rely on model binding and explicit request validation rather than manually parsing every field.

Reusable validation methods

static bool TryValidateAge(int age, out string error)
{
    if (age is < 0 or > 125)
    {
        error = "Age must be between 0 and 125.";
        return false;
    }

    error = string.Empty;
    return true;
}

if (int.TryParse("42", out int age) &&
    TryValidateAge(age, out string error))
{
    Console.WriteLine("Age accepted.");
}
else
{
    Console.WriteLine(error);
}

Do not use exceptions for routine invalid user input. Use TryParse and validation results for expected failures; reserve exceptions for exceptional or violated system conditions.

3. Operators, conditions and branching

Arithmetic and comparison

decimal consultation = 1800m;
decimal laboratory = 750m;
decimal discount = 100m;

decimal total = consultation + laboratory - discount;
bool isHighValue = total >= 2000m;
bool hasValidDiscount = discount >= 0m && discount <= consultation + laboratory;

Console.WriteLine(total);             // 2450
Console.WriteLine(isHighValue);       // True
Console.WriteLine(hasValidDiscount);  // True

Logical operators and short-circuiting

bool patientIsActive = true;
bool doctorIsAvailable = false;

if (patientIsActive && doctorIsAvailable)
{
    Console.WriteLine("Appointment can be booked.");
}

string? patientName = "Amina";
if (patientName is not null && patientName.Length > 2)
{
    Console.WriteLine("Name length is acceptable.");
}

&& stops when the left side is false; || stops when the left side is true. This is useful for null-safe checks, but keep conditions readable.

if / else for ranges and business rules

static string GetAgeGroup(int age)
{
    if (age < 0) return "Invalid";
    if (age < 13) return "Child";
    if (age < 18) return "Adolescent";
    if (age < 60) return "Adult";
    return "Senior";
}

Console.WriteLine(GetAgeGroup(67)); // Senior

switch statement for discrete choices

string departmentCode = "CARD";

switch (departmentCode)
{
    case "CARD":
        Console.WriteLine("Cardiology");
        break;
    case "ORTH":
        Console.WriteLine("Orthopedics");
        break;
    case "ER":
        Console.WriteLine("Emergency");
        break;
    default:
        Console.WriteLine("Unknown department");
        break;
}

Conditional operator and null-coalescing

decimal payable = discount > 0 ? total - discount : total;
string doctorDisplay = assignedDoctorName ?? "Not assigned";
string status = isActive ? "Active" : "Inactive";

Use the conditional operator for a simple expression. If it becomes nested or hard to scan, use if/else.

Guard clauses

static decimal CalculateInvoiceTotal(decimal consultation, decimal lab, decimal discount)
{
    if (consultation < 0) throw new ArgumentOutOfRangeException(nameof(consultation));
    if (lab < 0) throw new ArgumentOutOfRangeException(nameof(lab));
    if (discount < 0 || discount > consultation + lab)
        throw new ArgumentOutOfRangeException(nameof(discount));

    return consultation + lab - discount;
}

Guard clauses reject invalid states early and keep the main calculation uncluttered. The caller should validate ordinary form input before calling this domain method; the method still protects its own invariants.

4. Loops: for, foreach, while and do-while

for when the index matters

string[] departments = ["Emergency", "Cardiology", "Pediatrics"];

for (int index = 0; index < departments.Length; index++)
{
    Console.WriteLine($"{index + 1}. {departments[index]}");
}

foreach for normal traversal

decimal[] dailyCollections = [1200m, 2500m, 1800m];
decimal totalCollection = 0m;

foreach (decimal collection in dailyCollections)
{
    totalCollection += collection;
}

Console.WriteLine($"Total: {totalCollection:N2}");

while for condition-based repetition

int attempts = 0;
bool authenticated = false;

while (!authenticated && attempts < 3)
{
    attempts++;
    Console.WriteLine($"Authentication attempt {attempts}");
    // Replace this line with an authentication operation.
    authenticated = attempts == 2;
}

do-while for a menu that must appear once

string? choice;
do
{
    Console.WriteLine("1. Register patient");
    Console.WriteLine("2. Search patient");
    Console.WriteLine("0. Exit");
    Console.Write("Choice: ");
    choice = Console.ReadLine();

    switch (choice)
    {
        case "1": Console.WriteLine("Registration selected."); break;
        case "2": Console.WriteLine("Search selected."); break;
        case "0": Console.WriteLine("Goodbye."); break;
        default: Console.WriteLine("Invalid choice."); break;
    }
} while (choice != "0");

break and continue

int[] queueNumbers = [101, 102, 0, 104, 105];

foreach (int number in queueNumbers)
{
    if (number == 0) continue; // skip invalid placeholder
    if (number == 104) break;  // stop at a defined cutoff
    Console.WriteLine(number);
}

Use the loop that best expresses the intent. Avoid changing a collection while iterating it with foreach; use a separate result collection or an appropriate indexed loop when mutation is required.

5. Arrays and multidimensional arrays

An array stores a fixed number of elements of one type. Its length cannot grow after creation. Indexes are zero-based.

Declare, initialize, read and update

int[] patientIds = new int[3];
patientIds[0] = 1001;
patientIds[1] = 1002;
patientIds[2] = 1003;

Console.WriteLine(patientIds[0]); // 1001
patientIds[1] = 2002;

string[] wards = ["Medical", "Surgical", "Pediatrics"];
Console.WriteLine(wards.Length);
Console.WriteLine(wards[^1]); // last element

Array traversal and search

int[] waitingNumbers = [14, 8, 21, 5];

foreach (int number in waitingNumbers)
    Console.WriteLine(number);

int position = Array.IndexOf(waitingNumbers, 21);
Console.WriteLine(position); // 2

Array.Sort(waitingNumbers);
Array.Reverse(waitingNumbers);

Multidimensional array: fixed ward/bed grid

// Rows represent wards; columns represent bed positions.
bool[,] occupied =
{
    { true, false, true },
    { false, false, true }
};

for (int ward = 0; ward < occupied.GetLength(0); ward++)
{
    for (int bed = 0; bed < occupied.GetLength(1); bed++)
    {
        Console.WriteLine($"Ward {ward + 1}, Bed {bed + 1}: {occupied[ward, bed]}");
    }
}

Jagged array: rows with different lengths

string[][] doctorShifts =
[
    ["Dr. Ali", "Dr. Sara"],
    ["Dr. Hamza"],
    ["Dr. Noor", "Dr. Zain", "Dr. Hira"]
];

foreach (string[] shift in doctorShifts)
{
    foreach (string doctor in shift)
        Console.WriteLine(doctor);
}

Use a multidimensional array for a rectangular grid. Use a jagged array when each row can have a different number of elements. For real domain data, named classes are often clearer than arrays with positional meanings.

6. List<T> and collection operations

Arrays are fixed-size. List<T> is a resizable generic collection and is the common default for an in-memory sequence that grows or shrinks.

Create, add, read, update and remove

List patientNames = ["Amina", "Bilal"];
patientNames.Add("Hassan");
patientNames.AddRange(["Sara", "Noor"]);

string firstPatient = patientNames[0];
patientNames[1] = "Bilal Ahmed";
bool removed = patientNames.Remove("Hassan");

Console.WriteLine($"Count: {patientNames.Count}");
Console.WriteLine($"Removed: {removed}");

if (patientNames.Count > 0)
    Console.WriteLine(patientNames[0]);

List of domain objects

public sealed class Patient
{
    public int Id { get; init; }
    public required string Name { get; init; }
    public int Age { get; init; }
}

var patients = new List
{
    new() { Id = 1, Name = "Amina", Age = 30 },
    new() { Id = 2, Name = "Bilal", Age = 45 }
};

Patient? found = patients.Find(p => p.Id == 2);
if (found is not null)
    Console.WriteLine(found.Name);

Filter and transform with loops (before LINQ)

var adults = new List();

foreach (Patient patient in patients)
{
    if (patient.Age >= 18)
        adults.Add(patient);
}

foreach (Patient patient in adults)
    Console.WriteLine(patient.Name);

Capacity, count and safe removal

var queue = new List(capacity: 100);
queue.Add(101);
queue.Add(102);

Console.WriteLine(queue.Count);    // actual elements
Console.WriteLine(queue.Capacity); // allocated capacity

queue.RemoveAll(id => id == 101);

Count is the number of elements; Capacity is the current storage allocation. Do not rely on a specific capacity unless you are deliberately tuning performance.

7. IEnumerable<T>, ICollection<T>, IList<T> and IReadOnlyList<T>

These interfaces describe capabilities rather than concrete storage. Programming against the smallest useful contract reduces coupling and makes code easier to test.

TypeWhat it promisesTypical use
IEnumerable<T>Can be iteratedRead/stream a sequence
ICollection<T>Count, add, remove, containsMutable collection contract
IList<T>Indexed access and mutationOrdered, indexable mutable list
IReadOnlyList<T>Count and indexed read accessExpose a read-only list contract

Accept IEnumerable when only iteration is needed

static void PrintPatientNames(IEnumerable patients)
{
    foreach (Patient patient in patients)
        Console.WriteLine(patient.Name);
}

PrintPatientNames(patients);
PrintPatientNames(patients.Where(p => p.Age >= 18));

Return a read-only contract

public sealed class PatientDirectory
{
    private readonly List _patients = [];

    public void Add(Patient patient) => _patients.Add(patient);

    public IReadOnlyList GetAll() => _patients.AsReadOnly();
}

IReadOnlyList<T> prevents callers from using list mutation members through that reference, but it is not a deep immutable snapshot. The underlying list can still change inside the owning class. If callers need a stable snapshot, return a copy.

Why not always use List<T>?

// More flexible: caller can pass an array, List or LINQ query.
static int CountActivePatients(IEnumerable source)
    => source.Count(p => p.Age > 0);

// More restrictive: requires indexed read access.
static Patient? GetAt(IReadOnlyList source, int index)
    => index >= 0 && index < source.Count ? source[index] : null;

8. Dictionary, HashSet, Queue and Stack

Dictionary<TKey,TValue>: fast lookup by key

var patientById = new Dictionary
{
    [1001] = "Amina",
    [1002] = "Bilal"
};

patientById[1003] = "Sara"; // add or replace
if (patientById.TryGetValue(1002, out string? name))
    Console.WriteLine(name);

bool exists = patientById.ContainsKey(1001);
patientById.Remove(1003);

Use TryGetValue when a key may not exist. Avoid checking ContainsKey and then indexing, because that performs two lookups and still leaves a time window for concurrent mutation.

HashSet<T>: uniqueness and membership

var registeredMrns = new HashSet(StringComparer.OrdinalIgnoreCase);
registeredMrns.Add("MR-001");
registeredMrns.Add("mr-001"); // duplicate under this comparer

Console.WriteLine(registeredMrns.Count); // 1
Console.WriteLine(registeredMrns.Contains("MR-001"));

Set operations

var cardiologyDoctors = new HashSet { 1, 2, 3 };
var onCallDoctors = new HashSet { 2, 3, 4 };

var availableForBoth = cardiologyDoctors.Intersect(onCallDoctors);
var allRelevant = cardiologyDoctors.Union(onCallDoctors);
var notOnCall = cardiologyDoctors.Except(onCallDoctors);

Queue<T>: first-in, first-out

var receptionQueue = new Queue();
receptionQueue.Enqueue("Patient A");
receptionQueue.Enqueue("Patient B");
receptionQueue.Enqueue("Patient C");

if (receptionQueue.TryDequeue(out string? nextPatient))
    Console.WriteLine($"Call next: {nextPatient}");

if (receptionQueue.TryPeek(out string? waiting))
    Console.WriteLine($"Next waiting: {waiting}");

Stack<T>: last-in, first-out

var navigationHistory = new Stack();
navigationHistory.Push("Dashboard");
navigationHistory.Push("Patients");
navigationHistory.Push("PatientDetails");

string current = navigationHistory.Pop(); // PatientDetails
string previous = navigationHistory.Peek(); // Patients

These are in-memory data structures, not durable queues or databases. A hospital's real appointment queue must account for persistence, multiple application instances, concurrency, cancellation and audit history.

Integrated practice: reception registration console

This compact example combines input validation, methods, a list, search and a menu. It is an educational in-memory sample; it does not persist data after the process exits.

public sealed record PatientRecord(int Id, string Name, int Age);

var patients = new List();
int nextId = 1;
bool running = true;

while (running)
{
    Console.WriteLine("\n1 Register  2 List  3 Search  0 Exit");
    Console.Write("Choice: ");
    string? choice = Console.ReadLine();

    switch (choice)
    {
        case "1":
            Console.Write("Name: ");
            string? name = Console.ReadLine();

            Console.Write("Age: ");
            string? ageText = Console.ReadLine();

            if (string.IsNullOrWhiteSpace(name) ||
                !int.TryParse(ageText, out int age) ||
                age is < 0 or > 125)
            {
                Console.WriteLine("Invalid patient details.");
                break;
            }

            patients.Add(new PatientRecord(nextId++, name.Trim(), age));
            Console.WriteLine("Patient registered.");
            break;

        case "2":
            foreach (PatientRecord patient in patients)
                Console.WriteLine($"{patient.Id} | {patient.Name} | {patient.Age}");
            break;

        case "3":
            Console.Write("Patient ID: ");
            if (int.TryParse(Console.ReadLine(), out int id))
            {
                PatientRecord? match = patients.Find(p => p.Id == id);
                Console.WriteLine(match is null
                    ? "Patient not found."
                    : $"{match.Id} | {match.Name} | {match.Age}");
            }
            else
            {
                Console.WriteLine("Enter a numeric ID.");
            }
            break;

        case "0":
            running = false;
            break;

        default:
            Console.WriteLine("Unknown option.");
            break;
    }
}

In a larger application, move this code into separate UI, application and domain types. Keep the console responsible for input/output; keep validation and business rules in methods that accept ordinary values and can be tested without simulating a keyboard.

Common mistakes to avoid

  • Using double for money and then discovering rounding surprises.
  • Assuming user input is valid because a textbox or console prompt requested a number.
  • Using Parse for expected invalid input instead of TryParse.
  • Confusing array Length, collection Count and list Capacity.
  • Using a list when a set or dictionary better expresses uniqueness or keyed lookup.
  • Putting SQL queries, UI controls and business calculations in one method.
  • Returning mutable internal collections and allowing callers to change application state.
  • Using exceptions as ordinary branching for expected validation failures.

Practice exercises

  3. Use a Dictionary<int, PatientRecord> to look up patients by ID.
  4. Use a HashSet<string> to reject duplicate MRNs, ignoring letter casing.
  5. Build a reception queue using Queue<PatientRecord>; enqueue, peek and dequeue safely.
  6. Write a method that accepts IEnumerable<PatientRecord> and calculates the average age.
  7. Refactor the integrated example so input, validation, storage and display are separate methods.
