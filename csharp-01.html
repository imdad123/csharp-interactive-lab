01 · C# fundamentals

The building blocks used in almost every C# application. Learn these through HospitalApp.Console.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Why the fundamentals exist

Programs need to represent information, make decisions, repeat operations and organize instructions. Types, expressions, control flow and methods give these operations structure and compile-time safety.

Program structure and types

  • Namespaces, using directives, top-level statements, Main and project structure.
  • Built-in types: int, long, decimal, double, bool, char, string, DateTime, DateOnly.
  • Value types versus reference types; understand references and object lifetime without treating stack/heap rules as absolute.
  • Variables, const, readonly, var, type inference and scope.
  • Conversions, casting, parsing, TryParse and nullable values.
  • Use decimal for financial values; use appropriate date/time types for temporal meaning.
int patientId = 101;
string patientName = "Amina";
decimal fee = 1500.00m;
bool isActive = true;

if (int.TryParse(input, out int age))
    Console.WriteLine($"Age: {age}");

Operators, conditions and branching

  • Arithmetic, comparison, logical, assignment, null-coalescing and conditional operators.
  • if/else for conditions; switch and switch expressions for distinct cases.
  • Boolean logic, short-circuit evaluation, pattern matching and guard clauses.
  • Handle null deliberately; null is not the same as empty string or zero.

Loops and arrays

  • for when index control is needed; foreach for normal collection traversal.
  • while and do/while for condition-based repetition.
  • break and continue; avoid deeply nested control flow.
  • Arrays have fixed length; strings are immutable. StringBuilder helps with repeated large text construction.
foreach (var patient in patients)
{
    Console.WriteLine(patient.Name);
}

Methods and parameters

Methods name a unit of work, enable reuse and create testable boundaries. Learn signatures, return values, overloads, optional/named arguments, static versus instance methods, ref/out/in, expression-bodied members and local functions.

static decimal CalculateTotal(decimal fee, decimal tax)
{
    return fee + tax;
}

var total = CalculateTotal(1500m, 225m);

Pass values into business methods. Do not read directly from TextBox, GridView or HTTP request controls inside domain logic.

HospitalApp practice

  1. Create a console menu: register patient, list patients, search by ID, exit.
  2. Validate names and numeric IDs.
  3. Extract each operation into a method.
  4. Keep Console.ReadLine and Console.WriteLine at the UI boundary.

Deep dive: model a patient registration workflow

Reception registers a patient. Keep console input/output at the boundary so the same business rules can later serve WebForms, mobile apps or an API.

Types represent business meaning

int patientId = 1205;
string mrn = "MR-2026-001205";
string patientName = "Amina Khan";
decimal consultationFee = 1800.00m;
DateOnly dateOfBirth = new(1995, 4, 12);

Use decimal for money because binary floating-point types cannot represent every decimal fraction exactly. Keep currency numeric, not formatted text.

Validate at the boundary

Console.Write("Enter patient age: ");
string? input = Console.ReadLine();
if (!int.TryParse(input, out int age) || age is < 0 or > 125)
{
    Console.WriteLine("Enter a valid age between 0 and 125.");
    return;
}

TryParse handles expected invalid input without using exceptions as normal control flow.

Branching and guard clauses

An appointment may require an active patient and a future date. Guard clauses reject invalid cases early.

static bool CanBookAppointment(bool active, DateOnly date)
{
    if (!active) return false;
    if (date <= DateOnly.FromDateTime(DateTime.Today)) return false;
    return true;
}

Methods create testable units

static decimal CalculateInvoiceTotal(decimal consultation, decimal lab, decimal discount)
{
    if (discount < 0 || discount > consultation + lab)
        throw new ArgumentOutOfRangeException(nameof(discount));
    return consultation + lab - discount;
}
var total = CalculateInvoiceTotal(1800m, 750m, 100m); // 2450.00

The method receives values and returns a result. It does not read a textbox, query SQL Server or print to screen, so it is reusable and unit-testable. Use loops to process changing collections; arrays have fixed length, while List<T> suits patient lists. Strings are immutable; StringBuilder can help with large repeated text construction.

Practice task

  1. Ask for patient name, age and consultation fee.
  2. Reject blank names, invalid ages and negative fees.
  3. Calculate a discount in a separate method.
  4. Display a receipt and keep calculations separate from console I/O.
