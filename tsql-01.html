12 · SQL Server and relational foundations

Design relational data correctly and master the SQL used in everyday development.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Relational database foundations

Tables represent entities and relationships. Keys identify records and constraints protect data integrity. Normalize to reduce update anomalies; denormalize selectively when a measured reporting or performance need justifies it.

Keys, constraints and relationships

  • Primary key uniquely identifies each row.
  • Foreign key enforces a relationship.
  • Unique constraint prevents duplicate values/combinations.
  • Check constraint enforces valid ranges and business constraints.
  • Default supplies a value when omitted.
  • Model one-to-one, one-to-many and many-to-many relationships explicitly.

SQL Server data types

Choose by meaning, range, precision and storage. Use decimal(p,s) for exact financial values, datetime2/date for temporal values and nvarchar for Unicode text. Avoid storing dates or numbers as strings.

SELECT and filtering

SELECT PatientId, PatientName, RegistrationDate
FROM dbo.Patients
WHERE IsActive = 1
  AND RegistrationDate >= @StartDate
ORDER BY RegistrationDate DESC;

Learn SELECT, aliases, WHERE, AND/OR, IN, BETWEEN, LIKE, ORDER BY, TOP, DISTINCT, CASE, CAST, CONVERT and common string/date/numeric functions. Use explicit column lists in production.

NULL and date boundaries

NULL means unknown or absent, not zero or empty. Use IS NULL and IS NOT NULL. Understand COALESCE, ISNULL and NULLIF. For datetime filtering, use half-open ranges: timestamp >= @Start and timestamp < @End.

Deep dive: design the hospital relational database

Relational tables store facts and use keys and constraints to protect correctness. Design around entities and relationships, not a single screen.

CREATE TABLE dbo.Patients
(
 PatientId int IDENTITY PRIMARY KEY,
 MedicalRecordNo varchar(30) NOT NULL UNIQUE,
 PatientName nvarchar(150) NOT NULL,
 DateOfBirth date NULL,
 IsActive bit NOT NULL DEFAULT (1)
);
CREATE TABLE dbo.Appointments
(
 AppointmentId bigint IDENTITY PRIMARY KEY,
 PatientId int NOT NULL REFERENCES dbo.Patients(PatientId),
 ScheduledAt datetime2(0) NOT NULL,
 Status varchar(20) NOT NULL
);

Primary keys identify rows; foreign keys protect relationships; unique constraints prevent duplicate MRNs; NOT NULL prevents missing required values. A foreign key does not decide your deletion policy.

Normalization and types

Store a patient once and reference PatientId from appointments. Repeating patient name and phone creates update anomalies. Use nvarchar for Unicode names, decimal(p,s) for money, date for date-only facts and datetime2 for timestamps.

SELECT, NULL and date ranges

SELECT PatientId, MedicalRecordNo, PatientName
FROM dbo.Patients WHERE IsActive = 1 AND DateOfBirth IS NOT NULL;
DECLARE @Start date='2026-11-01', @End date='2026-12-01';
SELECT AppointmentId, PatientId, ScheduledAt FROM dbo.Appointments
WHERE ScheduledAt >= @Start AND ScheduledAt < @End;

NULL means unknown/absent, not zero or empty. Use IS NULL, not = NULL. Half-open datetime ranges avoid missing rows with time components.
