06 · Modern C#

Use modern language features when they make intent clearer and code safer.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Records and value equality

Records suit data-centric models where value-based equality is useful. Learn positional records, init-only properties and with expressions. Prefer a class when identity and mutable behavior are central.

public sealed record PatientSummary(int Id, string Name);
var changed = summary with { Name = "Amina Khan" };

Tuples and pattern matching

Tuples group a few related values without creating a named type. Use named tuple elements. Pattern matching combines type and value checks; switch expressions map known cases to values.

string label = status switch
{
    AppointmentStatus.Booked => "Scheduled",
    AppointmentStatus.Completed => "Visited",
    AppointmentStatus.Cancelled => "Cancelled",
    _ => "Unknown"
};

Nullable reference types

Nullable reference types provide compile-time analysis for possible null values. They do not guarantee runtime data is non-null. Validate external input and model optional values deliberately.

Modern syntax and APIs

  • Target-typed new, file-scoped namespaces and global using directives.
  • Null-coalescing, null-conditional operators and null patterns.
  • Required members and init-only setters.
  • Extension methods and iterator methods using yield return.
  • Attributes attach metadata; reflection inspects types and members at runtime.

Memory and performance awareness

Understand boxing/unboxing, allocations, Span<T> and ReadOnlySpan<T>, managed versus unmanaged resources, and profiling. Optimize only after measuring a real bottleneck.

HospitalApp practice

Use records for immutable report DTOs, nullable annotations for optional values and pattern matching for appointment status. Do not add advanced performance features without a measured reason.

Deep dive: modern C# features in enterprise code

Records for data-shaped values

DTOs often represent data rather than mutable entities with identity. Records provide concise syntax and value-oriented equality.

public sealed record PatientSummary(int Id, string Name, string Ward);
var first = new PatientSummary(10, "Amina", "Medical");
var updated = first with { Ward = "Surgical" };
Console.WriteLine(first == updated); // False

Records suit request/response models and immutable snapshots, but do not deeply freeze nested objects automatically.

Nullable reference types

A missing phone and an empty phone are different. Nullable annotations help the compiler warn about possible null dereferences.

#nullable enable
string patientName = "Amina";
string? phoneNumber = null;
Console.WriteLine(phoneNumber?.Length ?? 0);

Compiler annotations are not runtime validation: API input still needs validation.

Pattern matching

string GetQueueLabel(AppointmentStatus status) => status switch
{
    AppointmentStatus.Waiting => "Waiting room",
    AppointmentStatus.InConsultation => "With doctor",
    AppointmentStatus.Completed => "Completed",
    AppointmentStatus.Cancelled => "Cancelled",
    _ => "Unknown"
};

Tuples and deconstruction

Tuples work for small local grouped results; public APIs and complex concepts are usually clearer as named records.

static (int Count, decimal Total) Summarize(IEnumerable<Invoice> invoices)
    => (invoices.Count(), invoices.Sum(x => x.Amount));
var (count, total) = Summarize(monthlyInvoices);

Extension methods, reflection and performance

Extension methods add cohesive helper behavior without modifying a type. Reflection inspects metadata at runtime and powers serializers, DI and ORMs; do not use it for ordinary property access. Measure before optimizing; understand allocations, boxing, spans and pooling when profiling identifies a bottleneck.

Practice task

  1. Represent appointment responses as records.
  2. Enable nullable reference types.
  3. Use a switch expression for appointment status.
  4. Compare a tuple report result with a named record.
