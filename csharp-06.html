06 · Modern C#

Use modern language features when they make intent clearer and code safer.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Records and value equality

Records suit data-centric models where value-based equality is useful. Learn positional records, init-only properties and with expressions. Prefer a class when identity and mutable behavior are central.

public sealed record PatientSummary(int Id, string Name);
var changed = summary with { Name = "Amina Khan" };

Tuples and pattern matching

Tuples group a few related values without creating a named type. Use named tuple elements. Pattern matching combines type and value checks; switch expressions map known cases to values.

string label = status switch
{
    AppointmentStatus.Booked => "Scheduled",
    AppointmentStatus.Completed => "Visited",
    AppointmentStatus.Cancelled => "Cancelled",
    _ => "Unknown"
};

Nullable reference types

Nullable reference types provide compile-time analysis for possible null values. They do not guarantee runtime data is non-null. Validate external input and model optional values deliberately.

Modern syntax and APIs

  • Target-typed new, file-scoped namespaces and global using directives.
  • Null-coalescing, null-conditional operators and null patterns.
  • Required members and init-only setters.
  • Extension methods and iterator methods using yield return.
  • Attributes attach metadata; reflection inspects types and members at runtime.

Memory and performance awareness

Understand boxing/unboxing, allocations, Span<T> and ReadOnlySpan<T>, managed versus unmanaged resources, and profiling. Optimize only after measuring a real bottleneck.

HospitalApp practice

Use records for immutable report DTOs, nullable annotations for optional values and pattern matching for appointment status. Do not add advanced performance features without a measured reason.

Deep dive: modern C# features in enterprise code

Records for data-shaped values

DTOs often represent data rather than mutable entities with identity. Records provide concise syntax and value-oriented equality.

public sealed record PatientSummary(int Id, string Name, string Ward);
var first = new PatientSummary(10, "Amina", "Medical");
var updated = first with { Ward = "Surgical" };
Console.WriteLine(first == updated); // False

Records suit request/response models and immutable snapshots, but do not deeply freeze nested objects automatically.

Nullable reference types

A missing phone and an empty phone are different. Nullable annotations help the compiler warn about possible null dereferences.

#nullable enable
string patientName = "Amina";
string? phoneNumber = null;
Console.WriteLine(phoneNumber?.Length ?? 0);

Compiler annotations are not runtime validation: API input still needs validation.

Pattern matching

string GetQueueLabel(AppointmentStatus status) => status switch
{
    AppointmentStatus.Waiting => "Waiting room",
    AppointmentStatus.InConsultation => "With doctor",
    AppointmentStatus.Completed => "Completed",
    AppointmentStatus.Cancelled => "Cancelled",
    _ => "Unknown"
};

Tuples and deconstruction

Tuples work for small local grouped results; public APIs and complex concepts are usually clearer as named records.

static (int Count, decimal Total) Summarize(IEnumerable<Invoice> invoices)
    => (invoices.Count(), invoices.Sum(x => x.Amount));
var (count, total) = Summarize(monthlyInvoices);

Extension methods, reflection and performance

Extension methods add cohesive helper behavior without modifying a type. Reflection inspects metadata at runtime and powers serializers, DI and ORMs; do not use it for ordinary property access. Measure before optimizing; understand allocations, boxing, spans and pooling when profiling identifies a bottleneck.

Practice task

  1. Represent appointment responses as records.
  2. Enable nullable reference types.
  3. Use a switch expression for appointment status.
  4. Compare a tuple report result with a named record.

Worked examples: modern C# features

Nullable reference types

#nullable enable
string patientName = "Amina";
string? middleName = null;

string displayName = middleName is null
    ? patientName
    : $"{patientName} {middleName}";

Nullable reference types add compile-time warnings; they do not add automatic runtime null checks. Enable them in the project and treat warnings as useful design feedback.

Pattern matching with property and relational patterns

static string Triage(int age, int temperature)
    => age switch
    {
        < 0 => "Invalid age",
        >= 65 when temperature >= 39 => "Urgent review",
        _ when temperature >= 39 => "Urgent review",
        _ => "Standard assessment"
    };

Console.WriteLine(Triage(70, 39));

Switch expressions

static decimal GetDiscountRate(string patientCategory) =>
    patientCategory switch
    {
        "Staff" => 0.20m,
        "Senior" => 0.10m,
        "Standard" => 0m,
        _ => throw new ArgumentOutOfRangeException(nameof(patientCategory))
    };

Expression-bodied members

public sealed class Invoice(decimal subtotal, decimal tax)
{
    public decimal Subtotal { get; } = subtotal;
    public decimal Tax { get; } = tax;
    public decimal Total => Subtotal + Tax;
    public bool IsPayable => Total > 0;
}

Use expression-bodied syntax for short, obvious expressions. Prefer a block body when validation, multiple steps or debugging clarity is needed.

Object initializers

var patient = new PatientProfile
{
    FullName = "Amina Khan",
    DateOfBirth = new DateOnly(1995, 4, 12),
    IsActive = true
};

Collection initializers and collection expressions

List<string> departments = new()
{
    "Emergency",
    "Cardiology",
    "Pediatrics"
};

// C# 12 collection expression:
string[] wardCodes = ["MED", "SURG", "ICU"];

Collection expressions are a modern C# feature. Their target type must be known from context. Use a collection initializer when it reads more clearly or when working with older language versions.

Target-typed new

PatientProfile patient = new()
{
    FullName = "Bilal Ahmed",
    IsActive = true
};

List<int> appointmentIds = new() { 101, 102, 103 };

Init-only properties

public sealed class DoctorProfile
{
    public string Name { get; init; } = "";
    public string Specialty { get; init; } = "";
}

var doctor = new DoctorProfile { Name = "Dr. Sara", Specialty = "Cardiology" };
// doctor.Name = "Dr. Noor"; // not allowed after initialization

Required properties

public sealed class PatientDto
{
    public required int Id { get; init; }
    public required string FullName { get; init; }
    public string? Phone { get; init; }
}

var dto = new PatientDto { Id = 1205, FullName = "Amina" };

required enforces initialization at compile time for C# callers. It does not replace runtime validation for HTTP, JSON or database input.

Records and value-based equality

public sealed record Money(decimal Amount, string Currency);

var first = new Money(100m, "PKR");
var second = new Money(100m, "PKR");

Console.WriteLine(first == second); // True: value equality
var revised = first with { Amount = 150m };

Records are useful for immutable data contracts and value-like objects. Database entities with identity and tracked mutable lifecycle are usually modeled as classes.

Structs and enums

public enum AppointmentStatus
{
    Booked,
    CheckedIn,
    Completed,
    Cancelled
}

public readonly record struct Temperature(decimal Celsius);

var status = AppointmentStatus.Booked;
var temperature = new Temperature(37.2m);

Enums improve readability over magic strings, but persist stable values deliberately when storing them in a database or external contract. Structs copy by value; keep them small and immutable when possible.

Extension methods

public static class PatientExtensions
{
    public static bool IsAdult(this PatientProfile patient)
        => patient.Age >= 18;
}

bool adult = patient.IsAdult();

Extension methods add discoverable helper syntax without modifying the original type. Avoid using them to hide important domain behavior or create ambiguous APIs.

Tuples and deconstruction

static (int Count, decimal Total) Summarize(IEnumerable<Invoice> invoices)
    => (invoices.Count(), invoices.Sum(i => i.Total));

var (invoiceCount, amount) = Summarize(openInvoices);
Console.WriteLine($"{invoiceCount} invoices total {amount:N2}");

Advanced LINQ: chunking and distinct projection

var uniqueDepartments = patients
    .Select(p => p.Department)
    .Distinct(StringComparer.OrdinalIgnoreCase)
    .OrderBy(name => name)
    .ToArray();

foreach (var batch in patients.Chunk(2))
    Console.WriteLine($"Processing batch of {batch.Length} patients");

Performance: avoid repeated enumeration

IEnumerable<Patient> query = LoadPatients().Where(p => p.IsActive);

// Bad if the source is expensive or has side effects: enumerates repeatedly.
int count = query.Count();
Patient? first = query.FirstOrDefault();

// Materialize once when a stable in-memory snapshot is intended.
List<Patient> snapshot = query.ToList();
count = snapshot.Count;
first = snapshot.FirstOrDefault();
