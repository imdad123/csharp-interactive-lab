Objects, prototypes and classes

class Patient {
  #name;

  constructor(id, name) {
    if (!Number.isInteger(id) || id <= 0) throw new Error("Invalid id");
    this.id = id;
    this.#name = name.trim();
  }

  get name() { return this.#name; }
  rename(value) {
    if (!value.trim()) throw new Error("Name required");
    this.#name = value.trim();
  }
}

const patient = new Patient(101, "Amina");

JavaScript classes are syntax over the prototype system. Private fields use #. Prefer composition when inheritance does not represent a true “is-a” relationship.

Modules and dependency boundaries

// patient-service.js
export function createPatientService(repository) {
  return {
    async getById(id) {
      return repository.findById(id);
    }
  };
}

// app.js
import { createPatientService } from "./patient-service.js";

ES modules provide explicit imports/exports. Keep domain logic independent from browser DOM, database drivers and HTTP frameworks.

TypeScript interfaces and generics

interface Repository {
  findById(id: TId): Promise;
  save(entity: T): Promise;
}

type PatientDto = {
  id: number;
  fullName: string;
  dateOfBirth?: string;
};

Interfaces and type aliases disappear at runtime; do not treat them as runtime validation. Validate untrusted JSON with a schema or explicit checks.
