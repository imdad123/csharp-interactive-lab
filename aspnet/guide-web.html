ASP.NET Core web fundamentals

Concept, purpose, code examples and production considerations with hospital application scenarios.

Minimal APIs and route groups

Minimal APIs map HTTP routes directly and support DI, filters, validation and OpenAPI. Group endpoints by resource and shared policies.

var patients = app.MapGroup("/api/patients").WithTags("Patients");
patients.MapGet("/{id:int}", async (int id, IPatientService service, CancellationToken ct) =>
    await service.FindAsync(id, ct) is { } p ? Results.Ok(p) : Results.NotFound());
,

MVC controllers

Controllers organize API actions and can use model binding, filters, validation and authorization attributes. Expose DTOs rather than EF entities.

[ApiController]
[Route("api/[controller]")]
public sealed class PatientsController(IPatientService service) : ControllerBase
{
 [HttpGet("{id:int}")]
 public async Task<ActionResult<PatientDto>> Get(int id, CancellationToken ct)
  => await service.FindAsync(id, ct) is { } p ? Ok(p) : NotFound();
}
,

REST API design

Use resource-based URLs, HTTP methods and appropriate status codes. POST creates, GET reads, PUT replaces, PATCH partially updates and DELETE removes/deactivates.

[HttpPost]
public async Task<IActionResult> Create(CreatePatientRequest request, CancellationToken ct)
{
 var id = await service.RegisterAsync(request, ct);
 return CreatedAtAction(nameof(Get), new { id }, new { id });
}

Middleware pipeline

Middleware runs in registration order for each request and can inspect, modify, short-circuit or call the next component. Ordering is essential.

app.UseExceptionHandler();
app.UseHttpsRedirection();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
,

Filters and attributes

MVC filters run around resource, action, exception and result stages. Attributes declare routing, authorization and validation metadata. Middleware applies more broadly.

[Authorize(Policy = "Billing.Read")]
[HttpGet("{id:int}")]
public Task<IActionResult> GetInvoice(int id) => ...;
,

App settings and configuration

Configuration merges JSON, environment variables, user secrets, command-line arguments and secret stores. Use strongly typed options for related settings.

builder.Services.Configure<LabApiOptions>(builder.Configuration.GetSection("LabApi"));
public sealed class LabApiOptions { public string BaseUrl { get; set; } = ""; }
,

Problem Details and global errors

Translate unhandled exceptions into consistent safe Problem Details responses. Do not expose stack traces, SQL messages or secrets to clients.

builder.Services.AddProblemDetails();
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
app.UseExceptionHandler();
,

Authentication and authorization

Authentication establishes identity; authorization checks permission. Use policies/claims and resource-level checks for sensitive patient records.

builder.Services.AddAuthorization(o =>
 o.AddPolicy("Patient.Read", p => p.RequireClaim("permission", "patient.read")));
app.UseAuthentication();
app.UseAuthorization();
