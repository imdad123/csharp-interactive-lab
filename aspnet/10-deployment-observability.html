GUIDE 10 · ASP.NET CORE / .NET 10

Deployment, cloud, observability and operations

Ship, monitor, secure and recover production ASP.NET Core applications. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Environments, secrets and deployment configuration

Why this matters

Production configuration must be externalized, access-controlled and auditable. A deployment should not require editing source files or rebuilding for secrets.

What you must learn

Learn environment variables, secret stores, managed identity, Key Vault or equivalent, configuration validation and secret rotation.

Practical code example

dotnet user-secrets init
dotnet user-secrets set "ConnectionStrings:Hospital" "Server=localhost;Database=Hospital;Trusted_Connection=True;TrustServerCertificate=True"

// Production: inject secrets through a managed secret provider, not source control.

Build / practise

Remove credentials from repository history and configure a separate secret source for deployment.

TOPIC 02

Docker and containerization

Why this matters

Containers package an application and its runtime dependencies consistently. Production containers should be small, non-root, configured externally and easy to replace.

What you must learn

Learn Dockerfile, multi-stage builds, image tags, ports, health checks, volumes, environment variables, non-root execution and image scanning.

Practical code example

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish Hospital.Api/Hospital.Api.csproj -c Release -o /app/publish
FROM mcr.microsoft.com/dotnet/aspnet:10.0
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["dotnet", "Hospital.Api.dll"]

Build / practise

Build and run the API in Docker. Verify it runs as a non-root user and reads configuration from the environment.

TOPIC 03

CI/CD with GitHub Actions or Azure Pipelines

Why this matters

CI validates every change; CD promotes tested artifacts through environments. Reliable pipelines make releases repeatable and reduce manual mistakes.

What you must learn

Learn restore, build, test, publish, artifact retention, dependency scanning, database migration stages, approvals, rollback and deployment slots.

Practical code example

name: dotnet-ci
on: [push, pull_request]
jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.0.x'
      - run: dotnet restore
      - run: dotnet build --no-restore --configuration Release
      - run: dotnet test --no-build --configuration Release

Build / practise

Create a pipeline that fails on build or test errors and publishes a versioned artifact only from the main branch.

TOPIC 04

Health checks and readiness

Why this matters

A process can be running while its database or message broker is unavailable. Liveness and readiness answer different operational questions.

What you must learn

Learn health check endpoints, dependency checks, readiness gates, Kubernetes probes and avoiding expensive checks on every probe.

Practical code example

builder.Services.AddHealthChecks()
    .AddDbContextCheck<HospitalDbContext>();

app.MapHealthChecks("/health");

Build / practise

Expose separate liveness and readiness endpoints. Confirm deployment orchestration does not send traffic to an unready instance.

TOPIC 05

OpenTelemetry, metrics and distributed tracing

Why this matters

Logs tell what happened; metrics show trends; traces show where time was spent across service boundaries. Correlation is essential in distributed workflows.

What you must learn

Learn OpenTelemetry, Activity, trace/span IDs, metrics, histograms, exporters, dashboards and alert thresholds.

Practical code example

builder.Services.AddOpenTelemetry()
    .WithTracing(t => t.AddAspNetCoreInstrumentation()
                       .AddHttpClientInstrumentation())
    .WithMetrics(m => m.AddAspNetCoreInstrumentation()
                       .AddHttpClientInstrumentation());

Build / practise

Trace one appointment request across the API, SQL and SMS provider. Create an alert for elevated error rate and latency.

TOPIC 06

Backups, disaster recovery and operational readiness

Why this matters

A production service is not reliable unless data can be restored. Backups without tested restores are only assumptions.

What you must learn

Learn SQL Server full/differential/log backups, point-in-time recovery, RPO, RTO, restore drills, failover, runbooks and incident reviews.

Practical code example

BACKUP DATABASE Hospital
TO DISK = 'D:\SqlBackups\Hospital_full.bak'
WITH COMPRESSION, CHECKSUM;

RESTORE VERIFYONLY
FROM DISK = 'D:\SqlBackups\Hospital_full.bak'
WITH CHECKSUM;

Build / practise

Define RPO/RTO for patient and billing data. Perform a restore drill in an isolated environment and record the result.
