GUIDE 08 · ASP.NET CORE / .NET 10

External integrations, background work and messaging

Integrate reliably with payment, SMS, email, labs and asynchronous workflows. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

HttpClient and IHttpClientFactory

Why this matters

Creating HttpClient incorrectly can exhaust sockets or use stale DNS. The factory centralizes configuration, handler lifetime and resilience.

What you must learn

Learn typed clients, named clients, base addresses, timeouts, cancellation, headers, JSON serialization and safe retry policies.

Practical code example

builder.Services.AddHttpClient<ISmsGateway, SmsGateway>(client =>
{
    client.BaseAddress = new Uri(configuration["Sms:BaseUrl"]!);
    client.Timeout = TimeSpan.FromSeconds(10);
});

Build / practise

Build a typed SMS gateway. Handle timeouts and non-success status codes without logging credentials or message content.

TOPIC 02

Resilience, retries and circuit breakers

Why this matters

Retries can amplify outages and duplicate side effects. Resilience policies must respect idempotency, timeouts and downstream capacity.

What you must learn

Learn exponential backoff, jitter, retryable status codes, circuit breakers, bulkheads, timeouts and Polly or Microsoft.Extensions.Http.Resilience.

Practical code example

builder.Services.AddHttpClient<ILabClient, LabClient>()
    .AddStandardResilienceHandler();

Build / practise

Simulate a lab API timeout and 503. Verify bounded retries and ensure a payment is not charged twice.

TOPIC 03

BackgroundService and hosted services

Why this matters

Long-running work should not hold an HTTP request open. Hosted services process queues, scheduled work and maintenance tasks with controlled shutdown.

What you must learn

Learn `IHostedService`, `BackgroundService`, cancellation tokens, scoped dependencies, channels, graceful shutdown and health checks.

Practical code example

public sealed class ReminderWorker(IServiceScopeFactory scopes, ILogger<ReminderWorker> log)
    : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            await using var scope = scopes.CreateAsyncScope();
            var sender = scope.ServiceProvider.GetRequiredService<IReminderSender>();
            await sender.SendDueRemindersAsync(stoppingToken);
            await Task.Delay(TimeSpan.FromMinutes(1), stoppingToken);
        }
    }
}

Build / practise

Build appointment reminders. Ensure shutdown cancellation is handled and a new DI scope is created for each processing cycle.

TOPIC 04

Queues, brokers and event-driven design

Why this matters

A queue decouples the request from work that can happen later. A broker adds durable delivery and consumer coordination, but introduces operational complexity.

What you must learn

Learn RabbitMQ, Azure Service Bus or Kafka fundamentals, producer/consumer, acknowledgements, retries, dead-letter queues, ordering and competing consumers.

Practical code example

public sealed record AppointmentBooked(Guid AppointmentId, DateTimeOffset OccurredAtUtc);

await publisher.PublishAsync(new AppointmentBooked(id, clock.UtcNow), ct);

Build / practise

Publish an appointment-booked event and consume it to send notifications. Make the consumer safe when the same message arrives twice.

TOPIC 05

Outbox, idempotency and reliable delivery

Why this matters

Saving a database row and publishing a message are two separate operations. A crash between them can lose an event or publish an event for a rolled-back change.

What you must learn

Learn transactional outbox, inbox/deduplication, idempotency keys, at-least-once delivery, eventual consistency and reconciliation.

Practical code example

await using var tx = await db.Database.BeginTransactionAsync(ct);
db.Appointments.Add(appointment);
db.OutboxMessages.Add(OutboxMessage.From(new AppointmentBooked(appointment.Id, clock.UtcNow)));
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);

Build / practise

Implement an outbox table and background dispatcher. Prove that a committed appointment eventually produces an event even after a process restart.

TOPIC 06

Scheduling and job processing

Why this matters

Scheduled jobs need persistence, retries, monitoring and concurrency controls. A timer inside one web process is not a durable scheduler.

What you must learn

Learn Hangfire or Quartz, recurring jobs, misfire behavior, distributed locks, retry policies, job dashboards and idempotent handlers.

Practical code example

RecurringJob.AddOrUpdate<IInvoiceReminderJob>(
    "invoice-reminders",
    job => job.SendDueRemindersAsync(CancellationToken.None),
    Cron.Daily(8));

Build / practise

Schedule daily invoice reminders. Ensure multiple application instances do not send duplicate reminders.
