TOPIC GUIDE

Dependency injection, caching and logging

1. Why dependency injection exists

Business services need collaborators such as repositories, clocks, email senders and caches. Constructing concrete dependencies inside every class makes testing and replacement difficult. DI moves object construction to the composition root and supplies dependencies through constructors.

public interface IPatientRepository
{
    Task<Patient?> FindAsync(int id, CancellationToken cancellationToken);
}

public sealed class PatientLookupService(IPatientRepository repository)
{
    public Task<Patient?> GetAsync(int id, CancellationToken cancellationToken)
        => repository.FindAsync(id, cancellationToken);
}

// Program.cs
builder.Services.AddScoped<IPatientRepository, EfPatientRepository>();
builder.Services.AddScoped<PatientLookupService>();

2. Service lifetimes

LifetimeMeaningTypical use
TransientNew instance each resolutionSmall stateless helper
ScopedOne instance per request scopeDbContext and request services
SingletonOne instance for application lifetimeThread-safe shared immutable service
builder.Services.AddTransient<IReceiptFormatter, ReceiptFormatter>();
builder.Services.AddScoped<IPatientService, PatientService>();
builder.Services.AddSingleton<ISystemClock, SystemClock>();

Do not inject a scoped DbContext into a singleton. A singleton must be thread-safe and must not capture request-specific state. Hosted services that need scoped dependencies should create a scope with IServiceScopeFactory.

3. Avoid service locator; use constructor injection

public sealed class AppointmentService(
    IAppointmentRepository appointments,
    ILogger<AppointmentService> logger)
{
    public async Task BookAsync(Appointment appointment, CancellationToken ct)
    {
        logger.LogInformation("Booking appointment for patient {PatientId}",
            appointment.PatientId);

        await appointments.AddAsync(appointment, ct);
    }
}

4. Memory cache

builder.Services.AddMemoryCache();

app.MapGet("/api/departments", async (
    IMemoryCache cache,
    IDepartmentRepository repository,
    CancellationToken ct) =>
{
    const string key = "departments:v1";

    var departments = await cache.GetOrCreateAsync(key, async entry =>
    {
        entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
        return await repository.GetAllAsync(ct);
    });

    return Results.Ok(departments);
});

In-memory cache belongs to one process. It is not shared across multiple app instances and is cleared on restart. Cache only data whose staleness is acceptable; define invalidation and expiration rules.

5. Distributed cache and Redis

// Register a distributed cache provider (Redis package required).
builder.Services.AddStackExchangeRedisCache(options =>
{
    options.Configuration = builder.Configuration.GetConnectionString("Redis");
    options.InstanceName = "HospitalApi:";
});

// Use IDistributedCache in an application service.
public sealed class PatientSummaryCache(IDistributedCache cache)
{
    public async Task StoreAsync(string key, string json, CancellationToken ct)
    {
        await cache.SetStringAsync(
            key,
            json,
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(3)
            },
            ct);
    }
}

Use distributed cache when several instances need shared cached values. It introduces network dependency, serialization, operational monitoring and invalidation complexity.

6. Structured logging with ILogger

public sealed class PaymentService(ILogger<PaymentService> logger)
{
    public void RecordPayment(int invoiceId, decimal amount)
    {
        logger.LogInformation(
            "Payment recorded for invoice {InvoiceId} with amount {Amount}",
            invoiceId,
            amount);
    }
}

Use structured placeholders, meaningful event IDs where useful and appropriate log levels. Never log passwords, access tokens, full payment-card data or unnecessary patient-identifying/medical information.

7. Serilog and NLog

ASP.NET Core provides ILogger abstractions. Providers such as Serilog and NLog can route structured events to console, files and centralized log systems. Keep application code dependent on ILogger<T>, not a logging vendor API unless a specific feature requires it.

// Example Serilog host integration (requires Serilog packages).
builder.Host.UseSerilog((context, services, configuration) =>
    configuration.ReadFrom.Configuration(context.Configuration)
                 .ReadFrom.Services(services)
                 .Enrich.FromLogContext());

Practice

  1. Register repository and application services with correct lifetimes.
  2. Write a test double for IPatientRepository.
  3. Cache a department list with an explicit expiration.
  4. Compare in-memory cache and Redis for a two-instance deployment.
  5. Log request and business events without leaking sensitive data.
