API integrations and communication styles

The roadmap map includes REST, GraphQL, OData, gRPC, object mapping, API clients, API gateways and search engines. These are different integration approaches; select them according to the client, data shape, latency and operational needs.

1. Typed HTTP clients with IHttpClientFactory

Do not create a new HttpClient for every request. The factory manages handler lifetimes and supports centralized configuration.

builder.Services.AddHttpClient<LaboratoryClient>(client =>
{
    client.BaseAddress = new Uri("https://lab.example.internal/");
    client.Timeout = TimeSpan.FromSeconds(10);
});

public sealed class LaboratoryClient(HttpClient http)
{
    public Task<LabResult?> GetResultAsync(string orderId, CancellationToken ct)
        => http.GetFromJsonAsync<LabResult>(
            $"api/orders/{Uri.EscapeDataString(orderId)}/result", ct);
}

public sealed record LabResult(string OrderId, string Status);

In production, use trusted service URLs from configuration, authentication between services, bounded timeouts, cancellation and an explicit retry/resilience policy for transient failures. Do not blindly retry non-idempotent operations.

2. Object mapping: manual mapping

public sealed record PatientEntity(int Id, string Mrn, string FullName, bool IsDeleted);
public sealed record PatientResponse(int Id, string MedicalRecordNumber, string Name);

static PatientResponse Map(PatientEntity entity)
    => new(entity.Id, entity.Mrn, entity.FullName);

Manual mapping is explicit, debuggable and has no mapping-library dependency. It is often the best choice for a small number of important DTOs.

3. AutoMapper and Mapperly

AutoMapper provides convention-based runtime mapping; Mapperly generates mapping code at compile time. Generated mappings can improve visibility and reduce reflection/runtime work. Both require configuration and tests. Avoid hiding complex business rules inside mapping profiles.

// Illustrative Mapperly-style mapping declaration.
// Add the Riok.Mapperly package and generator to the project.
[Mapper]
public partial class PatientMapper
{
    public partial PatientResponse ToResponse(PatientEntity entity);
}

For AutoMapper, define a profile and register it with dependency injection according to the package version in use. Test important mappings so renamed or omitted properties do not silently alter API behavior.

4. GraphQL with Hot Chocolate

GraphQL lets clients request a selected graph of fields through a schema. It can reduce over-fetching for complex client screens, but adds schema governance, query complexity controls, authorization and caching considerations.

public sealed class PatientQueries
{
    public PatientResponse? GetPatient(
        int id,
        [Service] IPatientReadService service)
        => service.Find(id);
}

// Program.cs with Hot Chocolate packages installed:
builder.Services
    .AddGraphQLServer()
    .AddQueryType<PatientQueries>();

app.MapGraphQL("/graphql");

This is a shape example; in a real project use async resolvers, scoped services, field-level authorization and query depth/complexity limits. Do not expose every database entity automatically.

5. OData

OData standardizes query options such as filtering, sorting and selecting fields. It can be useful for data-oriented clients, but an unrestricted query surface can create expensive database workloads.

// Illustrative controller shape after installing/configuring ASP.NET Core OData.
[EnableQuery]
[HttpGet]
public IQueryable<PatientResponse> Get()
    => _db.Patients
        .Select(p => new PatientResponse(p.Id, p.Mrn, p.FullName));

Apply allowed query options, page-size limits and authorization. Verify that client-supplied expressions translate efficiently to SQL.

6. gRPC

gRPC uses Protocol Buffers and HTTP/2 for strongly typed service-to-service communication. It is suitable for internal services where contracts, streaming or compact payloads matter. Browser-facing clients may still need REST or gRPC-Web support.

// patient.proto
syntax = "proto3";
option csharp_namespace = "Hospital.Contracts";

service PatientDirectory {
  rpc GetPatient (PatientRequest) returns (PatientReply);
}

message PatientRequest { int32 id = 1; }
message PatientReply {
  int32 id = 1;
  string full_name = 2;
  string mrn = 3;
}

Generated C# service bases and clients come from the protobuf contract. Keep protocol definitions versioned and evolve fields compatibly; do not reuse removed field numbers.

7. API gateway: YARP and Ocelot

An API gateway is an edge entry point that can route requests to backend services and apply cross-cutting policies. YARP is a reverse-proxy toolkit from Microsoft; Ocelot is a gateway framework. A gateway is not a replacement for service authorization or domain logic.

// YARP setup (requires Microsoft.ReverseProxy package and routes config).
builder.Services.AddReverseProxy()
    .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));

app.MapReverseProxy();

Use gateway routing, TLS termination, rate limits and observability deliberately. Keep service-to-service identity and authorization checks at the backend too.

8. Search engines and databases

The map lists Elasticsearch, Solr and Sphinx as search-engine options. Search engines are optimized for text search and indexing; they are not the system of record for invoices, appointments or patient identity. Keep authoritative transactional data in a relational or suitable operational database, then project searchable data into a search index.

  • Relational: SQL Server, PostgreSQL, MySQL and MariaDB for transactions, constraints and joins.
  • Document/NoSQL: MongoDB, CouchDB, DynamoDB, Cosmos DB and others for specific access patterns.
  • Embedded: SQLite/LiteDB for local or embedded scenarios with appropriate concurrency and durability expectations.

Choose based on consistency, transaction requirements, query patterns, scale, team skills, backup/restore and operational cost—not popularity alone.

  2. Map an EF entity to a public response DTO explicitly.
  3. Compare REST and GraphQL for a ward dashboard.
  4. Define a protobuf contract for a patient lookup service.
  5. Draw a gateway route and identify where authentication and authorization are enforced.
