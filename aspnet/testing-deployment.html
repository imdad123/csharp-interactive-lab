TOPIC GUIDE

Testing and deployment

1. Unit tests vs integration tests

Unit tests isolate a small unit such as a domain rule or service. Integration tests verify that multiple components work together, for example routing, dependency injection, serialization and a database provider. End-to-end tests exercise a user workflow through a running application and browser.

public sealed class InvoiceCalculator
{
    public decimal Total(decimal consultation, decimal lab, decimal discount)
    {
        if (consultation < 0 || lab < 0 || discount < 0 ||
            discount > consultation + lab)
            throw new ArgumentOutOfRangeException();

        return consultation + lab - discount;
    }
}

// xUnit
public sealed class InvoiceCalculatorTests
{
    [Fact]
    public void Total_SubtractsDiscount()
    {
        var calculator = new InvoiceCalculator();

        decimal total = calculator.Total(1800m, 750m, 100m);

        Assert.Equal(2450m, total);
    }
}

2. Test an HTTP endpoint with WebApplicationFactory

Install the ASP.NET Core MVC testing package that matches the target framework. Keep test host configuration separate from production configuration.

public sealed class PatientsApiTests
    : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient _client;

    public PatientsApiTests(WebApplicationFactory<Program> factory)
    {
        _client = factory.CreateClient();
    }

    [Fact]
    public async Task HealthEndpoint_ReturnsSuccess()
    {
        using HttpResponseMessage response =
            await _client.GetAsync("/health");

        Assert.True(response.IsSuccessStatusCode);
    }
}

For top-level Program projects, expose the generated Program type to the test assembly when needed (for example with public partial class Program { } in the API project). Integration tests should use isolated test data and never connect to production.

3. Test database choices

  • Use a real disposable relational database for tests that depend on SQL translation, constraints, transactions or provider behavior.
  • Testcontainers can provision disposable dependencies such as SQL Server, PostgreSQL or Redis where supported.
  • Respawn can reset database state between tests.
  • EF Core InMemory is not a relational database and does not accurately model relational constraints or SQL translation.

4. Browser and end-to-end testing

Playwright, Puppeteer and Cypress automate browser workflows. Use them for important user journeys such as receptionist registration, appointment booking and invoice payment. Keep most business-rule tests at unit/integration level because browser tests are slower and more fragile.

5. Dockerize the API

FROM mcr.microsoft.com/dotnet/aspnet:10.0 AS runtime
WORKDIR /app
EXPOSE 8080

FROM mcr.microsoft.com/dotnet/sdk:10.0 AS build
WORKDIR /src
COPY . .
RUN dotnet publish src/Hospital.Api/Hospital.Api.csproj -c Release -o /out

FROM runtime AS final
WORKDIR /app
COPY --from=build /out .
ENTRYPOINT ["dotnet", "Hospital.Api.dll"]

Adjust project paths to match the actual solution. Run as a non-root user where supported, use a small trusted base image, pin and regularly update images, and inject secrets at runtime rather than baking them into layers.

6. CI/CD pipeline outline

dotnet restore
dotnet format --verify-no-changes
dotnet build --configuration Release --no-restore
dotnet test --configuration Release --no-build
dotnet publish src/Hospital.Api/Hospital.Api.csproj -c Release -o ./artifacts/publish

Build once and promote the same artifact through environments. Run database migrations as a controlled deployment step. Use health checks, rollback strategy, secrets management and monitoring.

7. Production checklist

  • HTTPS and secure proxy configuration.
  • Authentication and authorization policies on sensitive endpoints.
  • Request validation, rate limiting and safe error responses.
  • Database indexes, bounded pagination and query performance checks.
  • Structured logs, metrics, tracing and health checks.
  • Backups, restore drills, migration strategy and audit history.
  • Secrets outside source control; least-privilege identities.
  • CI pipeline, integration tests and repeatable deployment.
