TOPIC GUIDE

HTTP APIs, REST and MVC

An API is a contract between clients and the server. ASP.NET Core supports Minimal APIs and controller-based APIs; choose the style that best fits the application size, conventions and team.

1. HTTP essentials

MethodTypical meaningHospital example
GETRead a resourceGet patient details
POSTCreate/process a resourceRegister a patient
PUTReplace a resource representationReplace patient profile
PATCHPartially update a resourceChange phone number
DELETEDelete/deactivate a resourceRemove a draft record

Use status codes intentionally: 200 for successful reads/updates, 201 for created resources, 204 for success with no response body, 400 for invalid input, 401 for unauthenticated, 403 for forbidden, 404 for missing resources and 409 for conflicts.

2. DTOs separate the API contract from entities

public sealed record CreatePatientRequest(
    string MedicalRecordNumber,
    string FullName,
    DateOnly DateOfBirth);

public sealed record PatientResponse(
    int Id,
    string MedicalRecordNumber,
    string FullName,
    DateOnly DateOfBirth);

Do not expose EF Core entities directly as public API contracts. DTOs prevent clients from setting internal fields, avoid accidental navigation-property serialization and allow the API contract to evolve independently.

3. Minimal API endpoint group

var patients = new List<PatientResponse>();

var group = app.MapGroup("/api/patients")
    .WithTags("Patients");

group.MapGet("/", () => Results.Ok(patients));

group.MapGet("/{id:int}", (int id) =>
{
    var patient = patients.FirstOrDefault(p => p.Id == id);
    return patient is null
        ? Results.NotFound()
        : Results.Ok(patient);
});

group.MapPost("/", (CreatePatientRequest request) =>
{
    if (string.IsNullOrWhiteSpace(request.FullName))
        return Results.ValidationProblem(new Dictionary<string, string[]>
        {
            ["fullName"] = ["Full name is required."]
        });

    int id = patients.Count + 1;
    var response = new PatientResponse(
        id, request.MedicalRecordNumber,
        request.FullName.Trim(), request.DateOfBirth);

    patients.Add(response);
    return Results.Created($"/api/patients/{id}", response);
});

This in-memory collection is a teaching example only. It loses data on restart and is not safe for concurrent production writes. Replace it with an application service and database repository/use case.

4. Controller-based API

using Microsoft.AspNetCore.Mvc;

[ApiController]
[Route("api/[controller]")]
public sealed class DepartmentsController : ControllerBase
{
    [HttpGet]
    [ProducesResponseType<IReadOnlyList<string>>(StatusCodes.Status200OK)]
    public ActionResult<IReadOnlyList<string>> GetAll()
    {
        string[] departments = ["Emergency", "Cardiology", "Pediatrics"];
        return Ok(departments);
    }

    [HttpGet("{id:int}")]
    public IActionResult GetById(int id)
    {
        if (id <= 0) return BadRequest();
        if (id != 1) return NotFound();
        return Ok(new { Id = id, Name = "Cardiology" });
    }
}

Register controllers with builder.Services.AddControllers() and map them with app.MapControllers(). Controller APIs suit teams that prefer attribute routing, filters, conventions and explicit action classes.

5. Request validation

using System.ComponentModel.DataAnnotations;

public sealed class CreateDoctorRequest
{
    [Required, StringLength(100, MinimumLength = 3)]
    public string FullName { get; init; } = "";

    [Required, RegularExpression(@"^[A-Z]{2,5}$")]
    public string DepartmentCode { get; init; } = "";
}

With [ApiController], invalid model state automatically produces a 400 response for many controller binding scenarios. For complex domain rules, use explicit validators/application services; request-shape validation is not a replacement for business invariants.

6. REST resource design

GET    /api/patients/1205
GET    /api/patients?search=amina&page=1&pageSize=20
POST   /api/patients
PUT    /api/patients/1205
PATCH  /api/patients/1205/contact
GET    /api/patients/1205/appointments

Use nouns for resources, plural collections, consistent identifiers and predictable status codes. Pagination should have bounded page sizes. Search and sort parameters must be validated and translated safely by the data layer.

7. Razor Pages, Razor Components and alternatives

Razor Pages is a page-focused server-rendered web UI model. Razor Components are reusable UI components and are the foundation for Blazor experiences. These are different UI choices from a JSON API. Do not add Razor Pages or Blazor merely because an API project exists.

Practice

  1. Create a Minimal API group for doctors with list, detail and create endpoints.
  2. Build equivalent controller endpoints and compare organization.
  3. Use request and response DTOs; never bind an EF entity directly from public input.
  4. Add validation, pagination and correct status codes.
  5. Document endpoints with OpenAPI and test them with an API client.
