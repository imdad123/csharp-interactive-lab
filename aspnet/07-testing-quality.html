GUIDE 07 · ASP.NET CORE / .NET 10

Testing, debugging and code quality

Prove behavior at unit, integration, contract and browser levels. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Testing pyramid and test strategy

Why this matters

Different tests catch different failures. Unit tests are fast; integration tests verify real boundaries; end-to-end tests prove user workflows but cost more to maintain.

What you must learn

Learn test isolation, test naming, Arrange-Act-Assert, deterministic tests, test pyramid, fixtures and avoiding tests that only repeat implementation details.

Practical code example

[Fact]
public void Reschedule_RejectsPastDate()
{
    var appointment = Appointment.Create(DateTimeOffset.UtcNow.AddDays(1));
    Assert.Throws<InvalidOperationException>(() =>
        appointment.Reschedule(DateTimeOffset.UtcNow.AddDays(-1)));
}

Build / practise

Write domain tests for booking rules without a database or web server.

TOPIC 02

Unit testing services and handlers

Why this matters

A unit test checks one unit of behavior with controlled dependencies. It should not require a real SQL Server or network service.

What you must learn

Learn xUnit, NUnit or MSTest, test doubles, Moq/NSubstitute, fakes, theory data, boundary cases and testing async code.

Practical code example

[Fact]
public async Task GetAsync_ReturnsPatient_WhenRepositoryFindsIt()
{
    var expected = new PatientDto(Guid.NewGuid(), "Amina");
    var repository = Substitute.For<IPatientRepository>();
    repository.GetAsync(expected.Id, Arg.Any<CancellationToken>()).Returns(expected);
    var service = new PatientService(repository);
    var actual = await service.GetAsync(expected.Id, CancellationToken.None);
    Assert.Equal(expected, actual);
}

Build / practise

Test success, not found, invalid input and dependency failure paths. Avoid mocking every class in the call chain.

TOPIC 03

Integration testing with WebApplicationFactory

Why this matters

Integration tests run the actual ASP.NET Core pipeline and verify routing, DI, serialization, middleware and persistence integration.

What you must learn

Learn `WebApplicationFactory`, test host configuration, replacing services, test databases, Testcontainers and Respawn.

Practical code example

public sealed class PatientsApiTests : IClassFixture<WebApplicationFactory<Program>>
{
    private readonly HttpClient client;
    public PatientsApiTests(WebApplicationFactory<Program> factory) => client = factory.CreateClient();

    [Fact]
    public async Task Health_ReturnsOk()
    {
        var response = await client.GetAsync("/health");
        Assert.Equal(HttpStatusCode.OK, response.StatusCode);
    }
}

Build / practise

Test API status codes, JSON contracts, validation, authorization and SQL persistence against an isolated test database.

TOPIC 04

Debugging and diagnostics

Why this matters

Professional debugging is systematic evidence gathering, not random code changes. Understand the call stack, request trace, SQL and exception context.

What you must learn

Learn Visual Studio breakpoints, conditional breakpoints, watch/immediate windows, dump analysis, structured logs, tracing, metrics and profiling.

Practical code example

if (logger.IsEnabled(LogLevel.Debug))
    logger.LogDebug("Appointment {AppointmentId} loaded in {ElapsedMs} ms",
        id, stopwatch.ElapsedMilliseconds);

Build / practise

Reproduce a slow endpoint, identify whether time is spent in application code, SQL or an external HTTP call, and document evidence.

TOPIC 05

Static analysis, analyzers and code review

Why this matters

Automated analyzers catch maintainability and correctness issues before runtime. Code review catches design and business risks that tools cannot infer.

What you must learn

Learn nullable reference types, compiler warnings as errors, .NET analyzers, StyleCop, formatting, dependency scanning and review checklists.

Practical code example

<PropertyGroup>
  <Nullable>enable</Nullable>
  <TreatWarningsAsErrors>true</TreatWarningsAsErrors>
  <AnalysisLevel>latest</AnalysisLevel>
  <EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
</PropertyGroup>

Build / practise

Enable nullable analysis and analyzers. Fix warnings instead of suppressing them without explanation.
