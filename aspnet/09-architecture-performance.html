GUIDE 09 · ASP.NET CORE / .NET 10

Architecture, performance and scalability

Make sound engineering decisions for systems that must grow safely. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Domain-driven design and domain modeling

Why this matters

DDD helps when business rules are complex and terminology matters. It is not a requirement to wrap every table in repositories or create dozens of abstractions.

What you must learn

Learn ubiquitous language, entities, value objects, aggregates, invariants, domain events, bounded contexts and anti-corruption layers.

Practical code example

public sealed record Money(decimal Amount, string Currency);

public sealed class Invoice
{
    private readonly List<InvoiceLine> lines = [];
    public IReadOnlyCollection<InvoiceLine> Lines => lines;
    public void AddLine(InvoiceLine line)
    {
        if (line.Quantity <= 0) throw new ArgumentOutOfRangeException(nameof(line));
        lines.Add(line);
    }
}

Build / practise

Model invoice totals and payment rules in domain code, not only in controller conditionals.

TOPIC 02

Caching strategy

Why this matters

Caching reduces repeated work but introduces staleness and invalidation problems. Cache only data whose freshness requirements are understood.

What you must learn

Learn in-memory cache, distributed cache, Redis, cache-aside, expiration, stampede prevention, invalidation and cache key design.

Practical code example

builder.Services.AddMemoryCache();

var doctor = await cache.GetOrCreateAsync($"doctor:{id}", async entry =>
{
    entry.AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5);
    return await db.Doctors.AsNoTracking().SingleOrDefaultAsync(x => x.Id == id, ct);
});

Build / practise

Cache public doctor directory data, but do not cache sensitive patient data without a documented security and invalidation design.

TOPIC 03

Performance profiling and SQL tuning

Why this matters

Performance work starts with measurement. A slow endpoint may be caused by query plans, N+1 queries, serialization, network waits, allocations or locks.

What you must learn

Learn BenchmarkDotNet, dotnet-counters, dotnet-trace, profiling, SQL Server execution plans, indexes, Query Store, connection pooling and load testing.

Practical code example

var query = db.Appointments
    .Where(x => x.DoctorId == doctorId)
    .OrderBy(x => x.StartsAt)
    .Select(x => new { x.Id, x.StartsAt });

var sql = query.ToQueryString();

Build / practise

Capture the SQL and actual execution plan for a slow appointment search. Tune based on measured evidence, not guesses.

TOPIC 04

Async, threading and concurrency

Why this matters

Async I/O improves server scalability by freeing request threads while waiting. It does not automatically make CPU-bound work faster.

What you must learn

Learn async/await, Task, cancellation propagation, thread pool starvation, locks, concurrent collections, `Parallel.ForEachAsync` and avoiding `.Result`/`.Wait()`.

Practical code example

app.MapGet("/api/reports/{id:guid}", async (Guid id, IReportService reports, CancellationToken ct) =>
    await reports.GenerateAsync(id, ct));

Build / practise

Make database and HTTP calls asynchronous end-to-end. Add cancellation and inspect for sync-over-async.

TOPIC 05

Microservices versus modular monolith

Why this matters

Microservices add independent deployment and scaling but also network failures, distributed data, observability and operational overhead. Start with clear modules unless independent deployment is justified.

What you must learn

Learn service boundaries, data ownership, API/event contracts, saga, eventual consistency, service discovery, gateways, Docker and Kubernetes basics.

Practical code example

// A module boundary can be explicit without a network hop.
public interface IBillingModule
{
    Task<InvoiceSummary> CreateInvoiceAsync(Guid admissionId, CancellationToken ct);
}

Build / practise

Split the HMS into modules first. Write an evidence-based decision record before extracting any module into a separate service.

TOPIC 06

API versioning and compatibility

Why this matters

Public APIs evolve while old clients may remain deployed. Compatibility is a product and operational concern, not only a routing feature.

What you must learn

Learn semantic versioning, additive changes, deprecation, versioned routes or headers, schema compatibility and consumer-driven contract tests.

Practical code example

[ApiController]
[Route("api/v1/patients")]
public sealed class PatientsV1Controller : ControllerBase { }

Build / practise

Add a v2 response without breaking a v1 mobile client. Define a deprecation and migration policy.
