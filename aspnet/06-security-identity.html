GUIDE 06 · ASP.NET CORE / .NET 10

ASP.NET Core security and identity

Protect users, APIs, patient records and operational data. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Authentication versus authorization

Why this matters

Authentication establishes who the caller is; authorization decides what that identity may do. A logged-in user is not automatically allowed to view every patient.

What you must learn

Learn claims, principals, schemes, cookies, bearer tokens, policies, roles, resource-based authorization and least privilege.

Practical code example

builder.Services.AddAuthorizationBuilder()
    .AddPolicy("CanManageAppointments", policy =>
        policy.RequireClaim("permission", "appointments.manage"));

app.MapPost("/api/appointments", CreateAppointment)
   .RequireAuthorization("CanManageAppointments");

Build / practise

Create separate permissions for reception, doctor, billing and administrator roles. Test access to each API with different identities.

TOPIC 02

ASP.NET Core Identity

Why this matters

Identity provides user management primitives such as password hashing, sign-in, lockout, roles, claims and token support. Do not store passwords yourself.

What you must learn

Learn user stores, password policies, lockout, email confirmation, MFA, account recovery, external login and secure cookie settings.

Practical code example

builder.Services.AddIdentityCore<ApplicationUser>(options =>
{
    options.Password.RequiredLength = 12;
    options.Lockout.MaxFailedAccessAttempts = 5;
})
.AddRoles<IdentityRole>()
.AddEntityFrameworkStores<HospitalDbContext>();

Build / practise

Build secure staff account registration and password reset flows. Add MFA for privileged accounts.

TOPIC 03

JWT bearer tokens and API security

Why this matters

Bearer tokens allow clients to authenticate API requests. Validation must check signature, issuer, audience and lifetime; decoding a JWT is not validation.

What you must learn

Learn OAuth 2.0 and OpenID Connect roles, access versus refresh tokens, scopes, claims, key rotation, token expiry and secure storage.

Practical code example

builder.Services.AddAuthentication().AddJwtBearer(options =>
{
    options.Authority = configuration["Auth:Authority"];
    options.Audience = configuration["Auth:Audience"];
});

Build / practise

Configure a trusted identity provider and verify invalid signatures, wrong audience and expired tokens are rejected.

TOPIC 04

Resource-based authorization and tenant boundaries

Why this matters

A user may have permission to view appointments but only for their assigned department or facility. Authorization often depends on the specific resource.

What you must learn

Learn `IAuthorizationService`, requirements, handlers, ownership checks, tenant scoping and defense against insecure direct object references.

Practical code example

var result = await authorization.AuthorizeAsync(User, appointment, "CanReadAppointment");
if (!result.Succeeded) return Forbid();

Build / practise

Ensure changing an appointment ID in the URL cannot expose another department's or patient's records.

TOPIC 05

Web security essentials

Why this matters

Many vulnerabilities happen at the boundary between untrusted input and sensitive operations. Framework defaults help, but developers must configure and use them correctly.

What you must learn

Learn HTTPS, CORS, CSRF, XSS, SQL injection, mass assignment, rate limiting, secure headers, secrets, file upload validation and OWASP API risks.

Practical code example

builder.Services.AddRateLimiter(options => options.AddFixedWindowLimiter("login", o =>
{
    o.PermitLimit = 5;
    o.Window = TimeSpan.FromMinutes(1);
}));
app.UseRateLimiter();

Build / practise

Threat-model login, patient search and file upload endpoints. Add rate limits and test that CORS is not treated as authentication.

TOPIC 06

Audit trails and sensitive healthcare data

Why this matters

Sensitive systems need traceability: who accessed or changed a record, when, and through which workflow. Audit records must not become a second leak of sensitive data.

What you must learn

Learn append-only audit events, actor identity, correlation IDs, before/after change policy, retention, access logging and privacy-by-design.

Practical code example

public sealed record AuditEntry(Guid Id, string ActorId, string Action,
    string ResourceType, string ResourceId, DateTimeOffset OccurredAtUtc);

await auditWriter.WriteAsync(new AuditEntry(Guid.NewGuid(), userId,
    "Appointment.Rescheduled", "Appointment", appointmentId.ToString(), clock.UtcNow), ct);

Build / practise

Record access to patient records and changes to prescriptions or invoices. Do not copy full medical notes into ordinary logs.
