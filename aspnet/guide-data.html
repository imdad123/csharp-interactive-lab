ASP.NET Core databases ORM and caching

Concept, purpose, code examples and production considerations with hospital application scenarios.

EF Core and DbContext

EF Core maps entity types to relational tables and translates LINQ expressions to provider SQL. DbContext is a short-lived unit-of-work and is not thread-safe.

builder.Services.AddDbContext<HospitalDbContext>(o =>
 o.UseSqlServer(builder.Configuration.GetConnectionString("HospitalDb")));
public sealed class HospitalDbContext(DbContextOptions<HospitalDbContext> o) : DbContext(o)
{ public DbSet<Patient> Patients => Set<Patient>(); }
,

Code First and migrations

Migrations capture incremental schema changes. Review migration code and generated SQL; apply production migrations through controlled release steps.

dotnet ef migrations add AddPatientPhone
dotnet ef migrations script --idempotent
dotnet ef database update
,

Change Tracker API

EF tracks Added, Modified, Deleted and Unchanged entities. AsNoTracking suits read-only queries; use concurrency tokens for safe writes.

var patient = await db.Patients.FindAsync([id], ct);
patient!.Phone = request.Phone;
var state = db.Entry(patient).State;
await db.SaveChangesAsync(ct);
,

Lazy, eager and explicit loading

Eager loading uses Include; explicit loading requests navigation data on demand; lazy loading loads on property access when configured. Avoid N+1 queries and prefer DTO projections.

var patient = await db.Patients.Include(p => p.Appointments)
 .SingleAsync(p => p.Id == id, ct);
var card = await db.Patients.Where(p => p.Id == id)
 .Select(p => new PatientCard(p.Id, p.FullName)).SingleAsync(ct);
,

Dapper

Dapper is a lightweight micro-ORM with explicit SQL and object mapping. It suits SQL-heavy paths where precise query control is needed.

var patient = await connection.QuerySingleOrDefaultAsync<PatientDto>(
 "SELECT PatientId AS Id, MRN, FullName AS Name FROM Patients WHERE PatientId = @Id",
 new { Id = patientId });
,

RepoDB and NHibernate

RepoDB is a hybrid ORM/micro-ORM option; NHibernate is a mature full ORM with its own session and mapping model. Compare provider support, query behavior and team familiarity.

// RepoDB-style parameterized query illustration:
var rows = await connection.ExecuteQueryAsync<Patient>(
 "SELECT * FROM Patients WHERE IsActive = @IsActive", new { IsActive = true });
,

Relational databases

The roadmap lists SQL Server, PostgreSQL, MariaDB and MySQL. Relational databases fit transactional records, joins, constraints and referential integrity.

options.UseSqlServer(connectionString);
// PostgreSQL alternative: options.UseNpgsql(connectionString);

NoSQL and cloud databases

Memory and distributed caching

MemoryCache is local to one process. Distributed cache shares values across instances. Cache design requires key naming, TTL, invalidation and stale-data policy.

builder.Services.AddMemoryCache();
var cache = app.Services.GetRequiredService<IMemoryCache>();
cache.Set($"patient:{id}", patient, TimeSpan.FromMinutes(5));
,

Redis and Memcached

Redis supports distributed data structures and caching; Memcached provides a simpler distributed cache. Use distributed cache when multiple API instances need shared cached values.

builder.Services.AddStackExchangeRedisCache(o =>
{
 o.Configuration = builder.Configuration.GetConnectionString("Redis");
 o.InstanceName = "Hospital:";
});

Transactions and concurrency

Use transactions for related writes. Optimistic concurrency tokens detect conflicting updates. Unique constraints remain essential protection against duplicate records.

await using var tx = await db.Database.BeginTransactionAsync(ct);
db.Invoices.Add(invoice);
db.Payments.Add(payment);
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);
