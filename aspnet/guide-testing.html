ASP.NET Core testing, CI/CD and engineering quality

Concept, purpose, code examples and production considerations with hospital application scenarios.

Unit testing with xUnit, NUnit and MSTest

Unit tests verify small units of behavior without external infrastructure. All three are established .NET test frameworks. Test business rules and application services in isolation.

public class InvoiceTests
{
 [Fact]
 public void Balance_Is_Total_Minus_Paid()
 {
  var invoice = new Invoice(1000m, 250m);
  Assert.Equal(750m, invoice.Balance);
 }
}
,

Assertions and Shouldly

Assertions express expected outcomes. Standard framework assertions work well; Shouldly offers fluent readable assertion syntax.

result.ShouldBe(750m);
patient.Name.ShouldBe("Amina");
,

Mocking with Moq, NSubstitute and FakeItEasy

Mocks isolate meaningful external boundaries such as repositories, payment gateways and message senders. Avoid mocking every class or testing implementation details.

var sender = Substitute.For<IReceiptSender>();
var service = new InvoiceService(sender);
await service.FinalizeAsync(invoice, ct);
await sender.Received(1).SendAsync(Arg.Any<Receipt>(), ct);
,

Fake data with AutoFixture and Bogus

AutoFixture creates test specimens; Bogus generates realistic fake values. Use deterministic seeds when reproducibility matters and never put real patient records into fixtures.

var faker = new Faker<PatientDto>()
 .RuleFor(p => p.Id, f => f.IndexFaker + 1)
 .RuleFor(p => p.Name, f => f.Name.FullName());
var sample = faker.Generate();
,

Integration testing with WebApplicationFactory

WebApplicationFactory boots the ASP.NET Core app in a test host, allowing routes, middleware, DI and application services to be tested together.

public class PatientApiTests : IClassFixture<WebApplicationFactory<Program>>
{
 private readonly HttpClient _client;
 public PatientApiTests(WebApplicationFactory<Program> factory) => _client = factory.CreateClient();
 [Fact] public async Task Health_Returns_Ok()
  => (await _client.GetAsync("/health")).EnsureSuccessStatusCode();
}
,

Testcontainers and Respawn

Testcontainers starts real infrastructure such as SQL Server/PostgreSQL in containers. Respawn resets database state between tests. Keep test data isolated and deterministic.

// Start a disposable SQL container for integration tests.
// Reset the test database between test cases:
await respawner.ResetAsync(connectionString);
,

End-to-end testing with Playwright, Puppeteer and Cypress

E2E tests drive a real browser through user journeys. Cover critical workflows such as patient registration and appointment booking; keep the suite focused.

await page.GotoAsync(baseUrl + "/patients/new");
await page.GetByLabel("Full name").FillAsync("Amina Khan");
await page.GetByRole(AriaRole.Button, new() { Name = "Save" }).ClickAsync();
,

Behavior testing and SpecFlow

BDD describes behavior in business language. The roadmap lists SpecFlow and light BDD; verify current package support and licensing before selecting a framework.

Feature: Appointment booking
 Scenario: A doctor has an available slot
  Given Dr Ali has an open slot
  When a patient books the slot
  Then the appointment is confirmed

CI/CD: GitHub Actions, Azure Pipelines, GitLab and CircleCI

A pipeline restores, builds, analyzes and tests a commit before publishing an artifact. Add dependency scanning, secret scanning, migration review and deployment approvals.

dotnet restore
dotnet format --verify-no-changes
dotnet build -c Release --no-restore
dotnet test -c Release --no-build
dotnet publish -c Release -o ./artifacts
,

Nuke build automation

Nuke defines build pipelines in C# and can share build logic between developer machines and CI. Use it when the repository needs reusable build orchestration.

// Nuke target concept:
Target Compile => _ => _
 .Executes(() => DotNetBuild(s => s.SetProjectFile(Solution)));
