GUIDE 05 · ASP.NET CORE / .NET 10

EF Core and SQL Server engineering

Master data access, relational modeling, transactions and performance. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Relational database design

Why this matters

Application correctness depends on sound data modeling. Poor keys, relationships and constraints create duplicate, inconsistent or unqueryable data.

What you must learn

Learn normalization, primary/foreign keys, unique/check constraints, nullability, indexes, cardinality, migrations and when denormalization is justified.

Practical code example

modelBuilder.Entity<Patient>(entity =>
{
    entity.HasKey(x => x.Id);
    entity.Property(x => x.Mrn).HasMaxLength(30).IsRequired();
    entity.HasIndex(x => x.Mrn).IsUnique();
});

Build / practise

Design patient, doctor, appointment, invoice and payment tables. Enforce uniqueness and referential integrity in SQL Server.

TOPIC 02

DbContext, entities and mappings

Why this matters

DbContext is a unit-of-work boundary that tracks entity changes and coordinates database operations. It should not be shared concurrently between requests.

What you must learn

Learn entity configuration, Fluent API, conventions, owned types, value conversions, relationships, navigation properties and context lifetime.

Practical code example

public sealed class HospitalDbContext(DbContextOptions<HospitalDbContext> options) : DbContext(options)
{
    public DbSet<Patient> Patients => Set<Patient>();
    public DbSet<Appointment> Appointments => Set<Appointment>();
    protected override void OnModelCreating(ModelBuilder modelBuilder)
        => modelBuilder.ApplyConfigurationsFromAssembly(typeof(HospitalDbContext).Assembly);
}

Build / practise

Create entity configurations in separate `IEntityTypeConfiguration` classes and inspect the generated schema.

TOPIC 03

Migrations and database deployment

Why this matters

Migrations evolve a schema over time. Applying migrations safely requires understanding data changes, deployment ordering and rollback limitations.

What you must learn

Learn `dotnet ef`, migration snapshots, generated SQL, idempotent scripts, migration bundles, data migrations and production deployment practices.

Practical code example

dotnet ef migrations add AddAppointmentStatus --project Hospital.Infrastructure --startup-project Hospital.Api
dotnet ef migrations script --idempotent --output migration.sql

Build / practise

Generate and review an idempotent SQL script. Never blindly run destructive migrations against production data.

TOPIC 04

Querying, tracking and loading

Why this matters

EF Core can issue extra queries or transfer far more data than the endpoint needs. Query shape is a major source of performance problems.

What you must learn

Learn LINQ translation, projection, `AsNoTracking`, eager/explicit loading, split queries, pagination, compiled queries and N+1 detection.

Practical code example

var page = await db.Appointments
    .AsNoTracking()
    .Where(x => x.DoctorId == doctorId && x.StartsAt >= fromUtc)
    .OrderBy(x => x.StartsAt)
    .Select(x => new AppointmentListItem(x.Id, x.StartsAt, x.Patient.FullName))
    .Take(50)
    .ToListAsync(ct);

Build / practise

Build a paginated appointment search. Inspect generated SQL and ensure it does not load full patient entities unnecessarily.

TOPIC 05

Transactions, concurrency and consistency

Why this matters

Multiple users may update the same record at once. Transactions and concurrency tokens prevent partial writes and silent lost updates.

What you must learn

Learn transaction boundaries, isolation levels, optimistic concurrency, rowversion, unique constraints, retry behavior and idempotent commands.

Practical code example

public sealed class Invoice
{
    public Guid Id { get; private set; }
    [Timestamp] public byte[] RowVersion { get; private set; } = [];
}

try { await db.SaveChangesAsync(ct); }
catch (DbUpdateConcurrencyException) { /* reload and resolve conflict */ throw; }

Build / practise

Simulate two users updating one invoice. Return a clear conflict instead of silently overwriting the first update.

TOPIC 06

Dapper and choosing data access

Why this matters

EF Core is productive for aggregate persistence; Dapper gives direct SQL control for reporting and carefully optimized queries. Neither removes the need to understand SQL.

What you must learn

Learn parameterized SQL, async queries, multi-mapping, transactions, command timeout, connection lifetime and choosing per use case.

Practical code example

const string sql = "SELECT AppointmentId, StartsAt FROM dbo.Appointments WHERE DoctorId = @DoctorId AND StartsAt >= @FromUtc";
var rows = await connection.QueryAsync<AppointmentRow>(sql,
    new { DoctorId = doctorId, FromUtc = fromUtc });

Build / practise

Implement a high-volume report using Dapper with parameters. Compare its query plan and maintainability with EF Core LINQ.
