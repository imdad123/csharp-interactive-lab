GUIDE 03 · ASP.NET CORE / .NET 10

Professional API development

Build stable contracts with Minimal APIs, controllers, validation and consistent errors. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Minimal APIs

Why this matters

Minimal APIs are endpoint-first and reduce ceremony for focused HTTP services. They are especially useful for small services and modular endpoint groups.

What you must learn

Learn `MapGet`, `MapPost`, route groups, binding, filters, endpoint metadata, `Results`, typed results and when controller-based APIs are a better fit.

Practical code example

var patients = app.MapGroup("/api/patients").WithTags("Patients");
patients.MapGet("/{id:guid}", async (Guid id, IPatientService service) =>
    await service.GetAsync(id) is { } patient
        ? Results.Ok(patient)
        : Results.NotFound());

Build / practise

Build patient CRUD endpoints with a service abstraction, cancellation tokens and documented response types.

TOPIC 02

Controllers and MVC API pattern

Why this matters

Controllers organize related actions and are useful when an API has complex conventions, filters, model binding or a team standard based on MVC.

What you must learn

Learn `[ApiController]`, `[Route]`, action methods, model binding, `ActionResult`, filters, formatter behavior and controller discovery.

Practical code example

[ApiController]
[Route("api/[controller]")]
public sealed class DoctorsController(IDoctorService service) : ControllerBase
{
    [HttpGet("{id:guid}")]
    public async Task<ActionResult<DoctorDto>> Get(Guid id, CancellationToken ct)
    {
        var doctor = await service.GetAsync(id, ct);
        return doctor is null ? NotFound() : Ok(doctor);
    }
}

Build / practise

Implement the same read endpoint in Minimal APIs and a controller. Compare clarity, testability and conventions.

TOPIC 03

DTOs and API contract design

Why this matters

Returning database entities directly couples public clients to persistence details and can leak fields. DTOs define deliberate input and output contracts.

What you must learn

Learn request DTOs, response DTOs, validation attributes, mapping, versioning, over-posting prevention, pagination and backwards compatibility.

Practical code example

public sealed record CreatePatientRequest(
    [property: Required, StringLength(100)] string FullName,
    [property: Required] DateOnly DateOfBirth);

public sealed record PatientResponse(Guid Id, string FullName);

Build / practise

Create separate create, update and response DTOs. Prove that a client cannot set internal fields such as `IsAdmin` or `CreatedAt`.

TOPIC 04

Validation and business rules

Why this matters

Input validation checks shape and basic constraints. Domain rules enforce whether an operation is allowed in the real business, such as preventing overlapping doctor appointments.

What you must learn

Learn DataAnnotations, endpoint filters, FluentValidation, domain invariants, validation error contracts and validation at trust boundaries.

Practical code example

public sealed class CreateAppointmentValidator : AbstractValidator<CreateAppointmentRequest>
{
    public CreateAppointmentValidator()
    {
        RuleFor(x => x.PatientId).NotEmpty();
        RuleFor(x => x.DoctorId).NotEmpty();
        RuleFor(x => x.StartsAtUtc).GreaterThan(DateTimeOffset.UtcNow);
    }
}

Build / practise

Validate an appointment request and separately enforce doctor availability inside the application/domain workflow.

TOPIC 05

Consistent errors and Problem Details

Why this matters

Clients need a stable error format. Returning stack traces or arbitrary exception messages leaks implementation details and makes clients brittle.

What you must learn

Learn `ProblemDetails`, `IExceptionHandler`, exception mapping, validation problem details, status codes, trace IDs and safe production responses.

Practical code example

builder.Services.AddProblemDetails();
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();
var app = builder.Build();
app.UseExceptionHandler();

public sealed class GlobalExceptionHandler(ILogger<GlobalExceptionHandler> log) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(HttpContext context, Exception ex, CancellationToken ct)
    {
        log.LogError(ex, "Unhandled request failure {TraceId}", context.TraceIdentifier);
        context.Response.StatusCode = StatusCodes.Status500InternalServerError;
        await Results.Problem(statusCode: 500, title: "An unexpected error occurred.")
            .ExecuteAsync(context);
        return true;
    }
}

Build / practise

Create global error handling. Verify a 404, validation error, known business conflict and unexpected exception each produce the right response.

TOPIC 06

OpenAPI and API documentation

Why this matters

An API contract should be discoverable by frontend developers, mobile clients and integration partners without reading implementation source.

What you must learn

Learn OpenAPI schemas, operation summaries, response metadata, XML comments, authentication schemes, versioning and Scalar or Swagger UI.

Practical code example

builder.Services.AddOpenApi();
var app = builder.Build();
if (app.Environment.IsDevelopment()) app.MapOpenApi();

app.MapGet("/api/appointments/{id:guid}", (Guid id) => Results.Ok(new { id }))
   .WithName("GetAppointment")
   .WithSummary("Get one appointment by identifier");

Build / practise

Publish an OpenAPI document for the appointment API and inspect whether every response and security requirement is described.
