TOPIC GUIDE

Middleware, filters and configuration

Middleware handles cross-cutting HTTP concerns as requests pass through an ordered pipeline. Filters apply to MVC/controller execution stages. Configuration provides environment-specific settings without hard-coding deployment values.

1. Middleware mental model

Each middleware can perform work before and after the next component, short-circuit the pipeline, or pass control onward. Order matters.

app.Use(async (context, next) =>
{
    Console.WriteLine($"Incoming: {context.Request.Method} {context.Request.Path}");
    await next();
    Console.WriteLine($"Outgoing: {context.Response.StatusCode}");
});

app.MapGet("/api/ping", () => Results.Ok(new { message = "pong" }));

2. Build a custom middleware class

public sealed class RequestTimingMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<RequestTimingMiddleware> _logger;

    public RequestTimingMiddleware(
        RequestDelegate next,
        ILogger<RequestTimingMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var started = System.Diagnostics.Stopwatch.StartNew();
        await _next(context);
        started.Stop();

        _logger.LogInformation(
            "HTTP {Method} {Path} returned {StatusCode} in {ElapsedMs}ms",
            context.Request.Method,
            context.Request.Path,
            context.Response.StatusCode,
            started.ElapsedMilliseconds);
    }
}

// Register before endpoint execution:
app.UseMiddleware<RequestTimingMiddleware>();

3. Middleware ordering

app.UseExceptionHandler();
app.UseHttpsRedirection();
app.UseStaticFiles();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();

Authentication must run before authorization. Routing must establish endpoint metadata before endpoint-aware authorization. The correct complete order depends on enabled features (CORS, antiforgery, static files, rate limiting, output caching); follow the framework guidance for the selected features.

4. Exception handling

app.UseExceptionHandler(errorApp =>
{
    errorApp.Run(async context =>
    {
        context.Response.StatusCode = StatusCodes.Status500InternalServerError;
        context.Response.ContentType = "application/problem+json";

        await context.Response.WriteAsJsonAsync(new
        {
            title = "An unexpected error occurred.",
            status = StatusCodes.Status500InternalServerError
        });
    });
});

Do not return exception messages, stack traces, SQL details or secrets to clients. Log diagnostic details on the server with a correlation/trace identifier.

5. Filters and attributes

MVC filters run at specific stages around controller/action execution. They are useful for MVC-specific cross-cutting behavior. Middleware is broader and applies to the HTTP pipeline.

using Microsoft.AspNetCore.Mvc;
using Microsoft.AspNetCore.Mvc.Filters;

public sealed class RequireHospitalHeaderAttribute : ActionFilterAttribute
{
    public override void OnActionExecuting(ActionExecutingContext context)
    {
        if (!context.HttpContext.Request.Headers.ContainsKey("X-Hospital-Id"))
        {
            context.Result = new BadRequestObjectResult(
                new { error = "Hospital header is required." });
        }
    }
}

[RequireHospitalHeader]
[ApiController]
[Route("api/reports")]
public sealed class ReportsController : ControllerBase
{
    [HttpGet]
    public IActionResult Get() => Ok(new { report = "daily" });
}

Do not trust a client-supplied hospital identifier as authorization. Authenticate the caller and authorize access to the requested hospital using trusted claims and server-side policy checks. The header example only demonstrates filter execution.

6. appsettings.json and configuration providers

{
  "Hospital": {
    "Name": "Example General Hospital",
    "DefaultPageSize": 25
  },
  "ConnectionStrings": {
    "HospitalDb": "Server=localhost;Database=HospitalDb;Trusted_Connection=True;TrustServerCertificate=True"
  }
}

Connection strings in this sample are local-development examples only. Do not commit production credentials. Use user secrets locally and a managed secret store or protected environment configuration in production.

7. Bind configuration with options

public sealed class HospitalOptions
{
    public const string SectionName = "Hospital";
    public string Name { get; set; } = "";
    public int DefaultPageSize { get; set; } = 25;
}

// Registration
builder.Services.AddOptions<HospitalOptions>()
    .Bind(builder.Configuration.GetSection(HospitalOptions.SectionName))
    .Validate(o => !string.IsNullOrWhiteSpace(o.Name), "Hospital name is required.")
    .Validate(o => o.DefaultPageSize is > 0 and <= 100, "Page size must be 1–100.")
    .ValidateOnStart();

// Consumption
app.MapGet("/api/settings", (IOptions<HospitalOptions> options) =>
    Results.Ok(new { options.Value.Name, options.Value.DefaultPageSize }));

Practice

  1. Add request timing middleware and log method, path and duration.
  2. Configure a global exception handler returning Problem Details.
  3. Move hospital name and default page size into appsettings.
  4. Bind and validate strongly typed options at startup.
  5. Compare a middleware concern with an MVC filter concern.
