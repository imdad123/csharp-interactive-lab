TOPIC GUIDE

Entity Framework Core and data access

EF Core is an object-relational mapper. It maps .NET entity objects to relational tables and translates LINQ queries into database commands. It does not remove the need to understand SQL, indexes, transactions and database design.

1. Define entities and relationships

public sealed class Patient
{
    public int Id { get; set; }
    public required string MedicalRecordNumber { get; set; }
    public required string FullName { get; set; }
    public DateOnly DateOfBirth { get; set; }

    public List<Appointment> Appointments { get; set; } = [];
}

public sealed class Appointment
{
    public int Id { get; set; }
    public int PatientId { get; set; }
    public DateTime StartsAtUtc { get; set; }
    public string Status { get; set; } = "Booked";

    public Patient Patient { get; set; } = null!;
}

Patient has many appointments. The foreign key is Appointment.PatientId. For larger systems, define lengths, precision, required columns, indexes and delete behavior explicitly.

2. DbContext and configuration

using Microsoft.EntityFrameworkCore;

public sealed class HospitalDbContext(DbContextOptions<HospitalDbContext> options)
    : DbContext(options)
{
    public DbSet<Patient> Patients => Set<Patient>();
    public DbSet<Appointment> Appointments => Set<Appointment>();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Patient>()
            .HasIndex(p => p.MedicalRecordNumber)
            .IsUnique();

        modelBuilder.Entity<Patient>()
            .Property(p => p.FullName)
            .HasMaxLength(150)
            .IsRequired();

        modelBuilder.Entity<Appointment>()
            .HasOne(a => a.Patient)
            .WithMany(p => p.Appointments)
            .HasForeignKey(a => a.PatientId)
            .OnDelete(DeleteBehavior.Restrict);
    }
}

// Program.cs
builder.Services.AddDbContext<HospitalDbContext>(options =>
    options.UseSqlServer(
        builder.Configuration.GetConnectionString("HospitalDb")));

3. Code First migrations

dotnet tool install --global dotnet-ef
dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet add package Microsoft.EntityFrameworkCore.Design

dotnet ef migrations add InitialHospitalSchema
dotnet ef database update

Review generated migration SQL and test migrations against a disposable database before production. Keep migrations in source control. Do not treat automatic migration on every production startup as a universal deployment strategy.

4. Create and query records asynchronously

public sealed class PatientService(HospitalDbContext db)
{
    public async Task<int> RegisterAsync(
        string mrn,
        string fullName,
        DateOnly dateOfBirth,
        CancellationToken cancellationToken)
    {
        var patient = new Patient
        {
            MedicalRecordNumber = mrn,
            FullName = fullName.Trim(),
            DateOfBirth = dateOfBirth
        };

        db.Patients.Add(patient);
        await db.SaveChangesAsync(cancellationToken);
        return patient.Id;
    }

    public Task<Patient?> FindByMrnAsync(
        string mrn,
        CancellationToken cancellationToken)
    {
        return db.Patients
            .AsNoTracking()
            .SingleOrDefaultAsync(
                p => p.MedicalRecordNumber == mrn,
                cancellationToken);
    }
}

Use async database APIs in web requests so threads are not blocked while waiting for I/O. Pass cancellation tokens through to database operations.

5. Change tracking and AsNoTracking

// Tracked query: edit entity and save changes.
var patient = await db.Patients
    .SingleAsync(p => p.Id == id, cancellationToken);

patient.FullName = "Amina Khan";
await db.SaveChangesAsync(cancellationToken);

// Read-only query: avoid tracking overhead.
var rows = await db.Patients
    .AsNoTracking()
    .OrderBy(p => p.FullName)
    .Select(p => new PatientListItem(p.Id, p.FullName))
    .ToListAsync(cancellationToken);

Tracking is useful when changes will be saved through the same context. No-tracking is often appropriate for read-only endpoints. Project to DTOs to avoid loading unnecessary columns and entity graphs.

6. Eager, explicit and lazy loading

// Eager loading: fetch related appointments in the query.
var patient = await db.Patients
    .Include(p => p.Appointments)
    .SingleOrDefaultAsync(p => p.Id == id, cancellationToken);

// Explicit loading: load relationship after fetching patient.
if (patient is not null)
{
    await db.Entry(patient)
        .Collection(p => p.Appointments)
        .LoadAsync(cancellationToken);
}

Lazy loading loads navigation properties when accessed and can hide database round trips, causing N+1 query problems. Prefer deliberate projections or eager loading for API responses. Use lazy loading only when its behavior is understood and measured.

7. Transactions

await using var transaction =
    await db.Database.BeginTransactionAsync(cancellationToken);

try
{
    db.Patients.Add(patient);
    await db.SaveChangesAsync(cancellationToken);

    db.Appointments.Add(appointment);
    await db.SaveChangesAsync(cancellationToken);

    await transaction.CommitAsync(cancellationToken);
}
catch
{
    await transaction.RollbackAsync(cancellationToken);
    throw;
}

Use a transaction when multiple database operations must succeed or fail together. EF Core automatically wraps a single SaveChanges call in a transaction when the provider supports it. Do not keep transactions open during slow external network calls.

8. Raw SQL, stored procedures and alternatives

EF Core is not the only data-access choice. Dapper, RepoDB and ADO.NET can be appropriate for focused high-performance queries, legacy stored procedures or bulk operations. Parameterize all SQL; never concatenate user input into SQL text.

var patient = await db.Patients
    .FromSqlInterpolated(
        $"SELECT * FROM dbo.Patients WHERE MedicalRecordNumber = {mrn}")
    .AsNoTracking()
    .SingleOrDefaultAsync(cancellationToken);

FromSqlInterpolated parameterizes interpolated values. Do not use raw SQL interpolation APIs that treat user input as SQL syntax.
