GUIDE 12 · ASP.NET CORE / .NET 10

Capstone: build an enterprise Hospital Management API

Integrate the roadmap into one realistic, secure and observable system. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

Project architecture and module boundaries

Why this matters

A capstone proves that concepts work together. Start with a modular monolith and explicit modules before considering distributed services.

What you must learn

Create projects for Api, Application, Domain, Infrastructure and Tests. Define modules: Patients, Scheduling, Admissions, Wards, Pharmacy, Billing, Identity and Reporting.

Practical code example

Hospital.sln
src/Hospital.Api
src/Hospital.Application
src/Hospital.Domain
src/Hospital.Infrastructure
tests/Hospital.UnitTests
tests/Hospital.IntegrationTests

Build / practise

Create the solution, dependency rules, coding conventions and architecture decision records.

TOPIC 02

Patient registration and medical record access

Why this matters

Patient data requires validation, uniqueness, auditability and strict access control. Treat privacy and authorization as core domain requirements.

What you must learn

Implement patient DTOs, MRN uniqueness, database constraints, audit events, resource authorization, pagination and safe search.

Practical code example

public sealed record RegisterPatient(string Mrn, string FullName, DateOnly DateOfBirth);

public async Task<Guid> Handle(RegisterPatient request, CancellationToken ct)
{
    if (await patients.ExistsByMrnAsync(request.Mrn, ct))
        throw new PatientMrnAlreadyExistsException(request.Mrn);
    var patient = Patient.Register(request.Mrn, request.FullName, request.DateOfBirth);
    await patients.AddAsync(patient, ct);
    return patient.Id;
}

Build / practise

Build patient registration, search, detail access and audit logging. Test duplicate MRN and unauthorized access.

TOPIC 03

Doctor scheduling and appointment booking

Why this matters

Scheduling combines domain rules, concurrency and transactional persistence. Two receptionists must not book the same doctor at the same time.

What you must learn

Implement doctor availability, time zones, UTC storage, overlap detection, database constraints or locking strategy, cancellation and rescheduling.

Practical code example

public static bool Overlaps(DateTimeOffset startA, DateTimeOffset endA,
    DateTimeOffset startB, DateTimeOffset endB) => startA < endB && startB < endA;

Build / practise

Build booking, rescheduling and cancellation. Run concurrent booking tests to prove double booking is prevented.

TOPIC 04

Admissions, wards and bed occupancy

Why this matters

Bed allocation is a state transition with consistency requirements. A bed cannot be allocated to two active admissions simultaneously.

What you must learn

Implement admission workflow, bed status, ward/room relationships, transaction boundaries, concurrency tokens and occupancy reporting.

Practical code example

await using var tx = await db.Database.BeginTransactionAsync(ct);
var bed = await db.Beds.SingleAsync(x => x.Id == bedId, ct);
if (bed.IsOccupied) throw new BedAlreadyOccupiedException(bedId);
bed.AssignTo(admissionId);
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);

Build / practise

Build admission and discharge workflows and test concurrent attempts to allocate the same bed.

TOPIC 05

Billing, payments and financial integrity

Why this matters

Financial operations need exact decimal arithmetic, immutable ledger-style records, idempotency and auditability. Never trust a client-supplied total.

What you must learn

Implement invoice lines, decimal precision, payment intents, transaction boundaries, payment gateway integration, reconciliation, refunds and role permissions.

Practical code example

public sealed record PaymentRequest(Guid InvoiceId, decimal Amount, string Currency, string IdempotencyKey);

if (request.Amount <= 0) throw new ArgumentOutOfRangeException(nameof(request.Amount));
// Load invoice and calculate amount due on the server; never trust a client total.

Build / practise

Build invoice generation, cash/bank payment posting, refund and reconciliation. Test duplicate payment requests.

TOPIC 06

Pharmacy and inventory

Why this matters

Inventory requires controlled stock movements, lot/expiry tracking and transactional updates. A simple quantity column is insufficient for traceability.

What you must learn

Implement products, batches, expiry dates, stock ledger, issue/return, reorder levels, concurrency and audit events.

Practical code example

public sealed record StockMovement(Guid ProductId, Guid BatchId,
    decimal Quantity, string MovementType, DateTimeOffset OccurredAtUtc);

Build / practise

Build receive, dispense and return workflows. Prevent negative stock under concurrent dispensing.

TOPIC 07

Reporting and operational dashboards

Why this matters

Reports can be expensive and may expose data users are not allowed to see. Separate operational queries from transactional writes where needed.

What you must learn

Implement filtered reports, server-side pagination, aggregation, read models, export limits, role-based filtering and query performance checks.

Practical code example

var daily = await db.Appointments.AsNoTracking()
    .Where(x => x.StartsAt >= dayStartUtc && x.StartsAt < dayEndUtc)
    .GroupBy(x => x.Status)
    .Select(g => new { Status = g.Key, Count = g.Count() })
    .ToListAsync(ct);

Build / practise

Build daily appointments, revenue and bed occupancy reports with authorization and bounded date ranges.

TOPIC 08

Release readiness and production simulation

Why this matters

The final skill is operating the system, not merely making it run on a developer laptop.

What you must learn

Add unit/integration/E2E tests, CI/CD, migrations, Docker, secrets, health checks, OpenTelemetry, backups, restore drills, rate limits and incident runbooks.

Practical code example

dotnet restore
dotnet build -c Release --no-restore
dotnet test -c Release --no-build
dotnet publish src/Hospital.Api -c Release -o ./publish

Build / practise

Deploy to a staging environment, execute smoke tests, rehearse rollback and perform a database restore exercise.
