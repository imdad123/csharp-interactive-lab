GUIDE 02 · ASP.NET CORE / .NET 10

HTTP, hosting and the ASP.NET Core request pipeline

Learn how requests enter, flow through and leave an ASP.NET Core application. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

HTTP fundamentals for API developers

Why this matters

ASP.NET Core is an HTTP application framework. Correct use of methods, status codes, headers, content types and caching makes APIs predictable for clients.

What you must learn

Learn request/response structure, GET/POST/PUT/PATCH/DELETE, safe and idempotent methods, status codes, headers, JSON, content negotiation, cookies, CORS and HTTPS.

Practical code example

app.MapGet("/api/health", () => Results.Ok(new { status = "healthy" }));
app.MapPost("/api/appointments", (CreateAppointmentRequest request) =>
    Results.Created($"/api/appointments/{Guid.NewGuid()}", request));

Build / practise

Design HTTP contracts for patient lookup and appointment booking. Select correct status codes and explain idempotency.

TOPIC 02

Kestrel, hosting and reverse proxies

Why this matters

Kestrel is the cross-platform web server used by ASP.NET Core. In production it commonly runs behind a reverse proxy or cloud ingress that handles TLS, routing or edge concerns.

What you must learn

Learn Kestrel endpoints, hosting models, forwarded headers, reverse proxies, IIS integration, container hosting, graceful shutdown and health checks.

Practical code example

var builder = WebApplication.CreateBuilder(args);
builder.WebHost.ConfigureKestrel(options =>
{
    options.Limits.MaxRequestBodySize = 10 * 1024 * 1024;
});
var app = builder.Build();
app.MapGet("/health", () => Results.Ok("ok"));
app.Run();

Build / practise

Run locally, then behind a reverse proxy. Verify forwarded scheme and client IP handling before trusting proxy headers.

TOPIC 03

Middleware and pipeline ordering

Why this matters

Middleware forms an ordered pipeline. Ordering changes behavior: authentication must run before authorization, and exception handling should wrap downstream components.

What you must learn

Learn `Use`, `Run`, `Map`, `UseWhen`, short-circuiting, request delegates, exception handling, HTTPS redirection, static files, routing, authentication and authorization ordering.

Practical code example

var app = builder.Build();
app.UseExceptionHandler();
app.UseHttpsRedirection();
app.UseRouting();
app.UseAuthentication();
app.UseAuthorization();
app.MapControllers();
app.Run();

Build / practise

Write request-timing middleware and demonstrate how moving it before or after `next(context)` changes what it measures.

TOPIC 04

Build custom middleware

Why this matters

Custom middleware is useful for cross-cutting HTTP concerns that should not be duplicated in controllers, such as correlation IDs or request timing.

What you must learn

Learn constructor injection, `InvokeAsync`, `RequestDelegate`, scoped service resolution, response headers and safe exception handling.

Practical code example

public sealed class CorrelationIdMiddleware(RequestDelegate next)
{
    public async Task InvokeAsync(HttpContext context)
    {
        var id = context.Request.Headers["X-Correlation-ID"].FirstOrDefault()
                 ?? Guid.NewGuid().ToString("N");
        context.TraceIdentifier = id;
        context.Response.Headers["X-Correlation-ID"] = id;
        await next(context);
    }
}

Build / practise

Register middleware and confirm every API response returns a correlation ID. Avoid logging raw authorization headers.

TOPIC 05

Routing, endpoints and route constraints

Why this matters

Routing maps a URL and HTTP method to an endpoint. Route constraints prevent ambiguous or invalid URL values from reaching application code.

What you must learn

Learn endpoint routing, route templates, parameter binding, constraints, route groups, endpoint metadata and named routes.

Practical code example

app.MapGet("/api/patients/{id:guid}", (Guid id) =>
    Results.Ok(new { PatientId = id }));
app.MapGet("/api/doctors/{doctorId:int}/appointments", (int doctorId) =>
    Results.Ok(new { DoctorId = doctorId }));

Build / practise

Create consistent resource routes for patients, doctors, appointments and invoices. Avoid action names embedded in URLs where resource routes are clearer.
