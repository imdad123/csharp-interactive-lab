ASP.NET Core background jobs, messaging and gateways

Concept, purpose, code examples and production considerations with hospital application scenarios.

Native BackgroundService and IHostedService

Hosted services run background work inside the application host. Observe cancellation, keep iterations bounded and create a DI scope when scoped services are required.

public sealed class ReminderWorker(IServiceScopeFactory scopes) : BackgroundService
{
 protected override async Task ExecuteAsync(CancellationToken stoppingToken)
 {
  while (!stoppingToken.IsCancellationRequested)
  {
   await using var scope = scopes.CreateAsyncScope();
   var sender = scope.ServiceProvider.GetRequiredService<IReminderSender>();
   await sender.SendDueRemindersAsync(stoppingToken);
   await Task.Delay(TimeSpan.FromMinutes(1), stoppingToken);
  }
 }
}

Hangfire, Quartz and Coravel

Hangfire provides persistent jobs and dashboard capabilities; Quartz is a mature scheduler; Coravel offers lightweight scheduling. Compare persistence, clustering, retries, monitoring and licensing/hosting needs.

// Hangfire recurring job example (after package and storage setup):
RecurringJob.AddOrUpdate<ReminderJob>(
 "appointment-reminders", job => job.SendDueAsync(), Cron.MinuteInterval(5));

Message brokers: RabbitMQ, ActiveMQ, Kafka, NetMQ and Azure Service Bus

Message brokers decouple producers and consumers. RabbitMQ/ActiveMQ and Azure Service Bus support queue/routing patterns; Kafka is a distributed event log; NetMQ is a ZeroMQ-style messaging library. Choose by durability, ordering, throughput and operations.

public sealed record InvoiceFinalized(Guid EventId, int InvoiceId, DateTime OccurredAtUtc);
await bus.PublishAsync(new InvoiceFinalized(Guid.NewGuid(), invoice.Id, DateTime.UtcNow), ct);
,

Message bus frameworks: NServiceBus, MassTransit and EasyNetQ

These frameworks provide higher-level consumer, retry, routing and workflow abstractions over supported transports. They add conventions and operational dependencies; select one deliberately.

public sealed class InvoiceFinalizedConsumer : IConsumer<InvoiceFinalized>
{
 public Task Consume(ConsumeContext<InvoiceFinalized> context)
  => SendReceiptAsync(context.Message.InvoiceId);
}

Outbox and idempotent message processing

A database transaction and broker publish are not automatically atomic. The outbox records events in the same transaction as business data; a dispatcher publishes them later. Consumers should handle duplicate deliveries.

// In the same DB transaction as invoice finalization:
db.Invoices.Update(invoice);
db.OutboxMessages.Add(OutboxMessage.From(new InvoiceFinalized(...)));
await db.SaveChangesAsync(ct);
,

Microservices architecture

Microservices are independently deployable services aligned to business capabilities. They add network failures, distributed consistency, deployment and observability costs. A modular monolith is often the better starting point.

src/
  Modules/Patients/Patients.Domain/
  Modules/Patients/Patients.Application/
  Modules/Appointments/Appointments.Domain/
  Modules/Appointments/Appointments.Application/
  Hospital.Api/
,

API gateways: Ocelot and YARP

A gateway routes client requests to backend services and can centralize edge policies. It does not replace service authorization or domain rules.

builder.Services.AddReverseProxy()
 .LoadFromConfig(builder.Configuration.GetSection("ReverseProxy"));
app.MapReverseProxy();
,

Docker containerization

Docker packages application output and runtime dependencies into an image. Use multi-stage builds, non-root execution, health checks and externalized configuration.

dotnet publish -c Release -o ./publish
docker build -t hospital-api:1.0 .
docker run --rm -p 8080:8080 hospital-api:1.0
,

Kubernetes

Kubernetes orchestrates containers with deployments, services, probes, configuration and scaling. Use it when the operational need justifies cluster complexity.

kubectl apply -f deployment.yaml
kubectl get deployments
kubectl rollout status deployment/hospital-api
