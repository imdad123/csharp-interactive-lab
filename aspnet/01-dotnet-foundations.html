GUIDE 01 · ASP.NET CORE / .NET 10

.NET foundations for web engineers

Understand the platform before building services. Each topic includes its purpose, the knowledge to acquire, a practical example and an implementation exercise.

Learning rule: Do not just read the code. Create the project, run it, test normal and failure cases, inspect logs and SQL, then explain the trade-offs in your own words. Examples are focused teaching snippets; add the required namespaces, packages and surrounding application types when integrating them.

TOPIC 01

The .NET platform, SDK, runtime and CLR

Why this matters

The SDK builds and tests applications; the runtime executes them; the CLR manages managed execution, type safety, garbage collection and exceptions. Knowing the difference helps diagnose build-versus-runtime failures.

What you must learn

Install the .NET SDK, inspect `dotnet --info`, create a Web API, and learn the role of the shared framework and target framework moniker.

Practical code example

dotnet --info
dotnet new webapi -n Hospital.Api
dotnet build Hospital.Api
dotnet run --project Hospital.Api

Build / practise

Create a clean API project and explain what happens from `dotnet run` to the first HTTP response.

TOPIC 02

Solution and project structure

Why this matters

A solution groups projects; each project has its own compilation settings and dependencies. Separating API, application, domain and infrastructure prevents one giant project from becoming difficult to test.

What you must learn

Learn `.sln`, `.csproj`, target frameworks, package references, project references, build configurations, `Directory.Build.props`, user secrets and launch settings.

Practical code example

dotnet new sln -n Hospital
dotnet new classlib -n Hospital.Domain
dotnet new webapi -n Hospital.Api
dotnet sln add Hospital.Domain/Hospital.Domain.csproj Hospital.Api/Hospital.Api.csproj
dotnet add Hospital.Api/Hospital.Api.csproj reference Hospital.Domain/Hospital.Domain.csproj

Build / practise

Create a multi-project solution and reference the domain project from the API without introducing circular dependencies.

TOPIC 03

NuGet and dependency management

Why this matters

NuGet packages let applications reuse libraries, but uncontrolled package versions create security and compatibility risk.

What you must learn

Learn package references, transitive dependencies, version pinning, central package management, vulnerability auditing and package updates.

Practical code example

dotnet add package Microsoft.EntityFrameworkCore.SqlServer
dotnet list package --include-transitive
dotnet list package --vulnerable

Build / practise

Add EF Core SQL Server, inspect transitive dependencies and resolve a reported vulnerable package in a practice branch.

TOPIC 04

Configuration by environment

Why this matters

Development, testing and production need different connection strings and settings. Configuration providers allow the same build to run safely in each environment.

What you must learn

Learn `appsettings.json`, environment-specific JSON, environment variables, command-line configuration, user secrets, options binding and validation. Never commit production secrets.

Practical code example

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddOptions<ClinicOptions>()
    .Bind(builder.Configuration.GetSection("Clinic"))
    .ValidateDataAnnotations()
    .ValidateOnStart();

public sealed class ClinicOptions
{
    [System.ComponentModel.DataAnnotations.Required]
    public string Name { get; init; } = "";
}

Build / practise

Create Development and Production configurations and prove that an environment variable overrides JSON.

TOPIC 05

Logging and diagnostics foundations

Why this matters

A service that fails without useful logs is expensive to support. Logs should explain what happened without exposing patient data, credentials or tokens.

What you must learn

Learn `ILogger`, log levels, structured properties, scopes, exception logging, correlation IDs and the difference between logs, metrics and traces.

Practical code example

public sealed class AppointmentService(ILogger<AppointmentService> logger)
{
    public void Book(Guid appointmentId)
    {
        logger.LogInformation("Booking appointment {AppointmentId}", appointmentId);
    }
}

Build / practise

Add structured logs to appointment creation. Ensure logs contain identifiers needed for support but no sensitive medical details.
