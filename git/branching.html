GIT · MODULE 02

Branching and team collaboration

Branches allow developers to work on separate changes without constantly destabilizing the shared main branch.

Feature branch workflow

git switch main
git pull --ff-only origin main
git switch -c feature/patient-registration
# edit files, run tests
git add .
git commit -m "feat(patient): add registration"
git push -u origin feature/patient-registration

Open a pull request against main. Review the diff, verify tests and checks, request changes when needed, then merge according to team policy.

Merge and rebase

Merge combines histories and can create a merge commit. Rebase replays commits onto a new base and creates new commit IDs. Rebase is useful for cleaning a private feature branch; avoid rebasing commits other developers already depend on unless the team explicitly coordinates it.

# Update feature branch by replaying its commits on latest main
git fetch origin
git switch feature/patient-registration
git rebase origin/main

Resolve conflicts deliberately

  1. Inspect conflict markers and understand both changes.
  2. Edit the file into the intended combined result.
  3. Run formatter, tests and relevant application checks.
  4. Stage the resolved file and continue merge/rebase.
git status
git add src/AppointmentService.cs
git rebase --continue

Do not blindly choose “ours” or “theirs” for business logic. For appointment booking, a conflict may represent two important validation rules that both need to survive.

Remote commands

  • fetch downloads remote history without changing your current branch.
  • pull fetches and integrates remote changes.
  • push publishes your commits to the remote.
  • origin is commonly your repository remote; upstream often refers to the original repository when contributing to a fork.

Practice task

  1. Create two feature branches for patient and appointment work.
  2. Make overlapping edits and resolve a real conflict.
  3. Push both branches and open pull requests.
  4. Review a teammate's code and leave actionable feedback.
  5. Merge only after checks pass.
