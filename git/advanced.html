GIT · MODULE 03

Advanced Git and safe recovery

Professional Git skill includes recovering from mistakes without destroying teammates' work.

Restore, reset and revert are different

  • git restore: discard or restore file content in the working tree/index.
  • git reset: move the current branch pointer and optionally change staging/working state. It can rewrite local history.
  • git revert: create a new commit that reverses an earlier commit. Usually the safer choice for shared history.
# Undo a pushed faulty commit safely by creating a new inverse commit
git revert <commit-sha>

# Unstage a file without discarding its edits
git restore --staged src/PatientService.cs

# Inspect recent branch movements when a commit seems lost
git reflog

Before destructive commands, inspect status and log. Avoid force-pushing shared branches. If a force push is genuinely required on a private feature branch, coordinate and prefer --force-with-lease over --force.

Stash and cherry-pick

git stash push -m "WIP appointment validation"
git stash list
git stash pop

# Apply one commit from another branch
git cherry-pick <commit-sha>

Stash temporarily shelves working changes. Cherry-pick copies a commit's change onto the current branch and creates a new commit.

Tags and bisect

git tag -a v1.2.0 -m "Hospital HMS release 1.2.0"
git push origin v1.2.0

git bisect start
git bisect bad
git bisect good v1.1.0
# test the checked-out revision, then mark good or bad
git bisect good

Tags identify release points. Bisect performs a binary search through commit history to locate the change that introduced a regression.

Blame and reflog

git blame shows which commit last changed each line; use it to understand context, not to assign blame to a person. Reflog records local reference movements and can help recover a commit after an accidental reset, until reflog entries expire and unreachable objects are pruned.

Practice task

  1. Make a faulty appointment validation commit and revert it.
  2. Unstage a file while preserving its working changes.
  3. Stash unfinished work and restore it later.
  4. Cherry-pick a fix into a release branch.
  5. Use bisect to find a deliberately introduced bug.
