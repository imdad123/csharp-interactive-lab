GIT · MODULE 04

GitHub governance and delivery workflow

A repository becomes a professional engineering workspace when access, reviews, automated checks and releases are controlled.

Protect the main branch

  • Require pull requests rather than direct pushes.
  • Require successful build and test checks.
  • Require at least one review for critical repositories.
  • Restrict force pushes and branch deletion.
  • Use CODEOWNERS for sensitive areas such as billing and authentication.

Commit and pull request quality

Use focused commits with clear messages. A pull request should explain the problem, approach, risks, testing performed and screenshots/API examples when useful. Keep reviews specific and respectful. Small PRs are easier to review and safer to merge.

Continuous integration

A GitHub Actions workflow can restore dependencies, build the application, run unit tests, run static analysis and publish artifacts. Keep credentials in repository/environment secrets or a secure identity federation mechanism. Never print secrets in logs.

name: Hospital HMS CI
on:
  pull_request:
    branches: [ main ]
jobs:
  build-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run project checks
        run: |
          dotnet restore
          dotnet build --no-restore
          dotnet test --no-build

This is an illustrative .NET workflow; PHP, JavaScript and Python tracks will have their own dependency installation and test commands.

Release management

Use annotated tags for release points and a consistent versioning policy. Maintain release notes that describe features, fixes, migrations and operational changes. A production release should be traceable to a commit and a tested artifact.

Repository hygiene and security

Review dependencies, enable secret scanning where available, remove stale branches, document setup instructions, assign maintainers and define backup/restore expectations. If a secret enters Git history, rotate it immediately; history rewriting does not invalidate a leaked credential.

Hospital HMS team exercise

  1. Protect main and require CI checks.
  2. Add CODEOWNERS for billing and security-sensitive files.
  3. Open a feature PR with a clear test plan.
  4. Merge after review and successful checks.
  5. Create an annotated release tag and release notes.
  6. Deploy the same tested artifact to staging, then production using approval controls.
