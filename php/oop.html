OOP, Composer and architecture

Move from procedural scripts to organized application code without adding unnecessary complexity.

Classes and encapsulation

final class Patient
{
    public function __construct(
        public readonly int $id,
        private string $name,
        private bool $active = true,
    ) {
        if ($id <= 0 || trim($name) === '') {
            throw new InvalidArgumentException('Invalid patient');
        }
    }

    public function name(): string { return $this->name; }
    public function deactivate(): void { $this->active = false; }
    public function isActive(): bool { return $this->active; }
}

The object protects its invariants. Callers cannot directly reactivate a patient by changing a public field; they must use a defined operation.

Interfaces and dependency inversion

interface AppointmentNotifier
{
    public function sendConfirmation(int $appointmentId): void;
}

final class AppointmentService
{
    public function __construct(private AppointmentNotifier $notifier) {}

    public function confirm(int $appointmentId): void
    {
        // Apply booking rules and persist status here.
        $this->notifier->sendConfirmation($appointmentId);
    }
}

The service depends on a capability, not a specific SMS vendor. A test fake can implement the same interface.

Namespaces and Composer

Namespaces organize classes and avoid name collisions. Composer manages dependencies and PSR-4 autoloading. Commit composer.json and composer.lock; do not commit vendor dependencies unless a deployment policy explicitly requires it.

{
  "autoload": { "psr-4": { "Hospital\\": "src/" } },
  "require": { "php": "^8.2" }
}

Run composer dump-autoload after changing autoload configuration. Use dependency constraints intentionally and review updates for security and compatibility.

Architecture boundaries

  • Controller: HTTP input/output coordination.
  • Application service: use-case orchestration, such as booking an appointment.
  • Domain: rules and concepts such as appointment eligibility.
  • Infrastructure: PDO, email, SMS and external integrations.

Do not let a domain rule depend on $_POST, a framework request object or a SQL connection. Frameworks such as Laravel and CodeIgniter provide conventions, but the separation of responsibilities still matters.
