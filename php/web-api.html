Web applications and REST APIs

Understand how a browser, mobile application and PHP backend communicate.

HTTP request and response

A request has a method, URL, headers and sometimes a body. The server responds with a status code, headers and content. GET retrieves, POST creates/processes, PUT replaces, PATCH partially updates and DELETE requests removal. Design idempotency and retries carefully for financial operations.

Simple JSON endpoint

<?php
header('Content-Type: application/json; charset=utf-8');
http_response_code(200);
echo json_encode([
    'success' => true,
    'data' => ['patientId' => 1205, 'name' => 'Amina Khan']
], JSON_THROW_ON_ERROR);

In production, route requests through a front controller/router, validate input, authenticate the caller, authorize the specific resource, call an application service and map results to response DTOs.

Sessions and authentication

Sessions can maintain server-side login state for browser applications. Regenerate the session ID after login, set secure cookie flags, expire inactive sessions and implement logout. APIs commonly use appropriately managed bearer tokens or another identity protocol; do not invent a custom token format.

Framework architecture

Laravel and CodeIgniter provide routing, controllers, validation, database integration, middleware/filters and conventions. Learn what the framework does for you: request lifecycle, dependency resolution, model behavior, migrations, CSRF and error handling. Avoid putting all business logic in a controller.

Practice task

  1. Create GET /api/patients/{id} and POST /api/patients.
  2. Return JSON DTOs, not database rows with every column.
  3. Use correct status codes: 201 created, 400 invalid input, 401 unauthenticated, 403 forbidden, 404 missing and 409 conflict.
  4. Build an appointment booking endpoint with duplicate-slot protection.
  5. Call the API from a small frontend and test with an HTTP client.
