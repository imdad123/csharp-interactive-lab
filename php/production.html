PHP testing, security and production delivery

A practical guide to tests, code quality, security, containers and deployment.

Testing with PHPUnit

use PHPUnit\Framework\TestCase;

final class ConsultationFeeTest extends TestCase
{
    public function testDiscountCannotExceedFee(): void
    {
        $this->expectException(InvalidArgumentException::class);

        ConsultationFee::fromAmounts(1000, 1200);
    }
}

Separate domain rules from superglobals, HTTP request objects and database connections. Test business rules directly, then add integration tests against a real test database.

Security reference

  • Hash passwords with password_hash and verify with password_verify.
  • Use PDO prepared statements; never concatenate untrusted input into SQL.
  • Escape output for its HTML context to prevent XSS.
  • Use CSRF tokens for cookie-authenticated browser forms.
  • Enforce authorization on every protected operation and record sensitive access.
  • Validate uploaded file size, MIME/content, extension and storage location.
  • Keep secrets outside the repository and rotate exposed credentials.

Composer, standards and static analysis

composer init
composer require --dev phpunit/phpunit
composer require --dev phpstan/phpstan
composer dump-autoload

Use PSR-4 autoloading, PSR coding standards, PHPStan or Psalm, PHP_CodeSniffer/PHP-CS-Fixer and a lock file committed to version control.

Docker and CI/CD

Build a reproducible PHP runtime image, install dependencies from composer.lock, run tests and static analysis in CI, build an immutable artifact, then deploy to staging and production with environment-specific secrets. Run database migrations as a controlled release step.

composer install --no-interaction --prefer-dist
vendor/bin/phpunit
vendor/bin/phpstan analyse
vendor/bin/phpcs src
