PHP · MODULE 05

Security, testing and deployment

A hospital system handles sensitive patient and financial information. Security and reliability must be designed into every layer.

Password storage

$hash = password_hash($password, PASSWORD_DEFAULT);
// Store $hash, never the original password.
if (password_verify($submittedPassword, $hash)) {
    // Authentication succeeded.
}

Use password_hash/password_verify, enforce sensible password policies and rate-limit login attempts. Never log credentials or tokens.

Core web security controls

  • SQL injection: PDO prepared statements for all values.
  • XSS: context-aware output escaping, such as htmlspecialchars for HTML text/attributes.
  • CSRF: anti-CSRF tokens for state-changing browser requests.
  • Authorization: check role and resource ownership on the server for every sensitive operation.
  • File uploads: allow-list file types, inspect content, limit size, rename files and store outside public web root.
  • Secrets: environment/secret manager, never commit passwords or production connection strings.

Testing with PHPUnit

Unit-test business rules without HTTP or a database. Integration-test PDO queries against a test database. API tests verify response codes, authentication and validation. A fake notifier lets you test appointment confirmation without sending real SMS.

public function testInvoiceBalanceIsCalculatedCorrectly(): void
{
    $balance = BillingRules::balance(5000, 3200);
    self::assertSame(1800, $balance);
}

Production operations

Use Composer lock files, automated tests, static analysis, coding standards, structured logs, HTTPS, environment-specific configuration, least-privilege database users, database backups, monitoring and tested restore procedures. Use Docker/CI pipelines when they make builds and deployments reproducible.

Capstone acceptance criteria

  1. Patient records are protected by role/resource authorization.
  2. Appointment conflicts are prevented consistently.
  3. Invoice posting is transactional and auditable.
  4. Critical rules have automated tests.
  5. Secrets are not committed and errors do not expose sensitive data.
  6. Deployment and backup restoration are documented and tested.
