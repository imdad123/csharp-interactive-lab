05 · Exceptions, files and persistence

Handle failures intentionally, manage resources and understand basic persistence patterns.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Why exceptions exist

Exceptions represent failures that interrupt normal execution. They are for exceptional conditions, not ordinary validation or routine branching.

try
{
    var patient = repository.GetById(patientId);
}
catch (PatientNotFoundException ex)
{
    logger.LogWarning(ex, "Patient {PatientId} was not found", patientId);
    throw;
}

Professional exception handling

  • Catch only exceptions you can handle meaningfully.
  • Use throw; to rethrow and preserve the original stack trace.
  • Do not swallow exceptions or return fake success values.
  • Log at the boundary with useful context; avoid logging the same failure repeatedly.
  • Translate low-level errors into safe API or UI responses.
  • Use validation results for expected invalid input; exceptions for unexpected failures or violated invariants.

Files and serialization

Use System.IO for files and directories. Understand streams, async file operations, JSON serialization and deserialization. Validate external data and do not store secrets in plain-text files.

string json = JsonSerializer.Serialize(patient);
await File.WriteAllTextAsync(path, json, cancellationToken);
string loaded = await File.ReadAllTextAsync(path, cancellationToken);
Patient? restored = JsonSerializer.Deserialize<Patient>(loaded);

Resource management

Files, streams, sockets and database connections can hold operating-system resources. IDisposable and using provide deterministic cleanup; IAsyncDisposable and await using support asynchronous cleanup. Garbage collection does not replace resource disposal.

HospitalApp practice

  • Validate patient details before saving.
  • Represent missing patients as a defined outcome.
  • Practice a JSON export/import exercise before database persistence.
  • Dispose streams and connections correctly.

Deep dive: exceptions, validation, files and resource safety

Validation is not an exception

An invalid phone number is an expected input outcome: return validation errors. A database outage or corrupted configuration is exceptional and should be handled at a boundary with logging.

Throw near the violated rule; catch where recovery is possible

public static decimal Balance(decimal charges, decimal payments)
{
    if (charges < 0) throw new ArgumentOutOfRangeException(nameof(charges));
    if (payments < 0) throw new ArgumentOutOfRangeException(nameof(payments));
    return charges - payments;
}
try { Console.WriteLine(Balance(5000m, 2000m)); }
catch (ArgumentOutOfRangeException ex)
{ Console.WriteLine($"Invalid financial input: {ex.Message}"); }

Do not wrap every line in try/catch. Catch only when you can recover, translate the error or add context and rethrow. Use throw; to preserve the stack, not throw ex;.

Files and serialization

Use structured formats such as JSON for exports instead of fragile custom text formats.

using System.Text.Json;
var export = new PatientExport(101, "Amina Khan");
string json = JsonSerializer.Serialize(export);
await File.WriteAllTextAsync("patient-export.json", json);
string loaded = await File.ReadAllTextAsync("patient-export.json");
PatientExport? restored = JsonSerializer.Deserialize<PatientExport>(loaded);

Do not export sensitive patient data to uncontrolled folders. Apply access control, encryption and retention policies.

Dispose external resources

Files, streams and database connections hold external resources. using/await using guarantees disposal even when an exception occurs.

await using var stream = new FileStream("report.txt", FileMode.Create);
await using var writer = new StreamWriter(stream);
await writer.WriteLineAsync("Daily appointment report");

Never keep a database connection open while waiting for a user to type. Dispose ADO.NET connections and commands deterministically.

Practice task

  1. Validate patient data with clear messages.
  2. Throw for impossible internal states.
  3. Export a sample patient list to JSON.
  4. Handle missing-file and permission failures at the UI boundary.
  5. Ensure streams and database objects are disposed.

Worked examples: exceptions, files, JSON and configuration

Exception handling with try/catch/finally

try
{
    int age = int.Parse("not-a-number");
    Console.WriteLine(age);
}
catch (FormatException ex)
{
    Console.WriteLine($"Invalid numeric format: {ex.Message}");
}
finally
{
    Console.WriteLine("Validation attempt finished.");
}

Catch the most specific exception you can handle. finally runs whether an exception occurs or not; for disposable resources prefer using/await using.

Exception propagation and stack preservation

static void RegisterPatient()
{
    ValidatePatient();
}

static void ValidatePatient()
{
    throw new InvalidOperationException("Patient registration rule failed.");
}

try
{
    RegisterPatient();
}
catch (InvalidOperationException)
{
    // "throw;" preserves the original stack trace.
    throw;
}

Do not use throw ex; when rethrowing; it resets the stack trace origin. Either handle the exception meaningfully or let it propagate.

Custom domain exception

public sealed class DuplicateMedicalRecordException : Exception
{
    public DuplicateMedicalRecordException(string mrn)
        : base($"Medical record number '{mrn}' already exists.")
    {
        MedicalRecordNumber = mrn;
    }

    public string MedicalRecordNumber { get; }
}

static void EnsureUniqueMrn(string mrn, bool exists)
{
    if (exists)
        throw new DuplicateMedicalRecordException(mrn);
}

Use custom exceptions when callers can respond to a meaningful failure category. Avoid building a large hierarchy for every validation message; ordinary invalid input is often better represented as a validation result.

File paths and safe text file operations

string folder = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "HospitalApp");

Directory.CreateDirectory(folder);
string filePath = Path.Combine(folder, "daily-report.txt");

await File.WriteAllTextAsync(filePath, "Daily collection: 125000");
string report = await File.ReadAllTextAsync(filePath);
Console.WriteLine(report);

Use Path.Combine rather than manually joining path separators. Validate file names and permissions when paths come from user input. Do not store secrets or sensitive patient data in unprotected plain text files.

Append audit events

string auditPath = Path.Combine(folder, "audit.log");
string auditLine = $"{DateTimeOffset.UtcNow:O} | PatientViewed | User=42";

await File.AppendAllTextAsync(auditPath, auditLine + Environment.NewLine);

This simple example is not a production audit system: concurrent writes, tamper resistance, retention, access controls and centralized storage need deliberate design.

JSON serialization

using System.Text.Json;

public sealed record PatientExport(int Id, string Mrn, string Name);

var export = new PatientExport(1205, "MR-1205", "Amina Khan");
var options = new JsonSerializerOptions { WriteIndented = true };

string json = JsonSerializer.Serialize(export, options);
Console.WriteLine(json);

PatientExport? restored =
    JsonSerializer.Deserialize<PatientExport>(json);

Deserialize external JSON defensively

try
{
    PatientExport? imported = JsonSerializer.Deserialize<PatientExport>(json);

    if (imported is null || imported.Id <= 0 ||
        string.IsNullOrWhiteSpace(imported.Mrn))
        throw new InvalidDataException("Patient export is invalid.");
}
catch (JsonException ex)
{
    Console.WriteLine($"Malformed JSON: {ex.Message}");
}

Deserialization is not validation. Treat imported JSON as untrusted and validate required fields, ranges and authorization before using it.

Read configuration from appsettings.json

// appsettings.json
{
  "Hospital": {
    "Name": "General Hospital",
    "DefaultPageSize": 25
  }
}
using Microsoft.Extensions.Configuration;

IConfiguration configuration = new ConfigurationBuilder()
    .SetBasePath(Directory.GetCurrentDirectory())
    .AddJsonFile("appsettings.json", optional: false)
    .AddEnvironmentVariables()
    .Build();

string hospitalName = configuration["Hospital:Name"] ?? "Unknown";
int pageSize = configuration.GetValue<int>("Hospital:DefaultPageSize");

Environment variables override settings

// Environment variable name for Hospital:DefaultPageSize:
Environment.SetEnvironmentVariable("Hospital__DefaultPageSize", "50");

var config = new ConfigurationBuilder()
    .AddJsonFile("appsettings.json", optional: true)
    .AddEnvironmentVariables()
    .Build();

int effectivePageSize = config.GetValue<int>("Hospital:DefaultPageSize");

Double underscore maps to a configuration hierarchy separator. Use environment variables or a secret manager for environment-specific values; never commit real production passwords.

Logging with ILogger

using Microsoft.Extensions.Logging;

using var loggerFactory = LoggerFactory.Create(builder =>
    builder.AddConsole());

ILogger logger = loggerFactory.CreateLogger("HospitalApp");
logger.LogInformation(
    "Registered patient {PatientId} at {RegisteredAtUtc}",
    1205,
    DateTimeOffset.UtcNow);

Structured logging stores values as fields. Avoid string interpolation in log templates and never write passwords, tokens or unnecessary patient medical information to logs.

Validation result instead of exception for normal input

public sealed record ValidationResult(bool IsValid, string? Error)
{
    public static ValidationResult Valid() => new(true, null);
    public static ValidationResult Invalid(string error) => new(false, error);
}

static ValidationResult ValidateMrn(string? mrn)
{
    return string.IsNullOrWhiteSpace(mrn)
        ? ValidationResult.Invalid("MRN is required.")
        : ValidationResult.Valid();
}

Practice

  1. Read a patient export JSON file and validate it before importing.
  2. Handle malformed JSON separately from file-not-found and permission errors.
  3. Create a custom exception for a true domain conflict.
  4. Load hospital settings from JSON and override one value using an environment variable.
  5. Add structured logs while ensuring patient-sensitive fields are excluded.
