API ENGINEERING GUIDE 05

API testing and operations

Contract, integration, load, observability and API lifecycle practices. These guides focus specifically on designing APIs as stable, secure products for other software to consume.

API design principle: an API is a long-lived contract. Design for clients you do not control, handle failure explicitly, protect every resource and preserve compatibility deliberately.

TOPIC 01

API integration testing

Why this matters

Integration tests verify routing, middleware, DI, serialization, authorization and persistence together.

What you must learn

Learn WebApplicationFactory, test server, isolated database, Testcontainers, Respawn, fixture lifetime and test data isolation.

Code example

public sealed class PatientsApiTests(WebApplicationFactory<Program> factory)
{
    [Fact]
    public async Task UnknownPatient_ReturnsNotFound()
    {
        var client = factory.CreateClient();
        var response = await client.GetAsync($"/api/v1/patients/{Guid.NewGuid()}");
        Assert.Equal(HttpStatusCode.NotFound, response.StatusCode);
    }
}

Practice task

Test success, validation, authorization, not-found, conflict and unexpected failures through HTTP.

TOPIC 02

Contract testing and client compatibility

Why this matters

A provider can change without noticing that it broke a mobile or partner client. Contract tests protect assumptions at service boundaries.

What you must learn

Learn consumer-driven contracts, OpenAPI diffing, schema compatibility, generated clients and mock servers.

Code example

// Assert a stable public response shape rather than internal entity implementation.
var json = await response.Content.ReadFromJsonAsync<PatientResponse>();
Assert.NotNull(json);
Assert.NotEqual(Guid.Empty, json.Id);

Practice task

Add a contract test for the mobile patient lookup API and run it in CI.

TOPIC 03

Load, stress and resilience testing

Why this matters

An API that works for one request may fail under concurrent users, slow dependencies or large result sets.

What you must learn

Learn k6 or JMeter, throughput, p95/p99 latency, error rate, saturation, ramp-up, soak tests and realistic datasets.

Code example

// Example k6 script
import http from 'k6/http';
import { check } from 'k6';
export default function () {
  const res = http.get('https://localhost:7001/api/v1/doctors');
  check(res, { 'status is 200': r => r.status === 200 });
}

Practice task

Load-test doctor search and appointment booking. Record p95 latency, error rate and database resource usage.

TOPIC 04

API observability

Why this matters

APIs need enough telemetry to diagnose failures across callers, services and databases without exposing sensitive payloads.

What you must learn

Learn structured logs, correlation IDs, OpenTelemetry traces, metrics, latency histograms, health checks and alerting.

Code example

builder.Services.AddOpenTelemetry()
    .WithTracing(t => t.AddAspNetCoreInstrumentation().AddHttpClientInstrumentation())
    .WithMetrics(m => m.AddAspNetCoreInstrumentation());

Practice task

Trace a request from API entry to SQL and an external SMS provider. Create an alert for elevated 5xx responses.

TOPIC 05

API lifecycle and governance

Why this matters

Professional APIs need ownership, documentation, deprecation policy, security review and controlled releases.

What you must learn

Learn API catalogues, ownership, naming conventions, version support windows, changelogs, release notes, gateway policies and usage analytics.

Code example

// Add stable operation identifiers and metadata for generated API docs.
app.MapGet("/api/v1/patients/{id:guid}", GetPatient)
   .WithName("GetPatientV1")
   .WithTags("Patients");

Practice task

Create an API standards document covering naming, errors, auth, paging, versioning, deprecation and review requirements.
