API ENGINEERING GUIDE 04

API design and advanced patterns

Idempotency, concurrency, caching, webhooks, file transfer and long-running operations. These guides focus specifically on designing APIs as stable, secure products for other software to consume.

API design principle: an API is a long-lived contract. Design for clients you do not control, handle failure explicitly, protect every resource and preserve compatibility deliberately.

TOPIC 01

Idempotency keys

Why this matters

Clients retry requests after network failures. Without idempotency, a payment or booking may be performed twice.

What you must learn

Learn idempotency key scope, request hashing, persistence, replayed responses, expiry and concurrent duplicate handling.

Code example

app.MapPost("/api/v1/payments", async (PaymentRequest request, IIdempotencyService keys, CancellationToken ct) =>
{
    var replay = await keys.TryGetResponseAsync(request.IdempotencyKey, ct);
    if (replay is not null) return Results.Ok(replay);
    // Persist key and result transactionally with the payment workflow.
    return Results.Accepted();
});

Practice task

Implement idempotency for payment posting. Send the same key twice and prove only one financial operation occurs.

TOPIC 02

Concurrency and conditional requests

Why this matters

Two clients may edit the same record simultaneously. Concurrency controls prevent lost updates and stale writes.

What you must learn

Learn ETags, If-Match, rowversion, optimistic concurrency and 409/412 responses.

Code example

var etag = Convert.ToBase64String(invoice.RowVersion);
context.Response.Headers.ETag = $"\"{etag}\"";
// On update, compare If-Match with the current version before saving.

Practice task

Build invoice editing with rowversion and reject stale updates rather than silently overwriting them.

TOPIC 03

Caching and HTTP cache headers

Why this matters

Caching reduces server and database work when responses can be reused. Sensitive personalized responses require special care.

What you must learn

Learn Cache-Control, ETag, Last-Modified, conditional GET, public/private/no-store, Vary and CDN behavior.

Code example

app.MapGet("/api/v1/doctors/{id:guid}", async (Guid id, IDoctorService service) =>
{
    var doctor = await service.GetPublicProfileAsync(id);
    return doctor is null ? Results.NotFound() : Results.Ok(doctor);
}).CacheOutput();

Practice task

Cache public doctor directory responses with an explicit freshness policy. Ensure patient-specific data is never accidentally shared.

TOPIC 04

File uploads and downloads

Why this matters

File endpoints are common attack surfaces and can exhaust memory or storage. Validate size, content and ownership before accepting files.

What you must learn

Learn streaming, multipart forms, extension/content validation, antivirus scanning, storage outside web root, signed downloads and retention.

Code example

app.MapPost("/api/v1/patients/{id:guid}/documents", async (Guid id, IFormFile file, IDocumentStore store, CancellationToken ct) =>
{
    if (file.Length is <= 0 or > 10_000_000) return Results.BadRequest();
    await using var stream = file.OpenReadStream();
    var documentId = await store.SaveAsync(id, stream, ct);
    return Results.Created($"/api/v1/documents/{documentId}", new { documentId });
});

Practice task

Implement secure document upload with size limits, content inspection, authorization and non-public storage.

TOPIC 05

Long-running operations and 202 Accepted

Why this matters

Some operations take longer than an HTTP request should remain open. A 202 response means processing was accepted, not completed.

What you must learn

Learn job resources, operation IDs, polling, callbacks, cancellation, status states and durable background processing.

Code example

app.MapPost("/api/v1/reports", async (IReportQueue queue, CancellationToken ct) =>
{
    var jobId = await queue.EnqueueAsync(ct);
    return Results.Accepted($"/api/v1/operations/{jobId}", new { jobId, status = "queued" });
});

Practice task

Build an asynchronous report export with queued/running/completed/failed status and an authorized download endpoint.

TOPIC 06

Webhooks

Why this matters

Webhooks deliver events to external systems. Receivers must verify authenticity and tolerate duplicate or delayed delivery.

What you must learn

Learn HMAC signatures, timestamp tolerance, replay protection, retries, event IDs, idempotent consumers and secret rotation.

Code example

using var hmac = new HMACSHA256(secret);
var expected = hmac.ComputeHash(Encoding.UTF8.GetBytes(payload));
var valid = CryptographicOperations.FixedTimeEquals(expected, suppliedSignature);

Practice task

Build a payment-provider webhook receiver. Verify signatures and reject replayed event IDs.
