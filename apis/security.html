API ENGINEERING GUIDE 03

API authentication and security

Identity, OAuth/OIDC, JWT, policies, CORS, rate limiting and threat modelling. These guides focus specifically on designing APIs as stable, secure products for other software to consume.

API design principle: an API is a long-lived contract. Design for clients you do not control, handle failure explicitly, protect every resource and preserve compatibility deliberately.

TOPIC 01

Authentication and authorization

Why this matters

Authentication identifies the caller; authorization determines what that caller may do. Every sensitive API must enforce both at the server.

What you must learn

Learn schemes, claims, roles, policies, scopes, principals, resource-based checks and least privilege.

Code example

builder.Services.AddAuthorizationBuilder()
    .AddPolicy("Billing.Read", p => p.RequireClaim("permission", "billing.read"));

app.MapGet("/api/v1/invoices", GetInvoices)
   .RequireAuthorization("Billing.Read");

Practice task

Create role/permission policies for reception, doctors, pharmacy, billing and administrators.

TOPIC 02

OAuth 2.0, OpenID Connect and JWT

Why this matters

JWT is a token format, not a complete login protocol. Use a trusted identity provider and validate token signature, issuer, audience and expiry.

What you must learn

Understand authorization code with PKCE, client credentials, access tokens, refresh tokens, scopes, issuer, audience and key rotation.

Code example

builder.Services.AddAuthentication().AddJwtBearer(options =>
{
    options.Authority = configuration["Identity:Authority"];
    options.Audience = configuration["Identity:Audience"];
});

Practice task

Configure a trusted provider. Verify wrong issuer, wrong audience, expired token and invalid signature are rejected.

TOPIC 03

Resource-level authorization and IDOR

Why this matters

A valid user may still lack access to a specific patient, appointment or invoice. Guessable identifiers must never grant access by themselves.

What you must learn

Learn ownership checks, department/facility scope, `IAuthorizationService`, authorization handlers, tenant isolation and insecure direct object references.

Code example

var result = await authorization.AuthorizeAsync(User, patient, "CanReadPatient");
if (!result.Succeeded) return Results.Forbid();

Practice task

Attempt to access another department's patient by changing the URL ID. Confirm the server denies access.

TOPIC 04

CORS, CSRF and browser security

Why this matters

CORS controls which browser origins may read responses; it is not an authentication system. Cookie-based authentication also needs CSRF protection.

What you must learn

Learn exact origin allowlists, credentials, preflight, SameSite cookies, anti-forgery tokens, HTTPS and secure headers.

Code example

builder.Services.AddCors(options => options.AddPolicy("Frontend", policy =>
    policy.WithOrigins("https://portal.example.com")
          .AllowAnyHeader().AllowAnyMethod()));
app.UseCors("Frontend");

Practice task

Configure only approved front-end origins. Test preflight requests and do not combine wildcard origins with credentials.

TOPIC 05

Rate limiting and abuse protection

Why this matters

Public endpoints can be abused through brute force, scraping or expensive queries. Rate limits protect capacity but should be designed by user, IP or resource.

What you must learn

Learn fixed/sliding/token bucket limiters, concurrency limits, partition keys, 429 responses, Retry-After and upstream protections.

Code example

builder.Services.AddRateLimiter(options => options.AddFixedWindowLimiter("login", o =>
{
    o.PermitLimit = 5;
    o.Window = TimeSpan.FromMinutes(1);
}));
app.UseRateLimiter();

Practice task

Apply stricter limits to login and OTP endpoints. Verify legitimate clients receive useful retry guidance.

TOPIC 06

API security threat modelling

Why this matters

Security is a design activity. Identify assets, actors, trust boundaries, abuse cases and mitigations before exposing endpoints.

What you must learn

Study OWASP API Security risks: broken object-level authorization, broken authentication, property-level authorization, unrestricted resource consumption, SSRF and misconfiguration.

Code example

// Always project only fields the caller is authorized to see.
return Results.Ok(new PatientResponse(patient.Id, patient.FullName));
// Never serialize the persistence entity wholesale.

Practice task

Threat-model patient search, file uploads, prescription access and payment callbacks. Document mitigations and negative tests.
