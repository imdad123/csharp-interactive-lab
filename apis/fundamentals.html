API ENGINEERING GUIDE 01

HTTP and REST foundations

Resources, methods, status codes, headers, idempotency, JSON and API contracts. These guides focus specifically on designing APIs as stable, secure products for other software to consume.

API design principle: an API is a long-lived contract. Design for clients you do not control, handle failure explicitly, protect every resource and preserve compatibility deliberately.

TOPIC 01

Resource-oriented API design

Why this matters

An API is a contract used by other software. Resource-oriented URLs and consistent HTTP semantics make APIs predictable for web, mobile and partner clients.

What you must learn

Model nouns as resources, use plural collections, nested routes only for genuine ownership, and avoid exposing database table names as public contracts.

Code example

GET    /api/v1/patients/{patientId}
POST   /api/v1/patients
GET    /api/v1/doctors/{doctorId}/appointments
POST   /api/v1/appointments
PATCH  /api/v1/appointments/{appointmentId}
DELETE /api/v1/appointments/{appointmentId}

Practice task

Design patient, doctor, appointment, admission and invoice resources. Document ownership and lifecycle rules.

TOPIC 02

HTTP methods and semantics

Why this matters

HTTP methods communicate intent. Safe and idempotent behavior matters for retries, caching and client reliability.

What you must learn

Understand GET, POST, PUT, PATCH, DELETE, safe methods, idempotency, conditional requests and when a command should not be represented as a destructive GET.

Code example

app.MapPut("/api/v1/patients/{id:guid}", async (Guid id, UpdatePatientRequest request, IPatientService service, CancellationToken ct) =>
    await service.UpdateAsync(id, request, ct)
        ? Results.NoContent()
        : Results.NotFound());

Practice task

Test each method for correct semantics. A repeated PUT should leave the same state; a repeated payment POST needs an idempotency design.

TOPIC 03

Status codes and response headers

Why this matters

Status codes are part of the API contract. Clients should not need to parse arbitrary message text to understand success or failure.

What you must learn

Master 200, 201, 202, 204, 400, 401, 403, 404, 409, 415, 422, 429 and 500; learn Location, ETag, Cache-Control, Retry-After and correlation headers.

Code example

return Results.CreatedAtRoute(
    routeName: "GetPatient",
    routeValues: new { id = patient.Id },
    value: PatientResponse.From(patient));

Practice task

Create a response matrix for patient registration, booking conflicts, invalid input, missing records and asynchronous exports.

TOPIC 04

JSON serialization and contract shape

Why this matters

Serialization converts .NET values to wire formats. Public JSON contracts should be deliberate and stable rather than accidental reflections of internal entities.

What you must learn

Learn System.Text.Json, naming policies, enums, DateOnly/DateTimeOffset, converters, null handling, ignored properties, polymorphism and compatibility.

Code example

builder.Services.ConfigureHttpJsonOptions(options =>
{
    options.SerializerOptions.PropertyNamingPolicy = JsonNamingPolicy.CamelCase;
    options.SerializerOptions.Converters.Add(new JsonStringEnumConverter());
});

Practice task

Define JSON examples for patient and appointment responses. Test serialization and deserialization with real contract tests.

TOPIC 05

Pagination, filtering and sorting

Why this matters

Unbounded collection endpoints can overload databases and networks. Pagination and bounded filters protect both service performance and client usability.

What you must learn

Learn offset pagination, keyset pagination, page-size limits, stable ordering, filter validation, search terms and total-count trade-offs.

Code example

app.MapGet("/api/v1/appointments", async (int page, int pageSize, HospitalDbContext db, CancellationToken ct) =>
{
    page = Math.Max(page, 1);
    pageSize = Math.Clamp(pageSize, 1, 100);
    return await db.Appointments.AsNoTracking()
        .OrderBy(x => x.StartsAt).ThenBy(x => x.Id)
        .Skip((page - 1) * pageSize).Take(pageSize)
        .Select(x => new AppointmentListItem(x.Id, x.StartsAt))
        .ToListAsync(ct);
});

Practice task

Add paging, filters and stable sorting to appointment search. Test page-size caps and duplicate/missing records across pages.
