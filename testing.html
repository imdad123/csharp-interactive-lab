09 · Testing and professional practices

Test behavior at the correct level, from isolated domain rules to real API/database integration.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Why testing matters

Tests provide fast feedback and protect behavior during refactoring. Developers do not test only individual functions; they test units, integration boundaries and complete workflows based on risk.

Unit testing and Arrange-Act-Assert

Test one focused behavior in isolation. Test public behavior, normal cases, boundaries and invalid input. Keep tests deterministic and independent. Avoid tests that simply repeat private implementation details.

[Fact]
public void CalculateTotal_AddsFeeAndTax()
{
    decimal total = Billing.CalculateTotal(100m, 15m);
    Assert.Equal(115m, total);
}

DTOs make functions testable

If a method reads directly from a WebForms control or HTTP request, testing it requires that UI or web context. Map incoming data to a DTO, then call the business method with that DTO. A unit test can construct it directly.

Stubs, fakes and mocks

  • Stub supplies predetermined data or responses.
  • Fake is a lightweight working implementation, such as an in-memory repository.
  • Mock verifies an interaction when that interaction is part of the contract.
  • Do not mock every class; use real domain objects for simple business logic.

Integration and API testing

Test API + DI + database, EF Core mappings against SQL Server, stored procedures, transaction rollback, authentication middleware and authorization policies. Use an isolated test database, never production. Verify status codes, validation, authorization, duplicates, pagination, cancellation and failure responses.

HospitalApp test cases

  • Patient validation and duplicate registration.
  • Appointment scheduling conflicts and cancellation.
  • Invoice totals and payment allocation.
  • Repository behavior using fakes in unit tests.
  • SQL persistence and stored procedures in integration tests.
  • API authorization and invalid request handling.

Deep dive: test hospital business rules

A unit test verifies a small unit's observable behavior in isolation. A method can call other methods and still be unit-tested when external dependencies are controlled.

Test a pure rule

public static decimal CalculateBalance(decimal billed, decimal paid)
    => billed - paid;

[Fact]
public void Balance_IsChargesMinusPayments()
{
    var balance = BillingRules.CalculateBalance(5000m, 3200m);
    Assert.Equal(1800m, balance);
}

Use test names that describe scenario, action and expected result. Cover normal, boundary and invalid cases.

Test a service with a fake repository

Do not open SQL Server for every unit test. Depend on an interface and supply controlled data to test the service decision rather than the database provider.

public interface IPatientRepository
{
    Task<Patient?> GetByIdAsync(int id, CancellationToken ct);
}
public sealed class PatientLookupService(IPatientRepository repository)
{
    public async Task<string> GetNameAsync(int id, CancellationToken ct)
    {
        var patient = await repository.GetByIdAsync(id, ct);
        return patient is null ? "Not found" : patient.Name;
    }
}

Integration and API tests

Integration tests verify API routing, DI, EF Core mapping and SQL behavior together. Use a dedicated test database or a provider matching the behavior you need. EF Core InMemory is not a relational SQL Server replacement: it does not validate SQL translation, constraints or transactions accurately.

API tests verify status codes, validation, authorization and response DTO shape. Keep many fast unit tests, a useful number of integration tests and fewer broad end-to-end tests. Avoid testing private implementation details.

Practice task

  1. Unit test invoice totals and appointment eligibility.
  2. Test PatientLookupService with fake repository for found/missing cases.
  3. Integration-test registration against a test database.
  4. API-test invalid input, unauthenticated access and successful registration.
