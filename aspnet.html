10 · ASP.NET Core and Minimal APIs

Understand the HTTP request lifecycle and build maintainable, secure web APIs.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

HTTP foundations

Understand request/response, methods, status codes, headers, JSON payloads and resource URLs. GET reads, POST creates/processes, PUT replaces, PATCH partially updates and DELETE removes. Design idempotent write operations where possible.

Host, Kestrel and startup

WebApplication.CreateBuilder configures hosting, logging, configuration and dependency injection. Kestrel is the cross-platform web server. Program.cs registers services and builds the app.

Middleware and request lifecycle

Middleware components form an ordered pipeline. Each can inspect the request, call the next component and inspect the response. Ordering matters for exception handling, routing, authentication, authorization and endpoint execution.

Minimal APIs and route groups

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddScoped<IPatientService, PatientService>();
var app = builder.Build();

var patients = app.MapGroup("/api/patients");
patients.MapGet("/{id:int}", async (int id, IPatientService service) =>
    await service.GetByIdAsync(id));
app.Run();

Use route groups for shared prefixes, metadata and authorization. Keep handlers concise; put business workflows in application services.

DTOs, validation and errors

Bind requests into explicit DTOs. Validate required fields, ranges and business rules. Return meaningful status codes and consistent error payloads. Never expose stack traces or database details to clients.

Security, OpenAPI and operations

  • Authentication identifies the caller; authorization decides what they may do.
  • Use claims, roles and policies; apply least privilege.
  • Configure HTTPS, CORS, rate limiting and secret management.
  • Generate OpenAPI documentation.
  • Use structured logs, correlation IDs, exception handling and health checks.

HospitalApp API milestones

  1. GET patients and doctors.
  2. POST appointments with validation and conflict checking.
  3. Filter and paginate appointments.
  4. Add authentication and role/policy authorization.
  5. Write integration tests against a dedicated database.

Deep dive: build a Hospital Management API

HTTP request lifecycle

A mobile app sends HTTP. Kestrel accepts it; middleware runs in order; routing selects an endpoint; authentication/authorization run; the handler calls an application service; the response is serialized. Middleware order matters: authentication must run before authorization.

Minimal API structure

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddScoped<PatientService>();
builder.Services.AddAuthorization();
var app = builder.Build();
app.UseExceptionHandler();
app.UseAuthentication();
app.UseAuthorization();
var patients = app.MapGroup("/api/patients").RequireAuthorization();
patients.MapGet("/{id:int}", async (int id, PatientService service, CancellationToken ct) =>
{
    var patient = await service.GetAsync(id, ct);
    return patient is null ? Results.NotFound() : Results.Ok(patient);
});
app.Run();

This is structural sample code. Register a real authentication scheme, persistence and production error handling before deployment.

Route groups, DTOs and validation

Group related endpoints under /api/patients. Use request DTOs to control client-submitted fields. Validate names, dates and phone formats at the boundary; enforce critical invariants again in application/domain logic.

HTTP status codes

  • 200: successful retrieval/update with response.
  • 201: resource created; include its location.
  • 204: success without body.
  • 400: malformed or invalid request.
  • 401: authentication missing/invalid.
  • 403: authenticated caller lacks permission.
  • 404: resource absent.
  • 409: business conflict, such as an already-booked slot.

Security and documentation

Authenticate callers, authorize every operation and resource, validate input, use parameterized SQL, rate-limit sensitive endpoints and return only necessary patient data. Hiding a frontend button is not authorization. OpenAPI describes the contract; Scalar or Swagger UI can present it during development. Protect or disable public docs according to deployment policy.

Practice task

  1. Create GET /api/patients/{id} and POST /api/patients.
  2. Use request/response DTOs.
  3. Return 201, 400, 404 and 409 correctly.
  4. Protect endpoints with authentication and role/policy authorization.
  5. Test endpoints using an HTTP client and integration tests.
