14 · Stored procedures, transactions and T-SQL programming

Implement safe database workflows and protect multi-step business operations.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

INSERT, UPDATE and DELETE

Use explicit target column lists. Verify WHERE predicates before destructive operations. Learn OUTPUT, DELETE versus TRUNCATE, identity handling and safe upsert patterns. Understand MERGE caveats before using it in concurrent workflows.

Stored procedures

Stored procedures package parameterized operations, provide stable database interfaces and can encapsulate multi-step work. Learn input/output parameters, return codes, SET NOCOUNT ON, error handling and execution permissions.

CREATE OR ALTER PROCEDURE dbo.GetPatientById
    @PatientId int
AS
BEGIN
    SET NOCOUNT ON;
    SELECT PatientId, PatientName
    FROM dbo.Patients
    WHERE PatientId = @PatientId;
END;

Views, functions and temporary data

  • Views provide named query abstractions.
  • Scalar and table-valued functions have different use cases and performance characteristics.
  • #temp tables live in tempdb and can have indexes/statistics.
  • Table variables have different optimization behavior; choose based on volume and measured plans.
  • Table-valued parameters pass sets of rows to procedures.

Dynamic SQL and injection prevention

Use sp_executesql to parameterize values. Parameters cannot replace identifiers; validate and safely quote allowed object names. Never concatenate untrusted values into executable SQL.

Transactions and ACID

Atomicity, consistency, isolation and durability describe transaction guarantees. Use transactions when related changes must succeed or fail together. Keep transactions short and use TRY/CATCH with rollback handling.

SET XACT_ABORT ON;
BEGIN TRY
    BEGIN TRAN;
    -- related writes
    COMMIT;
END TRY
BEGIN CATCH
    IF XACT_STATE() <> 0 ROLLBACK;
    THROW;
END CATCH;

Isolation, locking and concurrency

Understand Read Uncommitted, Read Committed, Repeatable Read, Serializable, Snapshot and RCSI. Learn dirty reads, non-repeatable reads, phantom reads, blocking, deadlocks, deadlock graphs and rowversion-based optimistic concurrency. NOLOCK is not a universal performance fix.

HospitalApp practice

  • Book appointments safely under concurrent requests.
  • Post invoice and payment/ledger records in one transaction.
  • Prevent duplicate payment posting with unique business keys.
  • Allocate a bed atomically so two users cannot claim the same bed.

Deep dive: safe T-SQL programming and financial transactions

Stored procedures

Procedures provide a named database interface and can centralize operations and permissions. They do not automatically make SQL fast or secure; parameterize inputs.

CREATE OR ALTER PROCEDURE dbo.GetPatientAppointments
 @PatientId int, @FromDate date, @ToDate date
AS
BEGIN
 SET NOCOUNT ON;
 SELECT AppointmentId, ScheduledAt, Status FROM dbo.Appointments
 WHERE PatientId=@PatientId AND ScheduledAt >= @FromDate
 AND ScheduledAt < DATEADD(day,1,@ToDate)
 ORDER BY ScheduledAt DESC;
END;

Transactions: invoice header and lines

Invoice header, details and accounting entries must commit together or roll back together.

SET XACT_ABORT ON;
BEGIN TRY
 BEGIN TRANSACTION;
 INSERT dbo.Invoices(PatientId, InvoiceDate, TotalAmount)
 VALUES (@PatientId, SYSUTCDATETIME(), @TotalAmount);
 DECLARE @InvoiceId bigint=SCOPE_IDENTITY();
 INSERT dbo.InvoiceLines(InvoiceId, Description, Amount)
 VALUES (@InvoiceId, N'Consultation', @ConsultationFee);
 COMMIT;
END TRY
BEGIN CATCH
 IF XACT_STATE() <> 0 ROLLBACK;
 THROW;
END CATCH;

Validate header total against line totals and apply correct currency rounding before posting.

Isolation, locks and deadlocks

Understand READ COMMITTED, SNAPSHOT and SERIALIZABLE. Keep transactions short, access tables in consistent order and index predicates to reduce lock duration. Retry deadlock victims only when the operation is safe to retry.

Views, functions, temp tables and dynamic SQL

Views package query logic; functions return scalar or table values with trade-offs; temp tables hold intermediate results. For dynamic SQL, use sp_executesql parameters for values. Object names cannot be parameters: whitelist them and use QUOTENAME.

  2. Write invoice posting with rollback.
  3. Simulate two users updating one invoice and inspect blocking.
  4. Capture a deadlock graph.
  5. Build a safe dynamic report.
