02 · Collections and LINQ

Choose the right data structure and query data cleanly in memory or through a database provider.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Why collections exist

Arrays have fixed length. Collections support changing data and common operations such as adding, removing, searching and grouping.

Core collections

  • List<T>: ordered collection with dynamic size and indexed access.
  • Dictionary<TKey,TValue>: key-based lookup, such as patient ID to patient.
  • HashSet<T>: unique values and efficient membership checks.
  • Queue<T>: first-in, first-out; Stack<T>: last-in, first-out.
  • Choose by lookup pattern, ordering, uniqueness and mutation needs.
var patientsById = new Dictionary<int, Patient>();
patientsById[101] = patient;

if (patientsById.TryGetValue(101, out var found))
    Console.WriteLine(found.Name);

Collection interfaces

  • IEnumerable<T>: can be iterated.
  • ICollection<T>: count and mutation operations.
  • IReadOnlyCollection<T>: exposes count without mutation.
  • IReadOnlyList<T>: read-only indexed access.
  • Accept the least powerful interface your method needs to reduce coupling.

LINQ operators

  • Where filters; Select projects; SelectMany flattens nested sequences.
  • OrderBy and ThenBy sort; Distinct removes duplicates.
  • First/FirstOrDefault and Single/SingleOrDefault express different assumptions.
  • Any, All and Contains test membership and conditions.
  • GroupBy, Join and GroupJoin combine and summarize data.
  • Count, Sum, Average, Min and Max aggregate.
  • Skip and Take support pagination when ordering is stable.
var today = appointments
    .Where(a => a.StartTime.Date == DateTime.Today)
    .OrderBy(a => a.StartTime)
    .Select(a => new { a.PatientName, a.StartTime })
    .ToList();

Deferred execution and IQueryable

Many LINQ operations build a query that runs when enumerated. ToList and ToArray materialize results immediately. IEnumerable generally represents in-memory iteration; IQueryable allows a provider such as EF Core to translate expression trees into SQL. Avoid repeated enumeration, premature materialization and loading entire tables.

HospitalApp practice

  1. Store patients in List<Patient> and index by ID in Dictionary.
  2. Find appointments by doctor, date and status.
  3. Group appointments by doctor and calculate visit counts.
  4. Project report results into DTOs instead of returning full entities.

Deep dive: collections and LINQ for hospital data

Hospitals have changing numbers of patients, doctors, appointments and invoices. Collections handle data structures with different lookup and update patterns.

List<T>: ordered records

var patients = new List<Patient>
{
    new(101, "Amina", true), new(102, "Bilal", false)
};
patients.Add(new Patient(103, "Sara", true));
Patient? found = patients.FirstOrDefault(p => p.Id == 102);

List searches are generally linear. For frequent lookup by a unique key, consider Dictionary.

Dictionary: lookup by patient ID

var patientById = new Dictionary<int, Patient>
{
    [101] = new Patient(101, "Amina", true),
    [102] = new Patient(102, "Bilal", false)
};
if (patientById.TryGetValue(102, out Patient? patient))
    Console.WriteLine(patient.Name);

TryGetValue handles missing keys safely. A duplicate patient ID should be treated as a data-integrity problem, not silently overwritten.

HashSet: uniqueness

var uniqueIds = new HashSet<int> { 101, 102, 101 };
Console.WriteLine(uniqueIds.Count); // 2

Use it when a daily report merges patient IDs from multiple sources and each patient should appear once.

Interfaces and LINQ

IEnumerable<T> means a sequence can be enumerated. Accept the least powerful interface your method needs.

static void PrintNames(IEnumerable<Patient> patients)
{
    foreach (var patient in patients) Console.WriteLine(patient.Name);
}
var activeNames = patients.Where(p => p.IsActive)
    .OrderBy(p => p.Name).Select(p => p.Name).ToList();

Where filters, OrderBy sorts and Select projects. This resembles SQL WHERE, ORDER BY and SELECT.

Deferred execution and IQueryable

Many LINQ-to-Objects queries execute when enumerated; ToList materializes them. IQueryable builds an expression a provider such as EF Core may translate to SQL. Avoid materializing too early, or you may pull every patient into memory before filtering.

var result = await db.Patients.Where(p => p.IsActive)
    .Select(p => new PatientListItem(p.Id, p.Name))
    .ToListAsync();

Worked examples: collections and LINQ

The examples below use this small model. Run the snippets in a console project and compare the output.

public sealed record Patient(int Id, string Name, int Age, string Department, decimal Balance);

List<Patient> patients =
[
    new(1, "Amina", 30, "Cardiology", 250m),
    new(2, "Bilal", 17, "Pediatrics", 0m),
    new(3, "Sara", 45, "Cardiology", 500m),
    new(4, "Hamza", 62, "Emergency", 125m),
    new(5, "Noor", 28, "Pediatrics", 0m)
];

List operations: add, update, remove and search

var waitingList = new List<string> { "Amina", "Bilal" };
waitingList.Add("Sara");
waitingList.Insert(1, "Noor");
waitingList[0] = "Amina Khan";

bool exists = waitingList.Contains("Sara");
int index = waitingList.FindIndex(name => name.StartsWith("N"));
waitingList.Remove("Bilal");
waitingList.RemoveAll(name => name.Length < 4);

Console.WriteLine($"Contains Sara: {exists}; Noor index: {index}");

Dictionary: lookup and safe insertion

var patientIndex = patients.ToDictionary(p => p.Id);

if (patientIndex.TryGetValue(3, out Patient? patient))
    Console.WriteLine(patient.Name);

if (!patientIndex.TryAdd(6, new Patient(6, "Zain", 35, "Surgery", 0m)))
    Console.WriteLine("Patient ID already exists.");

HashSet: prevent duplicate medical record numbers

var mrns = new HashSet<string>(StringComparer.OrdinalIgnoreCase);
string[] imported = ["MR-100", "mr-100", "MR-101"];

foreach (string mrn in imported)
{
    if (!mrns.Add(mrn))
        Console.WriteLine($"Duplicate MRN rejected: {mrn}");
}

Queue and Stack: FIFO versus LIFO

var reception = new Queue<Patient>();
foreach (Patient p in patients) reception.Enqueue(p);

Patient next = reception.Dequeue(); // first registered is called first

var undoHistory = new Stack<string>();
undoHistory.Push("Created invoice");
undoHistory.Push("Added laboratory charge");
string lastAction = undoHistory.Pop(); // most recent action first

LINQ Where and Select

var adultNames = patients
    .Where(p => p.Age >= 18)
    .Select(p => p.Name)
    .ToList();

foreach (string name in adultNames)
    Console.WriteLine(name);

FirstOrDefault and null handling

Patient? patientWithId3 = patients.FirstOrDefault(p => p.Id == 3);
Patient? missing = patients.FirstOrDefault(p => p.Id == 999);

Console.WriteLine(patientWithId3?.Name ?? "Not found");
Console.WriteLine(missing is null ? "No matching patient" : missing.Name);

Use First when absence is an error and you want an exception. Use FirstOrDefault when no match is a normal possibility. Use Single when the data contract requires exactly one match; it detects duplicates.

Any, All, Count and aggregates

bool hasEmergencyPatient = patients.Any(p => p.Department == "Emergency");
bool allHaveNames = patients.All(p => !string.IsNullOrWhiteSpace(p.Name));
int cardiologyCount = patients.Count(p => p.Department == "Cardiology");
decimal totalBalance = patients.Sum(p => p.Balance);
decimal averageAge = patients.Average(p => p.Age);
int oldestAge = patients.Max(p => p.Age);

OrderBy and ThenBy

var ordered = patients
    .OrderBy(p => p.Department)
    .ThenBy(p => p.Name)
    .ToList();

foreach (Patient p in ordered)
    Console.WriteLine($"{p.Department}: {p.Name}");

GroupBy for department reporting

var report = patients
    .GroupBy(p => p.Department)
    .Select(group => new
    {
        Department = group.Key,
        PatientCount = group.Count(),
        Outstanding = group.Sum(p => p.Balance)
    })
    .OrderByDescending(row => row.PatientCount);

foreach (var row in report)
    Console.WriteLine($"{row.Department}: {row.PatientCount}, balance {row.Outstanding}");

Deferred execution and materialization

var outstandingQuery = patients.Where(p => p.Balance > 0); // not executed yet
patients.Add(new Patient(6, "Zain", 35, "Surgery", 300m));

foreach (Patient p in outstandingQuery)
    Console.WriteLine(p.Name); // includes Zain

var snapshot = outstandingQuery.ToList(); // executes and stores results now

LINQ-to-Objects queries are often deferred until enumeration. Calling ToList, ToArray, Count or an aggregate usually executes the query. Be deliberate about repeated enumeration and snapshot requirements.

IEnumerable versus IQueryable

// In-memory sequence: filtering runs in .NET after data is already loaded.
IEnumerable<Patient> inMemory = patients;
var localResult = inMemory.Where(p => p.Age >= 18);

// EF Core query: expression can be translated into SQL by the provider.
IQueryable<Patient> databaseQuery = db.Patients;
var serverQuery = databaseQuery.Where(p => p.Age >= 18);
var rows = await serverQuery
    .Select(p => new PatientListItem(p.Id, p.Name))
    .ToListAsync(cancellationToken);

Do not call AsEnumerable or ToList too early on a large database query. Keep filters, projections, sorting and pagination in SQL where possible. IQueryable depends on a provider and not every .NET method can be translated.

Method syntax and query syntax

var methodSyntax = patients
    .Where(p => p.Age >= 18)
    .OrderBy(p => p.Name)
    .Select(p => p.Name);

var querySyntax =
    from p in patients
    where p.Age >= 18
    orderby p.Name
    select p.Name;

Both compile to LINQ query operations. Method syntax is common for fluent pipelines; query syntax can be clearer for joins and grouped queries.

Join patients to appointments

var appointments = new[]
{
    new { PatientId = 1, Doctor = "Dr. Ali" },
    new { PatientId = 1, Doctor = "Dr. Sara" },
    new { PatientId = 3, Doctor = "Dr. Hamza" }
};

var schedule = from p in patients
               join a in appointments on p.Id equals a.PatientId
               select new { p.Name, a.Doctor };

foreach (var item in schedule)
    Console.WriteLine($"{item.Name} -> {item.Doctor}");
