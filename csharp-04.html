04 · Generics, DTOs and architecture

Write reusable type-safe code and separate domain rules from UI and infrastructure.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Why generics exist

Generics make reusable containers and algorithms work with different types without losing compile-time type safety. They avoid object-based storage and repetitive casting.

public class Repository<T>
{
    private readonly List<T> _items = new();
    public void Add(T item) => _items.Add(item);
    public IReadOnlyList<T> GetAll() => _items;
}

Generic constraints and variance

Learn where T : class, struct, notnull, new(), or an interface/base type. Constraints express what operations a generic type can safely perform. Understand covariance (out) and contravariance (in) when consuming generic interfaces and delegates.

DTOs and why they matter

A Data Transfer Object carries data across a boundary such as a form, API or service. It prevents business methods from depending on UI controls and avoids exposing database entities as public contracts. DTOs also make unit tests straightforward: construct the input object and call the method.

public sealed record RegisterPatientRequest(
    string Name, DateOnly DateOfBirth, string PhoneNumber);

public Patient Register(RegisterPatientRequest request)
{
    // Validate and apply business rules.
    return new Patient(request.Name);
}

SOLID principles

  • Single Responsibility: one coherent reason to change.
  • Open/Closed: extend stable behavior without constantly modifying it.
  • Liskov Substitution: derived types honor base expectations.
  • Interface Segregation: focused contracts beat oversized interfaces.
  • Dependency Inversion: high-level policy should not depend on low-level implementation details.

Dependency injection and architecture

Constructor injection makes dependencies explicit and testable. Separate domain rules, application use cases, infrastructure and delivery mechanisms when the complexity justifies it. Repository abstractions can protect meaningful boundaries; unnecessary interfaces create indirection without value.

HospitalApp practice

  1. Create RegisterPatientRequest and BookAppointmentRequest DTOs.
  2. Keep validation independent of Console.ReadLine and HTTP.
  3. Inject repository abstractions into application services.
  4. Unit-test service behavior by constructing DTOs directly.
