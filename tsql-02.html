13 · Joins, aggregation, CTEs and window functions

Build reliable reporting queries and understand how SQL combines and summarizes relational data.

Study approach: Understand the problem first, then the concept, syntax, trade-offs, and its use in a real enterprise application.

Joins

INNER JOIN returns matching rows; LEFT JOIN preserves all left rows; FULL JOIN preserves unmatched rows from both sides. A filter on the right table in WHERE can unintentionally remove unmatched left rows and change LEFT JOIN behavior.

SELECT a.AppointmentId, p.PatientName, d.DoctorName
FROM dbo.Appointments AS a
JOIN dbo.Patients AS p ON p.PatientId = a.PatientId
JOIN dbo.Doctors AS d ON d.DoctorId = a.DoctorId;

Aggregation and grouping

GROUP BY creates groups; HAVING filters groups after aggregation. Watch for one-to-many joins that multiply rows and inflate totals. Learn COUNT, COUNT_BIG, SUM, AVG, MIN, MAX and conditional aggregation.

SELECT DoctorId, COUNT(*) AS AppointmentCount
FROM dbo.Appointments
WHERE AppointmentDate >= @StartDate
GROUP BY DoctorId
HAVING COUNT(*) >= 10;

Subqueries, EXISTS and set operators

Learn scalar and correlated subqueries, EXISTS/NOT EXISTS, UNION/UNION ALL, INTERSECT and EXCEPT. EXISTS is often clear for checking whether related rows exist.

CTEs and recursive queries

A CTE names a query expression for readability within one statement. Recursive CTEs can traverse hierarchies. A CTE is not automatically a materialized temporary table.

Window functions

Window functions calculate across related rows while retaining row-level detail. Learn OVER, PARTITION BY, ORDER BY, ROW_NUMBER, RANK, DENSE_RANK, NTILE, LAG, LEAD and running aggregates.

SELECT DoctorId, AppointmentDate,
       ROW_NUMBER() OVER (
           PARTITION BY DoctorId
           ORDER BY AppointmentDate DESC) AS RowNum
FROM dbo.Appointments;

HospitalApp reporting practice

  • Doctor-wise appointment counts by date range.
  • Latest appointment per patient using ROW_NUMBER.
  • Daily cash and bank collection with conditional aggregation.
  • Running daily revenue using SUM() OVER.
  • Outstanding invoice aging grouped by patient or department.
